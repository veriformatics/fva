This is not silent weakening: the report says `The formal ` followed by the backticked R2 identifier and `is the necessary overflowing-input subset emphasized by the` at `runs/prompted-avg_floor/VERIFICATION.md:59`, then expressly states the subset-refutation argument. ### P8

C signed-overflow undefinedness is disclosed separately; no source fix or successful R1/R2 verification is claimed.

## Scope + evidence limits

- All three projects execute literal shipped bytes through small manually specified Wasm interpreters. Envelope checks fix module structure/export identity; byte execution, rather than an asserted equality with a handwritten C algorithm, supplies the local semantic link. This still trusts each interpreter's correspondence to Wasm. Every report discloses that boundary; no report claims a verified compiler or official-Wasm refinement. Same M3/M6 bar as verdicts.md.
- Checker claims inspected against entrypoints, driver source, and retained logs. isqrt + avg_floor: Lean C++, Nanoda, Con-Ron accept real exports and reject false-type forgeries. sat_add: C++ default/paranoid + Lean4Lean do likewise; the report does not count the C++ modes as independent implementations. Nanoda's expected type-equality assertion and Lean4Lean's final explicit mismatch are present; pretty-printer diagnostics are not mistaken for proof acceptance/rejection. sat_add mismatch logs inspected by their final eight lines; the positive logs + other rejection logs read whole. No checker implementation or kernel-correctness audit performed; none is claimed by the reports.
- Formal project-only review sizes independently recomputed from source with each report's stated counting convention. Standard-library closure + orchestration infrastructure are separately disclosed. Full serialized dependency censuses were not independently regenerated; driver logic inspected.
