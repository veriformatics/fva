# Agent benchmark law

- Rubric first: `rubric.md` (or a dated addendum) is committed before any run it grades; scoring follows it as written, a deviation = a new addendum + a note in `results.md`.
- Arms run as fresh `codex exec` sessions in dirs outside this repo (own `git init`), because teammates inherit this repo's `CLAUDE.md` + `spec.md` (FVA's whole approach) and a copy of the repo leaks the rubric + planted-bug commit messages; the fva arm gets a history-free copy of the FVA package (`fva init`'s vendored package, prebuilt, + the fetched canaries, assembled by `bench/tasks/prepare` from the bench tag's frozen worktree). `codex exec` needs `< /dev/null`, else it blocks on stdin.
- Bench root = `$HOME/.cache/fva-bench` (runs, inputs, batches, grading, arm tools, package store), named so in bench docs, rules + the rubric — user ruling on the `CLAUDE.md` `Authoring` portability clause: `$HOME`-derived ⇒ the same path on every host; outside the repo by the isolation law above ⇒ no repo-relative form.
- `bench/harness/run-session` jails every run (bubblewrap; visible = system, own run dir, arm tools, package store, `PATH` entries under `$HOME`; `/tmp` + `/var/tmp` = the run's `jail-tmp` on disk, since a tmpfs holds agents' scratch files in the shared host memory), since Codex's workspace-write sandbox limits writes alone and agents read ancestor `AGENTS.md` files; a graded run's `result.json` carries `jail.visible` + a clean `harness_commit`. `bench/tests/check-prep` (by hand, mock Codex) asserts the jail and `run-order`'s scheduling (one CPU, order, sequence, `CHECK` lines, memory gate).
- Every agent claim is rechecked by MAIN: clean build, axiom audit, `leanexport` → `lake check --from-export` kernel replay (outside the agent sandbox; nested `bwrap` fails inside it, D19); the rubric's judged metrics (M3 + M6, M9) go to fresh `reviewer`s per arm, calibrated on the earlier `verdicts.md`; M4 = MAIN's, from the run's evidence (a machine-checked outcome confirmed by its M1 result).
- Verdict-table rulings — user ruling on the `CLAUDE.md` `Teammates` advisor fit (a teammate verdict table before its judgment rows are ruled), applied to every task: MAIN rules each row it rechecks on a bench `reviewer` table (non-`faithful` M3 verdicts, M6 findings, any rating it changes) after an advisor consult — inside the rubric's `MAIN rechecks` clause, so no addendum; one procedure grades every task (`results.md` records it + each changed ruling); the grading procedure + rulings live in `bench/grade/README.md`. A grading session without the advisor → ask the user to resume it with one before ruling.
- `bench/grade/inject` (Lean arms) + `bench/grade/inject-tool` (Frama-C + Verus arms) (M8) count a catch only when the arm's own check exits nonzero or its output names the cheat by a cheat-specific token (`sorryAx`, `fvaCheatAx`, `fvaCheatOneEqTwo`, a byte/hash mismatch; generic words such as `axioms` or `kernel` appear in clean output too); confirm each catch's cause in its log, since a syntax error from the injection would also exit nonzero, and run the clean baseline (`C0`) of every documented check: a check red on a clean copy credits catches by name alone.
- Graded batch = a seeded interleaved order (`bench/harness/run-batch --order-only TASK SEED ARM…` writes it, recorded under `~/.cache/fva-bench/batches/`; every arm × n = 5; inputs prepared once per arm; fva arm = `FVA_BENCH_FVA_BIN`/`FVA_BENCH_FVA_BUILD` of the bench tag's frozen worktree), run beside the user's other work (rubric addendum 2026-10-28 (3)) by `bench/harness/run-order TASK ORDER_FILE`: one run at a time on one CPU, each started at ≥ 16 GB available memory, launched as a capped systemd user service, since Claude Code's low-memory reaper stops its own background shells (`systemd-run --user --unit fva-bench-<task> --collect -p MemoryMax=20G -p OOMPolicy=continue …`); every graded run used codex-cli 0.163.0 (binary sha256 in `results.md`), so a batch on another Codex binary is a rubric deviation. `FVA_BENCH_SECONDS=14400` = the hard limit; from 90 min on, `CHECK` log lines every 30 min → MAIN's progress check (stop only a run with no new event and no rising CPU time for 30 min, scored as unfinished). MAIN's heavy jobs here and on the pool run memory-capped too. After each batch, `bench/tools/codex-quota` → `results.md`.
- Tool-arm containers: a podman container outlives its client, so `bench/tools/frama-c` names + labels each one (`FVA_TOOL_LABEL`, set per run by `run-session`) and kills it on TERM/INT/EXIT, and `bench/tools/tool-broker` kills the run's labelled containers when the run ends; each is capped at 16 GiB without swap and pinned to the run's CPUs (`FVA_TOOL_CPUS`), like the agent's own processes. `bench/tests/check-tool-broker` (by hand, podman + the Frama-C image) asserts the limits, both kill paths and the cap; it fails on a wrapper that sets no label. After each batch, `podman ps -q` is empty.
- `results.md`'s grading figures (M1, M2 link checks, M5 splits, M8) come from drivers in the gitignored `.scratch/u15/grade/` until D53 ports them to `bench/grade/`; each ruling's evidence is in `.scratch/u15/t{2,3,7}-grading.md`.
