# Mutation check law (U12, `docs/contracts/U12-mutation.md`)

- `fvamut` = `FVATest/Mutate/*.lean`, scope + stages = `FVATest/Mutate/config.json`. Gate: full = `scripts/test-mutation` (`check`: `results.tsv` current, every survivor/inconclusive ruled, 3 seeded rows replayed; never writes); fast = `scripts/test-mutation --fast` (`update`: every stale mutant runs, user ruling: no cap; rewrites `results.tsv`). Many stale rows → run the update where `CLAUDE.local.md` says, then commit `results.tsv` with the change that made it stale. Every update runs under a memory cap (a cgroup limit such as `systemd-run --scope -p MemoryMax=…`): growth mutants allocate without bound, the capped job ends as a crash (inconclusive) and later stages may still kill it, while an uncapped run takes the host into swap.
- Runner identity = the sha256 of `FVATest/Mutate/*.lean` (fixture excluded): any edit there makes every row stale (≈ 2,455 mutants, hours) → batch runner edits, rerun once. `--fresh` (every row, both caches ignored) once per phase, after its last scope or runner change (at the latest at the phase close); later updates reuse its rows.
- A survivor = behavior no proof or test pins. Contract specifies it → add the theorem or test that kills it. Otherwise rule it: copy its line from `.cache/mutate/rulings-todo.tsv` into `rulings.tsv` with verdict `equivalent` (argument: no input distinguishes it) | `unspecified` (contract clause; `path@<16-hex sha256>`) | `resource` (inconclusive, cost growth only); the reviewer ≠ the author of the tests and proofs involved; MAIN-drafted rulings stay open `.agent/review.md` rows until the closing-diff reviewer rules them. A ruling binds the declaration's text: editing that declaration makes it stale.
- Engineering-law use (a test pinning already-passing behavior): `scripts/test-mutation update --files <files the test imports or calls> [--stages … test:<name>]` — ad-hoc runs never write the table; record scope, command and every survivor in the commit body.
- Planted inputs = `scripts/test-mutation-fixture` (run by `scripts/test-checks`): a new outcome, mode or digest input ships with a fixture case asserting its exact rc/row/finding. `fixture/ops.expected` = the reviewed operator listing: a listing change → review the diff line by line, then regenerate (`lake env <fvamut> list --config <ops-only config>` in a fixture copy).
- Test scripts keep the rc protocol 0 pass / 1 assertion / 2 setup or infrastructure / 3 crash: only rc 1 counts as a kill, so a script must never map a setup failure to 1.
- Scope files (config.json group dirs + `FVA/Spec`) declare definitions at command level: `fvamut sites` does not descend into `<command> in` (`open … in def …` hid both certificate checkers from the scope), so namespaces open and options set at section level (`section … open X … end`); `scripts/check-scope` (gate) fails on any `open|set_option|variable|universe|attribute|omit|include … in` line in a scope file.
