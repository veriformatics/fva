# Mutation check law (U12, `docs/contracts/U12-mutation.md`)

- `fvamut` = `FVATest/Mutate/*.lean`, scope + stages = `FVATest/Mutate/config.json`. Gate: full = `scripts/test-mutation` (`check`: `results.tsv` current, every survivor/inconclusive ruled, 3 seeded rows replayed; never writes); the fast gate runs none (user ruling: mutation re-runs scale with invalidation, outside the latency-bounded fast gate). A unit whose change stales rows runs `scripts/test-mutation --update` (`update`: every stale mutant runs, user ruling: no cap; rewrites `results.tsv`) before its commit, where `CLAUDE.local.md` says, and commits `results.tsv` with that change. Sharded form (user ruling: updates run over GitHub-hosted runners): `scripts/mutation-ci push NAME` (the stale tree → `ci/mut-NAME`; `.github/workflows/mutation.yml` = build, `scripts/mutation-plan` packs whole files (large ones split by declaration) into shards by mutant count, one runner + one worker per shard: an ad-hoc `update --files … --decls …` writes the content-keyed execution cache, uploaded per shard), `scripts/mutation-ci collect RUN` (every shard's cache → `.cache/mutate/exec`), then the full `--update` here reuses them and writes the table (`test-mutation-fixture` `shard_case`: two trees' half-scope ad-hoc runs + a cache merge → the full update executes nothing, table byte-identical to the one-host run). Never `--stages` on a shard (a stage override changes the run context). Every mutation run (local `--update`/`check`, ad-hoc shard scopes) runs in a checkout where `scripts/fetch-subjects` placed the subjects: `bench/subjects/wasm` is a declared difftest input, gitignored, so an unplaced checkout keys every survivor/inconclusive row + the difftest kills apart from CI and the GH shards (both place it) and writes a table CI finds stale (D97). Growth mutants allocate without bound: `fvamut` caps each stage's process group at `memLimitMiB` (K7: past it = `inconclusive … crash: memory over N MiB`, later stages may still kill), so workers × `memLimitMiB` must fit the host; a host-wide cgroup around the run stays where `CLAUDE.local.md` says.
- Runner identity = the sha256 of `FVATest/Mutate/*.lean` (fixture excluded): any edit there makes every row stale (≈ 3,393 mutants, hours) → batch runner edits, rerun once. An edit to any module-graph file re-keys every survivor row (83 rows ≈ 2.5 h of pool `--update`), an edit to a killing test (e.g. `FVATest/Trust.lean`) the rows it kills → batch such edits per unit, update once. `--fresh` (every row, both caches ignored) once per phase, after its last scope or runner change (at the latest at the phase close) = the campaign-tier mutation sweep; later updates reuse its rows.
- A survivor = behavior no proof or test pins. Contract specifies it → add the theorem or test that kills it. Otherwise rule it: copy its line from `.cache/mutate/rulings-todo.tsv` into `rulings.tsv` with verdict `equivalent` (argument: no input distinguishes it) | `unspecified` (contract clause; `path@<16-hex sha256>`) | `resource` (inconclusive, cost growth only); the ruler ≠ the author of the tests and proofs involved; MAIN-drafted rulings count as unruled survivors (`CLAUDE.md` `Engineering`; IMPLEMENT: open `.agent/review.md` rows until a `consultant` rules them before the phase close). A ruling binds the declaration's text: editing that declaration makes it stale.
- Engineering-law use (a test pinning already-passing behavior): `scripts/test-mutation update --files <files the test imports or calls> [--stages … test:<name>]` — ad-hoc runs never write the table; record scope, command and every survivor in the commit body.
- Planted inputs = `scripts/test-mutation-fixture` (run by `scripts/test-checks`): a new outcome, mode or digest input ships with a fixture case asserting its exact rc/row/finding. `fixture/ops.expected` = the reviewed operator listing: a listing change → review the diff line by line, then regenerate (`lake env <fvamut> list --config <ops-only config>` in a fixture copy).
- Test scripts keep the rc protocol 0 pass / 1 assertion / 2 setup or infrastructure / 3 crash: only rc 1 counts as a kill, so a script must never map a setup failure to 1.
- The module graph = every `.lean` under `srcRoots` minus `exclude`: each graph module must have an olean (fvamut loads them all) and enters every survivor's digest, so `exclude` keeps out what can never build or kill: `FVATest/Subjects` (planted `Neg/*` modules fail by design; subjects are neither proof roots nor tests), the cheats, examples and certificate negatives, the fuzz entries `FVATest/Fuzz` (D70: no stage builds or runs them). `exclude` is part of the manifest: editing it stales every row.
- Scope files (config.json group dirs + `FVA/Spec`) declare definitions at command level: `fvamut sites` does not descend into `<command> in` (`open … in def …` hid both certificate checkers from the scope), so namespaces open and options set at section level (`section … open X … end`); `scripts/check-scope` (gate) fails on any `open|set_option|variable|universe|attribute|omit|include … in` line in a scope file.
