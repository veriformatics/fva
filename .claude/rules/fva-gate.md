# FVA gate

- Full gate = `scripts/gate` (CI + every closing commit); fast gate = `scripts/gate --fast` (iteration; skips the network/history scanners `osv-scanner`, `gitleaks git`). rc 0 = every step passed; each step prints its wall-clock, failures print their last 20 log lines.
- Fresh checkout: `lake exe cache get` before the first `scripts/gate` (Mathlib oleans from the cache, never a rebuild); `scripts/gate` fetches `.tools/` itself. Template `CI gate` = not adopted: `gate.yml` runs on `main` pushes + PRs alone, a `ci/*` push triggers nothing (adoption = D32) ⇒ the full gate + worktree builds run where the machine's `CLAUDE.local.md` says.
- Steps: `lake --wfail build` (type-check; warnings fail), `lake --wfail test` (`fvatest` + compile-time `#guard`s in the modules `FVATest.Main` imports: CLI dispatch, validator AST fixtures `FVATest.Valid`), `scripts/test-decoder` (decoder vs the official binary tests + `wasm-tools print` differential + lift kernel check), `scripts/test-numerics` (integer spec + verified float impl vs the official numeric scripts), `scripts/test-spec` (the official Wasm 2.0-profile scripts: every module payload through the verified validator (category counts pinned) + a `wasm-tools validate` differential, every command through the reference stepper `FVA.Wasm.Exec.Ref`; fast = 80 scripts ≈ 30 s, full = 82 (adds bulk + memory_fill) ≈ 5 min with 4 workers; memory_copy validates without executing (D30); `--kernel` = edgeR.so validated by `decide +kernel`, ≈ 200 s, outside the gate), `scripts/test-floatdiff` (verified float impl vs `wasmtime wast`: case matrix + fixed-seed boundary-biased operands; fast 105,832 assertions, full 1,971,832; generation ≈ 18 s of the full run), `scripts/test-difftest` (`fva difftest`: Lean-predicted WAST for every export of the lz4-wasm codec, the committed lz4 C/Rust builds + edgeR, checked by `wasmtime wast`; fast 8 cases per function (edgeR 2), full 32 (edgeR 16); assertion counts pinned), `lake --wfail lint` (Batteries `runLinter`), `scripts/check-format` (Lean text format: ≤ 100 columns, no tabs, no trailing whitespace, final newline — Lean has no official formatter; `fva lift` output is exempt from the column rule), `scripts/test-checks` (planted inputs for the purpose-built checks incl. the mutation battery `scripts/test-mutation-fixture`; runs inside the Lean lane after `build`, beside the other Lean steps, since it needs the built `fvamut`), `scripts/test-mutation` (U12 mutation check: full = `check`, fast = `update` — every stale mutant runs; `.claude/rules/fva-mutation.md`), `scripts/test-trust` (U7, full gate only: `fva trust` on the self package — default + `--paranoid` replay — the cheat suite with each tag set pinned, the worked examples through `fva explain`, the certificate fixtures; `.claude/rules/fva-checks.md`), `scripts/test-init` (U11, full gate only: an `fva init` project PASS with a 14-line surface + an edited vendored file reviewed), shellcheck + `shfmt -d` (the bash scripts under `scripts/` + `bench/`, selected by shebang), `.agent/spec-lint`, `scripts/check-pins`, `scripts/make-base-manifest --check` (the FVA base manifest `fva trust` classifies by is current), actionlint + `zizmor --offline` (workflows), `gitleaks dir` (+ `gitleaks git` full), `osv-scanner` (lockfiles; full).
- Test scripts exit 0 pass / 1 assertion failure / 2 setup or infrastructure / 3 program under test crashed (signal); the mutation check counts rc 1 alone as a kill (U12 K4), `fva difftest` exits 3 when wasmtime cannot run.
- `FVATest` and the `fva` executable (`Main.lean`) import the executable modules they run (spec, impl, tools), never the proof modules: a planted impl bug then still builds the tests and `fva difftest`, which must catch it on their own (mutation check U12 relies on this).
- `lake build` success alone proves nothing about proofs (accepts `sorry`, custom axioms, kernel bypass); verification claims go through `fva trust` (U7 onward).
- Pins move together: `lean-toolchain` = installed `lean` = Mathlib tag in `lakefile.toml` = `lake-manifest.json` inputRev (`scripts/check-pins`); Renovate groups Lean + Mathlib and never automerges. Tool binaries (scanners, shellcheck, shfmt, wasm-tools, wasmtime) = `scripts/fetch-tools` (version + sha256; a Renovate bump fails there until the sha256 is refreshed from the release), so CI + every host check with one version: `scripts/` disables shellcheck codes by number, and SC2329 exists from 0.11.0 on (an older shellcheck reports SC2317 there instead).
