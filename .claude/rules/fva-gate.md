# FVA gate

- Full gate = `scripts/gate` (CI + every closing commit); fast gate = `scripts/gate --fast` (iteration; skips the network/history scanners `osv-scanner`, `gitleaks git`). rc 0 = every step passed; each step prints its wall-clock, failures print their last 20 log lines.
- Where the full gate runs on this machine: the pool form from the main root, `offload run -- bash -c 'lake exe cache get && scripts/gate'` (the host workdir keeps the Mathlib cache between runs; `scripts/gate` fetches `.tools/` itself). The fast gate and single-module builds run direct; a linked worktree's module build stays direct or `offload run --local` (a pool run would bootstrap its own 7.2 GB Mathlib).
- Steps: `lake --wfail build` (type-check; warnings fail), `lake --wfail test` (`fvatest` + compile-time `#guard`s in `FVATest`), `scripts/test-decoder` (decoder vs the official binary tests + `wasm-tools print` differential + lift kernel check), `scripts/test-numerics` (integer spec + verified float impl vs the official numeric scripts), `scripts/test-spec` (the official Wasm 2.0-profile execution scripts through the reference stepper `FVA.Wasm.Exec.Ref`; fast = 79 scripts ≈ 34 s, full adds bulk + memory_fill ≈ 6 min with 4 workers; memory_copy deferred D30), `scripts/test-floatdiff` (verified float impl vs `wasmtime wast`: case matrix + fixed-seed boundary-biased operands; fast 105,832 assertions, full 1,971,832; generation ≈ 18 s of the full run), `scripts/test-difftest` (`fva difftest`: Lean-predicted WAST for every export of the uBO codec, the committed lz4 C/Rust builds + edgeR, checked by `wasmtime wast`; fast 8 cases per function (edgeR 2), full 32 (edgeR 16); assertion counts pinned), `lake --wfail lint` (Batteries `runLinter`), `scripts/check-format` (Lean text format: ≤ 100 columns, no tabs, no trailing whitespace, final newline — Lean has no official formatter), `scripts/test-checks` (planted inputs for the purpose-built checks), shellcheck + `shfmt -d` (scripts/), `.agent/spec-lint`, `scripts/check-pins`, actionlint + `zizmor --offline` (workflows), `gitleaks dir` (+ `gitleaks git` full), `osv-scanner` (lockfiles; full).
- `FVATest` and the `fva` executable (`Main.lean`) import the executable modules they run (spec, impl, tools), never the proof modules: a planted impl bug then still builds the tests and `fva difftest`, which must catch it on their own (mutation check U12 relies on this).
- `lake build` success alone proves nothing about proofs (accepts `sorry`, custom axioms, kernel bypass); verification claims go through `fva trust` (U7 onward).
- Pins move together: `lean-toolchain` = installed `lean` = Mathlib tag in `lakefile.toml` = `lake-manifest.json` inputRev (`scripts/check-pins`); Renovate groups Lean + Mathlib and never automerges. Scanner binaries = `scripts/fetch-tools` (version + sha256; a Renovate bump fails there until the sha256 is refreshed from the release).
