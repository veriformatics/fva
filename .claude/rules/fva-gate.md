# FVA gate

- Full gate = `scripts/gate` (CI + every closing commit); fast gate = `scripts/gate --fast` (iteration; skips the network/history scanners `osv-scanner`, `gitleaks git` and the mutation table — user ruling on the template's latency-bounded fast gate: each unit that stales mutation rows runs `--update` before its commit, `.claude/rules/fva-mutation.md`). rc 0 = every step passed; each step prints its wall-clock + verdict, failures print their last 20 log lines.
- Step ledger = `scripts/gate-ledger` (gitignored `.cache/gate-ledger/<host>.tsv`: run, host, tree, mode, step, seconds, verdict, note): every gate run appends one row per step; a pool run's file returns by `--get .cache/gate-ledger` (`CLAUDE.local.md`). Each red → `scripts/gate-ledger classify <step> product|gate|flake|planted [tree [note]]` before any rerun (a CI red: its commit's tree + `ci:<run id>`); `scripts/gate-ledger reds` = the open ones. `scripts/gate-ledger summary` = per step: runs, seconds, reds by class, unique catches (product reds alone in their run) = the record a campaign-tier move rests on.
- Fresh checkout: `lake exe cache get` before the first `scripts/gate` (Mathlib oleans from the cache, never a rebuild); `scripts/gate` fetches `.tools/` itself.
- CI gate (template `CI gate`, D32): `gate.yml` runs on `main`, `ci/**` and PRs as a fan-out — one build job (`.lake/build` cached per commit), then one job per gate group (`scripts/gate --group G`; `scripts/gate --groups`: lean, trust, init, subjects, static). Full gate of a commit = `git push -f origin HEAD:ci/<unit>` + `gh run watch <id>` in the background; red → fix, amend, push again; green → `git push origin --delete ci/<unit>`. A full local `scripts/gate` fails (`ci-groups`) when a step belongs to no group or the matrix misses one. The CI gate runs `test-mutation` in check mode: an `--update` (stale rows) still runs where the machine's `CLAUDE.local.md` says, before the push.
- Steps and what each checks (build, test, decoder, numerics, spec suite, float + export difftests, lint, format, planted-input checks, mutation, trust, init, subjects, shell, spec-lint, pins, base manifest, scope, workflows, secrets, vulnerabilities) = `.claude/rules/fva-checks.md`, which loads with `scripts/**`.
- Test scripts exit 0 pass / 1 assertion failure / 2 setup or infrastructure / 3 program under test crashed (signal); the mutation check counts rc 1 alone as a kill (U12 K4), `fva difftest` exits 3 when wasmtime cannot run.
- `FVATest` and the `fva` executable (`Main.lean`) import the executable modules they run (spec, impl, tools), never the proof modules: a planted impl bug then still builds the tests and `fva difftest`, which must catch it on their own (mutation check U12 relies on this).
- Test form (ruling on the template's `Engineering` property-test clause): a predicate proven as a theorem over its whole input domain needs no property test of its own — the kernel checks every input; the compiled code's agreement with the proven definitions stays with the official-suite + difftest runs (Lean compiler = residual trust). Property tests + fuzz targets cover unproven code (glue, tools, harnesses): `.agent/deferred.md` D69, D70.
- Timings (user ruling on the template's `Authoring` `CLAUDE.local.md` scope): the wall-clock figures in `.claude/rules/` stay as cost guidance (their order of magnitude holds on the desktop, the pool + CI and steers gate + batching choices); host names, deictic host references + host-only quirks → `CLAUDE.local.md`.
- `lake build` success alone proves nothing about proofs (accepts `sorry`, custom axioms, kernel bypass); verification claims go through `fva trust` (U7 onward).
- Pins move together: `lean-toolchain` = installed `lean` = Mathlib tag in `lakefile.toml` = `lake-manifest.json` inputRev (`scripts/check-pins`); Renovate groups Lean + Mathlib and never automerges. Tool binaries (scanners, shellcheck, shfmt, wasm-tools, wasmtime) = `scripts/fetch-tools` (version + sha256; a Renovate bump fails there until the sha256 is refreshed from the release), so CI + every host check with one version: `scripts/` disables shellcheck codes by number, and SC2329 exists from 0.11.0 on (an older shellcheck reports SC2317 there instead).
