## Intent

FVA (Formally Verify Anything) aims to follow a software development tooling trend brought on by REA (Reverse Engineer Anything): https://github.com/morluto/rea. Our goal is to allow a user to apply FVA to any pre-existing or new project and find a path towards formal verification of it. It is important that the formal verification is directly linked to the code of the software's actual implementation, for instance Verus is tightly integrated with Rust, and Lean allows for metaprogramming. For other languages, we may have to develop our own solutions and it is best if we can find a unified approach to avoid an excess of language-specific handling, which is likely to be brittle and inelegant in approach.

Like REA, FVA should be readily usable by an AI agent that requests it, and that is the primary target. FVA uses extensive AI-generated proofs to achieve its verification claims. At the same time FVA should aim to minimize the surface of human-reviewable spec. This is treated as an optimization problem: provided a minimally sufficient spec, and a trusted kernel like that of Lean's, we can assume that an unbounded amount of proofs can be used to verify correctness of a program. See https://github.com/schildep/verified-3d-mesh-intersection, for an excellent example of this approach. Spec review may be further simplified by informalization back into natural language (https://github.com/metareflection/claimcheck); we must be open to considering alternative and supplementary approaches at all times.

Proof writing alone is not what FVA adds: a capable agent can already write and check proofs when it is asked to verify a project. FVA adds what such an agent does not supply on its own. It keeps the human-reviewable spec small, and it measures that spec as its main result. It does not trust a single checker: it replays proofs through independent kernels and tests each checker against known false proofs. It links the proofs to the real implementation without a rewrite of the source. It verifies the compiled artifact, or, for components that are not practical to verify as programs (compilers, interpreters, code generators, AI pipelines), it certifies each output that they produce.

## Decisions

- Link path = WASM lift: any source language → wasm (compiler + source untrusted) → `fva lift` → `Lifted.lean` = the `.wasm` bytes as one little-endian `Nat` literal + length + readable `module` value + `decode_eq : decode bytes len = .ok module` by `decide +kernel` (Lean decoder evaluated by the kernel ⇒ no lifter trust; structural equality hand-written, since `deriving DecidableEq` rejects the nested `Instr` type); theorems quantify over `module`; the `.wasm` = the verified artifact, committed; `fva trust` checks literal = file bytes + `decode_eq`'s type + kernel replay.
- Trusted base = Lean kernel + axioms {propext, Classical.choice, Quot.sound} + Mathlib at the pinned rev (user ruling: trusted) + FVA's reviewed-once Lean specs, shared across every project/language: Wasm syntax, binary grammar (declarative relation the decoder is proven against), execution semantics (integers, IEEE-754 floats, memory, tables, globals, calls), C-ABI vocabulary, verdict spec. Difftest vs wasmtime + the official Wasm spec suite = evidence for the specs, not proof.
- Claims = `Prop`-valued defs in `<Lib>/Spec.lean`; proofs = theorems typed by the claim constant, downstream in `<Lib>/Proof.lean` (never read); `<Lib>/Lifted.lean` generated. Spec imports reviewed modules alone; the reverse layout (spec importing proofs) lets unreviewed macros/notation change spec meaning.
- Human-review surface = every module in the spec module's import closure minus Lean core, Mathlib, FVA base + subject, read whole (code lines counted); statement closure reports which subject/base/core names the claims use. Core = by `.olean` origin (Lean sysroot); Mathlib = by origin in the pinned Mathlib package; FVA base = vendored sources whose content hashes match the set the CLI pins; never by module name.
- Distribution: `fva init` vendors the pinned FVA Lean package into each project + requires Mathlib at FVA's pinned rev, oleans from its cache (works offline once fetched, inside `lake check`'s sandbox + in history-free exports).
- `fva trust` FAIL on: unproven claim, non-standard axiom (incl. `sorryAx`, `native_decide` + `bv_decide` aux axioms), syntax extension in a review module, `implemented_by`/`extern`/`unsafe`/`partial`/`opaque` in the non-core closure, a claim not mentioning a subject, lifted literal ≠ file bytes or `decode_eq` missing/mistyped, kernel replay rejection (`leanexport` → `lake check --from-export`; `--paranoid` adds every bundled kernel; per-checker status read directly, since Lake labels any nonzero rc `rejected` and nanoda rejects by panic). `lake build` success alone proves nothing (accepts sorry, axioms, kernel bypass).
- Scope (user ruling): greenfield rebuild of every prototype Decision (lift, trust, difftest, explain) + link reach + per-output certification + bench v2, in one IMPLEMENT session.
- Stack (user ruling): Lean-native, no Python: one Lean 4.35 Lake package on Lean core + Mathlib (user ruling: Mathlib trusted, usable in FVA's core and elsewhere; no other external Lean deps) = specs + proven verdict path + proof library + CLI (`lake exe fva`) + harnesses (Lean + bash). Difftest = Lean-predicted results emitted as WAST, checked by `wasmtime wast` (a registered helper module reads/writes the subject's memory); Wasm spec suite = `wasm-tools json-from-wast` → Lean runner. Rust + Verus rejected: FVA's own verdicts would rest on Z3 + Verus's VC generator, which no independent checker re-checks. Talos (AGPL-3.0 Lean Wasm) = reference only.
- Self-verification (user ruling): FVA verifies itself to the greatest extent possible. Boundary table, shipped in the trust report + README: spec (reviewed once) / verified implementation (proven against a spec: decoder sound + complete for the supported profile + grammar unambiguous, verdict function, closures, checker-output parser, certification checkers) / trusted glue (Environment fact collection, IO orchestration, external checker binaries: small, tested, canaried) / residual trust (Lean kernel cross-checked by 5 independent checkers, Lean compiler, the specs). Type soundness proven this phase: validated modules never get stuck. Gate runs `fva trust` on FVA's own self-proof package + a Lean mutation check on verified modules (each mutant must break a theorem or a test).
- Floats (user ruling): in scope: IEEE-754 ops = exact rational arithmetic + one correct-rounding function + NaN/infinity/zero rules; NaN payloads nondeterministic per the Wasm spec ⇒ claims quantify over every allowed NaN result; validated by the official float tests + difftest.
- Language reach (user ruling): C++ joins the targets; goal = any language, or trivial porting: program proofs for every language compiling to core wasm (one C-ABI vocabulary for C, C++, Rust, Zig, …), per-output certificates for every other language (a new language = a capture runner); WasmGC languages deferred.
- Update automation (user ruling): Renovate (GitHub Actions + `lean-toolchain` regex manager); the user installs the Renovate app on the repo.
- Non-expert review aid = `fva explain`, layered under `fva trust` (verdict stays there; explain = advisory): per claim → proof status (trust issues naming it + project-wide ones), plain-English breakdown + caveats, examples table, intent check.
  - Method = Claimcheck's two-pass round trip, reimplemented (Claimcheck itself parses Dafny + calls Anthropic/Vertex/Bedrock only): pass 1 explains from comment-stripped spec source + each claim's elaborated statement (post-macro = what the kernel checks; source text alone hid cheat 7's `False →` on 3 claims); pass 2 = separate call comparing pass 1 with intent → `matches|weaker|stronger|different|vacuous`.
  - Intent = claim docstring, else its name. Blinding beyond docstring stripping (names, independent requirements) = deferred (D5); current scope = LLM breakdown of a spec.
  - Example values never come from the model: inputs = model-proposed + fixed `0`,`1` per argument; spec value = Lean evaluation of the claim's `Returns` result (claims of shape `∀ (x : BitVec n)…, Returns m "f" args res`; other shapes print their elaborated statement instead); binary value = wasmtime on the pinned `.wasm`.
  - Persistence: result saved to `<project>/fva-explain.json` (LLM text + examples + verdicts + `inputsSha`); a rerun shows it with no LLM call, `--force` alone regenerates. `inputsSha` = review-surface files + `.wasm` + `Semantics.lean` + `Explain.lean` + prompts/schemas + model + effort; mismatch → STALE banner + rc 1. Proof status = fresh `fva trust` every run, never saved.
  - LLM backend = `gpt-6-luna` via `codex app-server` (JSON-RPC stdio, ephemeral read-only thread, `outputSchema`-constrained reply), both passes.
- Direction (user-approved): FVA supplies what an agent told to "formally verify this repo" does not; proof writing = commodity (`prototype/bench/results.md`: a bare agent matched FVA on proof validity, requirement faithfulness, bug finding + honest reporting). FVA's work goes to:
  - Review surface = the product metric: measured + budgeted by a gate. An unconstrained agent grows specs toward implementation size (parsers, printers, digests restated as spec); reviewed-once shared patterns + base modules shrink the per-project surface.
  - Checker trust: never one checker. Kernel replay + independent kernels + a canary set of known-false proofs per pinned toolchain, since verifiers ship soundness bugs; deterministic kernel checking preferred over solver-backed verification (timeouts, resource limits, version drift).
  - Link paths, no source rewrite required: program verification over the compiled artifact (wasm lift) + per-output certification (translation validation) for components unfit for program verification (compilers, interpreters, generators, LLM pipelines).
  - Plain-English review: LLM informalization (`fva explain`) now; controlled-language claims evaluated beside it (deterministic, but expressivity gaps lose meaning).
- Link framing: per-language links already exist (Verus, Aeneas/hax → Lean/F*, Frama-C, SPARK; recalled, unverified); FVA's claim = one language-agnostic link at the compiled artifact with a small trusted base. Reach gap = semantics subset (D1), lifter in the trusted base (D2), one source language shown (D7).
- Benchmark v2 (user rulings): purpose = show on a sufficiently large project that FVA gains in time, cost, spec size + readability, plus cases where a naive approach finds no path to verification at all; targets = the subjects below (compiled cores first, then Python, R, Java, TypeScript as each gains a link); agents = headless Claude sessions launched + graded by MAIN (no codex, no GPT teammates), n = 5 per cell; baselines = bare agent, prompted agent (`Intent` principles), the established per-language tool where installable (e.g. Frama-C for C, Verus for Rust); readability = proxy metrics only (lines + definitions to trust, LLM-judged), no timed human review.
- Benchmark v2 outcomes (user ruling): the bench exists to make three sentences true — bug-finding "a bare agent 'verified' X; FVA showed the shipped binary is wrong"; readability "a ~25-line spec of Y a biologist can read, proven about the real binary"; direct link "the Pachter lab's Lean theorem now applies to the code they ship". Subjects = graspable by most bioinformaticians + explainable to lay people, plus one non-bioinformatics example.
- Benchmark v2 subjects (user ruling):
  - LZ4 block format (non-bio): proofs on lz4 (C) + lz4_flex (Rust); bug-finding target = uBlock Origin's shipped hand-written wasm codec `src/lib/lz4/lz4-block-codec.wasm` (1,226 B, = gorhill/lz4-wasm dist): encoder breaks End-of-block condition 3 on ~5% of blocks (minimal repro `abaaaaaaaaaba` → block `316162610100506161616261`, official `LZ4_decompress_safe` at exact size → −2); decoder reads past its input on the spec's empty block `00`.
  - edgeR (bio): bug-finding = `filterByExpr` exact-threshold boundary (C `cpm` count·1e6/lib vs R `min.count/median·1e6` rounding: a median-library sample with exactly `min.count` reads fails in ~13% of library sizes, edgeR 4.10.7 + 4.99.10); proof target = the `cpm` C core in R-universe's shipped emscripten `edgeR.so` (exports `calc_cpm_raw`/`calc_cpm_log`); certification + spec-ambiguity case = TMM (R) vs RNAnorm (Python): equal-in-exact-arithmetic A-value formulas round differently, tied genes at the 5% trim fall differently (18/150 datasets, ≤ 0.94%).
  - Direct link = PFlog (runorm, Rust) ↔ the Pachter lab's Lean CLR uniqueness theorem; honest form carries a proven floating-point tolerance.
- Bench protocol (user ruling): arms get plain-language requirements only; headline spec metric = total trusted surface at equal faithfulness, requirement statement and link/model trust reported apart; a pilot run sets the per-run cap; runs on pinned CPUs. No blinded reference judge; FVA's library is not frozen against the subjects, so results state that FVA was built with the subjects known.
- Disclosure (user ruling): upstream reports after the bench runs, for the uBlock Origin / gorhill lz4-wasm codec and RNAnorm's TMM parity claim only.
- Managed-language link (consultant ruling under the user's research-first rule): per-output certification (D22) built once, exercised by unchanged Python, R, Java + TypeScript producers; exact-byte binding (decode the original output bytes, never runtime-rounded values); accepted-output theorems reported apart from artifact theorems (the tag marks attachment, not quantifier strength: a compiler-output certificate can prove ∀ inputs for one artifact). Deferred: WasmGC (TeaVM, J2Wasm, p2w), bytecode/AST lifting (CPython, R, JVM), interpreter-in-wasm proofs (Pyodide, webR, QuickJS); Waspy/AssemblyScript = conditional feature-inventory probes on unchanged code only.
- Review flow (user rulings): review-ledger + attest, pattern-catalog, review-page = kept for a later scope (tags `archive/review-ledger`, `archive/attest`, `archive/pattern-catalog`, `archive/review-page`; D25–D27); predict-quiz + spot-the-mutant = retired (tags `archive/predict-quiz`, `archive/spot-the-mutant`).
