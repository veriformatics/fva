### Q4

Remaining risks, ranked by semantic distance from the spike:

1. **SegD near-end I3 + prologue = highest.** `Seg.lean:183–205,226–244` combines offset≥8 memcpy, eight table cases for offset<8, a capacity error **after** prologue writes, far/near wildcopies, and the final byte tail. `dec64` includes `2^32−1`/`2^32−4` (`:211`): exactly the kind of concrete modular literals implicated in both arms' S2 normal-form failures. Keep these biases symbolic. The near-end wildcopy may write past `oend−7`, then its source pointer is reset to the exact unrounded limit before the byte tail (`:200–205`); reusing `wc_until` requires the correct memory summary **and** that pointer adapter. Frozen `HeadLocals`/error stores must match, not merely the final decoded prefix.
2. **I3 is an unproved compiled-loop/continuation shape, not the first demonstrated memory-evolving byte loop.** C's S1 `cp1_until` already inducts over arbitrary forward-overlapping byte copies, changing memory each iteration and composing `fwdCopy` (`C/FVATest/Subjects/Lz4C/SpikeC/S1.lean:11–45`). Its seven-slot locals and loop body are not func 2's nineteen-slot tail, so adaptation is real work, but the relevant engine/memory pattern exists. Use a small byte-tail `Until` summary, ordinary decreasing-counter induction, and `fwdCopy` composition; do not infer its cost from read-only SegC or unroll a symbolic whole loop through `blockEval`.
3. **SegB = callee/continuation + state-preservation seam.** The near path must invoke S2 and return through the real caller frame; the far path invokes S3, then reads offset bytes from memory that the scratch copy must leave unchanged (`Seg.lean:61–97`). Both current buffer separation and exact `move` versus `fwdCopy` summaries matter. S5 and `wc_until` support feasibility; they do not measure this full return/offset adapter. Nineteen-local normalization is the known iteration-cost hazard, not a new semantic interpreter.
4. **ExtL1B = closed shared work, preserve it.** `Cut/ExtB.lean:229–249` proves the broad statement and composes `segA`; `Cut/SegA.lean:128–154` retains reachable overflow and the exact bound exit `p+k=lim`. SegC assumes a 2 MiB profile and excludes overflow (`C/FVATest/Subjects/Lz4C/SpikeC/SegC.lean:143–174`); it cannot replace that proof unchanged. Do not charge this closure as C transfer evidence or redo it to homogenize engines.

Mitigation = small block/callee summaries with symbolic memory, exact cutpoint adapters, and resource/replay checks as each root closes. Both engines still need these invariants. `Top.r1_of`, `r2_of`, `r3_of` consume the same seven cutpoint hypotheses (`FVATest/Subjects/Lz4C/Top.lean:193–234`); risk is obtaining the exact cutpoints, not a missing engine-specific top composition.
