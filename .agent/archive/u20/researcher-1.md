## Detail R1.2 — performance evidence boundary

Sources inspected: LNSym benchmark command/scripts + benchmark inputs; Lean #14329 + #14331 verbatim page text; official 4.34/4.35 releases; pinned Kraken experiment sources (R1.8). No upstream builds executed. Prior survey already records whole-build timings; the new granular issue table distinguishes final metavariable instantiation from total elaboration.

- [#14329](https://github.com/leanprover/lean4/issues/14329), reporter's initial probe table: `N=27` approximately `25 ms` in 4.29; OOM in 4.30–4.32; `17.4 ms` after reverting the implicated substitution change. Later comment's separate table: `N=27 ... 0.477 ms` with PR #14520. The issue explains what is timed: “the single `instantiateMVars` call on the final proof term”. These are **not full theorem times** and are not comparable to total `58 s` from the initial whole-proof table.
- Same issue's investigator: “at N=10 the profiler reports 28ms of tactic execution, but 7.4s of instantiate metavars and another 6.5s of share common exprs”; “each step references the previous step's effect hypotheses 3–4 times”. The proof DAG is intended to share those references; fused substitution was copying open terms under binders. [4.34 release](https://lean-lang.org/doc/reference/latest/releases/v4.34.0/) confirms the shipped fix: “Lifting substituted values is now memoized and canonicalized across a whole pass, restoring linear behavior”; “exceeding 41GB ... about 1.2 seconds”. The current regression status is therefore **fixed**, not a generic warning that Lean 4.35 cannot step this many instructions.
- [#14331](https://github.com/leanprover/lean4/issues/14331): source explains the separate kernel issue: “`simp` no longer emits proof terms for `rfl`-`@[simp]` lemmas and instead relies on the kernel to re-derive each such rewrite by definitional reduction”. ### Read-before-write aliasing, not disjointness by fiat

[PLDI24 cryptographic-server paper §2.3](https://adam.chlipala.net/papers/GarageDoorPLDI24/GarageDoorPLDI24.pdf), exact specification excerpt (paper text):

```text
fnspec! "memmove" (dst src n : word) / (d s : list byte) (R Rs : mem -> Prop),
{ requires t m := m =* bytes src s * Rs ∧ m =* bytes dst d * R ∧
                  length s = n :> Z ∧ length d = n :> Z ∧ n <= 2^31;
  ensures t' m := m =* bytes dst s * R ∧ t=t' }.
```

The two heap views use **ordinary conjunction** on the same `m`; each has its own separating frame. “The source frame Rs is intentionally unused in the postcondition to indicate that it may not be preserved.” “Each non-separating conjunct is solved independently, instantiating each frame quantifier through cancellation.” This permits source=destination or partial overlap, while preserving only the destination's complement. Footnote: the memmove proof relies on Bedrock2's permissive semantics for comparing addresses across allocations; it is not a direct drop-in C provenance proof.

Effort evidence, same paper §2.4: “specification and proof of memmove (2 days)”; §4: “memmove (350 and 21 lines)”. This is a manually written Bedrock2 program integrated through a verified compiler; it is **not** 350 lines of direct Wasm instruction proof. Its relevant contribution is the overlap contract + call automation, not an FVA performance ratio.

**Inference for U19:** a helper contract can use an initial-memory snapshot and a functional interval update, plus a destination frame. Prove access bounds separately over all helper execution prefixes. LZ4's *match* loop often intends forward recurrence through freshly written output; snapshot memmove is not interchangeable with it. No complete direct binary memmove proof in the inspected LNSym, Islaris, or s2n examples was confirmed. Searches: `"machine code" "memmove" "proof" Isabelle HOL Coq`, the three pinned repository trees, Islaris memcpy paper/source, PLDI24 memmove source-verification paper. This is a bounded none-found, not nonexistence.

[Main `Kraken/Tactics.lean:127–194,343–356,366–436`](https://github.com/AeneasVerif/kraken/blob/c9aa45ee1b273892d7efa7bbf8a8a9391e17b2c0/Kraken/Tactics.lean#L127-L436): hoists let-bindings before unfold/reduction so they are not silently inlined; maximal-shares expressions; `Sym.dsimp` + cached `Sym.simp`; indexes spec lemmas in a discrimination tree; tries ground simplification/assumptions then `grind` for side conditions.
