### Q4

**Prioritize exact-state composition and normal forms, not more instruction execution machinery.**

- **ExtL1B:** no remaining engine decision. Main has `extL1B : ExtL1B` and `segA := segA_of extL1B` (`FVATest/Subjects/Lz4C/Cut/ExtB.lean:229–249`). Its domain permits arbitrary `acc < 2^31` and reachable overflow (`Cut/SegA.lean:128–154`); SegC's profile excludes overflow. Preserve this shared proof. Counting it as a successful C transfer or requiring C to rewrite it would both distort the remaining-work picture.
- **SegB:** three different exits plus calls under nested caller/frame contexts (`Seg.lean:52–97`). S2 supplies the exact `memmove` semantics, S3 the literal wildcopy; the new risk is carrying the returned memory, constant/dead locals, source offset bytes and footprint through the near/far join. Literal writes must preserve the original source bytes used to decode the offset. S5 is closer evidence than read-only SegC, but is not a ready-made SegB adapter. Keep callee summaries symbolic rather than unfolding them into the block evaluator.
- **SegD, highest risk:** small offsets combine a zero write, four byte copies, table reads and signed-bit-pattern entries `4294967295/4294967292`; errors after the prologue must retain the written store (`Seg.lean:183–244`). C already needed symbolic BitVec bases to avoid large-normal-form recursion in S2 (`spike-c/report.md:189`). Use symbolic pointer/copy boundaries before feeding these terms to `wasm_eval`; preserve `ReadSet`'s table region as well as both buffers. `Match.match_holds` already connects the exact memory model to format-level copying (`Match.lean:372–396`), so this is a compiled execution-linkage gap, not missing functional-model mathematics.
- **I3 near-end byte loop:** a new compiled loop/local layout and near-wildcopy-to-byte-tail join remain. It is not the first demonstrated memory-evolving byte-loop class: C's `cp1_until` already inducts over current memory, executes a byte load/store and composes `fwdCopy` (`C/FVATest/Subjects/Lz4C/SpikeC/S1.lean:11–45`); `wc_until` generalizes evolving memories and call contracts (`Wild.lean:23–94`). Its code/context differs from I3, so only the invariant/composition pattern transfers. Keep stores symbolic and prove one iteration, then induct; avoid treating the compiled decoder as one concrete evaluator expansion. C's `cp4_until` needed eight explicit access facts (`S1.lean:61–75`), and nested-label SegC required depth 4000 (`spike-c/report.md:227`): those are concrete warning signs for the table+memory joins, not evidence of inevitable failure.

These are prospective risks inferred from frozen source and recorded failures. No SegB/SegD production result after the cut-offs is used. No performance or completion forecast follows.
