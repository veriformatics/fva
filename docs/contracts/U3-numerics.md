# U3 contract — Wasm numerics: integers + IEEE-754 floats (tier: kernel)

Purpose: the value-level meaning of every numeric instruction in profile P, reviewed once and shared by every subject (Decisions: Trusted base, Floats). Reviewed spec = `FVA/Spec/Numerics/{Int,Float}.lean`; verified impl = `FVA/Impl/Numerics/{Int,Float}.lean` (kernel-evaluable, proven against the spec); evidence = the official numeric tests + difftest. Consumers: U4 semantics (instruction → op), U8 proof library (rounding-error lemmas), U14 bench (edgeR `calc_cpm_raw`: f64 mul/div).

## Spec (reviewed once)
- N1 Integers (Wasm 2.0 §4.3.2): i32/i64 values = `BitVec 32/64`. Each op is written spec-shaped: `signed`/`unsigned` interpretations into ℤ/ℕ, then back modulo 2^N (e.g. `idiv_s i j` = truncate(signed i / signed j), `none` when j = 0 or the quotient is 2^(N−1)). Partial ops return `Option` (`none` = trap). Ops: add sub mul div_{u,s} rem_{u,s} and or xor shl shr_{u,s} rotl rotr clz ctz popcnt eqz eq ne lt/gt/le/ge_{u,s} extend{8,16,32}_s; conversions wrap, extend_{u,s}. Lean core `BitVec` operations may appear only inside proofs of the impl, not as the spec's definition (the spec mirrors the Wasm text so a reviewer checks it line by line).
- N2 Float formats: `Format` = precision p + emax (binary32 = 24/127, binary64 = 53/1023); bits = `BitVec 32/64`; `classify : bits → {nan s payload (payload ≠ 0), inf s, finite s m e}` per the IEEE 754 encoding (biased exponent, implicit bit, subnormals); finite value = (−1)^s · m · 2^e ∈ ℝ (Mathlib).
- N3 Rounding (IEEE 754-2019 §4.3.1, roundTiesToEven) as a relation on ℝ: `RoundsTo F x r` ⇔ r is a representable value of F nearest to x, a tie broken to the one whose canonical significand is even; `Overflows F x` ⇔ |x| ≥ 2^emax·(2 − 2^−p) (result ±∞ with x's sign). Representable = m·2^e with |m| < 2^p, e within the format's exponent range (subnormals included); canonical significand = the normalized one (subnormal: e = emin − p + 1).
- N4 Operations per Wasm 2.0 §4.3.3, as relations `bits → … → Set bits` (singleton except NaN results): fadd fsub fmul fdiv (exact real result rounded; ±0 sign rules; ∞ and NaN cases), fsqrt (rounded √; −0 ↦ −0; negative ↦ NaN), fmin fmax (−0 < +0; NaN in ↦ NaN out), fabs fneg fcopysign (sign-bit ops, payload preserved), fceil ffloor ftrunc fnearest (integral rounding, ties to even for nearest, sign of zero kept), feq fne flt fgt fle fge (NaN ↦ false except ne; −0 = +0).
- N5 NaN results (§4.3.3 `nans_N{z*}`): canonical NaN set (payload = 2^(p−2), either sign) when every NaN input is canonical (or none), arithmetic NaN set (payload ≥ 2^(p−2), either sign) otherwise. Claims quantify over every allowed result.
- N6 Conversions: `trunc_{s,u}` = `none` (trap) on NaN, ±∞ or out of range, else truncation toward zero; `trunc_sat_{s,u}` saturate (NaN ↦ 0); `convert_{s,u}` = rounded exact integer; `demote` = rounded value (NaN ↦ nans{z}); `promote` = exact value (NaN ↦ nans{z}); `reinterpret` = bits unchanged.

## Implementation (kernel-shaped, U2 lessons: `bif` on `Nat.blt/beq`, direct `Nat`/`Int` ops, no `Decidable`-driven `if` on hot paths, structural recursion)
- I1 Integer ops over `Nat` (values < 2^N) with the spec's `Option` traps; proven equal to N1.
- I2 One rounder `roundFrac F (s : Bool) (n d : Nat) : bits` for the exact non-negative rational n/d (d > 0) with sign s: normalize by an exponent search on `Nat.log2`, integer division with remainder, ties to even, subnormal + overflow handling. add/sub/mul/div/convert/demote compute their exact result as (s, n, d) from decoded inputs and call it. `fsqrt` uses `Nat.sqrt` on a scaled significand with a remainder test (its own rounding lemma: r rounds √x ⇔ the rounding interval of r, squared, brackets x).
- I3 Theorems: `roundFrac_spec : RoundsTo F (n/d) (value (roundFrac …))` or overflow ↦ ±∞; per op `impl x y ∈ spec x y` (equality for non-NaN results); every impl op total and kernel-evaluable.

## Open for the consultant
- C1 Spec domain: ℝ (Mathlib) relational `RoundsTo` as above vs ℚ-only (exact rational results; `fsqrt` by squared bounds). Review-surface cost vs U8/U16 needs (error bounds, `Real.log` host contract).
- C2 Rounding definition: nearest-representable + canonical-even + overflow threshold (declarative) vs a constructive definition (⌊x/2^e⌉ with exponent formula); which is easier to review and to prove the impl against?
- C3 Integer spec: ℤ-shaped transcription vs Lean core `BitVec` ops as the spec (smaller surface, but semantics live in core and differ in edge cases such as `sdiv` overflow).
- C4 NaN representation: `Set bits` per op vs a relation `OpResult` vs a deterministic choice + separate "allowed set" lemma; consequences for U4's nondeterministic semantics and for claims.
- C5 Evidence sufficiency for a kernel unit whose impl is proven: is E1 + E3 the right weight, and what would a reviewer of the spec compare it against (IEEE 754 text, Wasm §4.3.3, Flocq)?
