# U12 contract — mutation check over the verified modules (tier: kernel infra)

Purpose: Decisions "Self-verification" — "a Lean mutation check on verified modules (each mutant must break a theorem or a test)". Claim delivered: every enumerated viable mutant of the scoped definitions is rejected by a proof or a test, or carries a current independent ruling; the report states its coverage (scoped declarations, zero-site declarations, sites per operator). A proof rejection is mutation evidence (the proof no longer checks), not a proof that the theorem became false; finite first-order operators never show that every behavior is pinned. Second consumer = Engineering law: a test pinning already-passing behavior counts once this tool shows it killing the mutants of the files it imports or calls. No downstream re-check exists, so every classification errs toward `survived`/`inconclusive`/`error`, never toward `killed`. Rulings below = consultant-5 review (C1–C8, D1), all accepted; user rulings: committed results table, `--update` via the offload pool, fast gate runs every stale mutant, scope = impl + shared helpers.

## Scope (S)
- S1 Groups (data: `FVATest/Mutate/config.json`): `decode` = `FVA/Impl/Decode/**`, `float` = `FVA/Impl/Numerics/**`, `exec` = `FVA/Impl/Exec/**`, `helpers` = every definition in `FVA/Spec/**` whose constant an impl definition's value reaches (transitive closure over definition values in the imported environment, by defining module, never by name prefix). Never mutated: theorems, Prop-valued definitions, `structure`/`inductive`/`class` declarations, generated constants. Later verified modules (U7 verdict function, U9 checkers, U6 validator) join through the config in one batch before the phase-close `--fresh` run (the groups enter the manifest, so any group change makes every row stale); until then each unit's E-evidence = an ad-hoc run with its own config (`fvamut update --config <copy with the unit's group>`, cache only).
- S2 Sites = terms in definition bodies (`def`, `abbrev`, `instance` values, equation RHSs, `where` helpers), never signatures, binders, match/equation patterns, the type side of `(e : T)` (its `e` stays), `by` blocks, `termination_by`/`decreasing_by`, attributes, `deriving`, comments, docstrings or string literals.
- S3 Inventory per run: scoped declarations with site counts (zero-site ones listed), excluded declarations with the reason.
- S4 Ad-hoc scope (per-unit test mutation): `--files`, `--decls`, `--stages` select a subset and never write the table. `--files`/`--decls` only filter (each selected mutant runs exactly as configured, so its execution is reusable); `--stages` changes the stage line inside every digest (R2), so such a row never stands in for a configured one.

## Operators (O) — default set
Sources: mCoq Table I (Coq), PIT defaults (Java), tollgate `check_lean_mutants` (Lean); excerpts in Sources.
- O1 `ROR`: `<`↔`≤`, `>`↔`≥`, `Nat.blt`↔`Nat.ble`, `Nat.beq`→`Nat.blt`.
- O2 `EQN`: `==`↔`!=`, `=`↔`≠`.
- O3 `LCR`: `&&`↔`||`, `∧`↔`∨`.
- O4 `BOOL`: `true`↔`false`; `!e` → `e`.
- O5 `AOR`: `+`↔`-`, `*`↔`/`, `%`→`/`, `Nat.add`↔`Nat.sub`, `Nat.mul`↔`Nat.div`, `Nat.mod`→`Nat.div`, `min`↔`max`; integer division family `tdiv`↔`fdiv`, `tmod`↔`fmod`, `ediv`→`tdiv`, `emod`→`tmod` (qualified `Int.f a b` and method `a.f b` spellings).
- O6 `BIT`: `&&&`↔`|||`, `^^^`→`|||`, `<<<`↔`>>>`, `Nat.land`↔`Nat.lor`, `Nat.xor`→`Nat.lor`, `Nat.shiftLeft`↔`Nat.shiftRight`.
- O7 `LIT`: numeric literal `n` → `n + 1` (same base), plus `1` → `0`.
- O8 `GIB`: `if`/`bif` branches swapped.
- O9 `GME`: match alternative `i ≥ 2` → RHS of alternative `i − 1`.
- O10 `LST`: `x :: xs` → `xs`; non-empty `[a, …]` → `[]`; `xs ++ ys` → `ys ++ xs` | `xs` | `ys`; `e.reverse` / `List.reverse e` → `e`.
- O11 `OPT`: `some e` → `none`.
- O12 `NEG`: unary `-e` → `e`.
- A mutant whose edits reproduce the original bytes, or another mutant's edits, is dropped.

## Mutants (M)
- M1 Mutant = one operator variant at one site = non-overlapping byte edits on one file (first-order).
- M2 Id = `<path>:<decl>:<op>:<k>` (`k` = index among that operator's mutants in that declaration, ordered by position, operator, replacement) + snippet (original → replacement); deterministic for a given tree.
- M3 Parsing = Lean's frontend over the file command by command (one process per file), so local and imported notation parse as in a build; every edit range's original text equals the source bytes at that range.

## Kill pipeline (K)
- K1 Snapshot: at run start the primary tree is built, then copied once (tracked + untracked-unignored files, `.lake/build`, `.lake/config`); workers fork from the snapshot; `.lake/packages`, `.tools`, `.cache/corpus` are shared read-only by contract and covered by an integrity manifest taken before and after the run (change → `error`). The primary tree is never written except `results.tsv` in update mode.
- K2 Positive control + baseline per mutated module: a probe mutant appends a fresh unused definition (`fvamutProbe…`), which changes the module's `.olean` and rebuilds every dependent; it must pass every stage of its group, else the run aborts (rc 2). Its per-stage wall-clock sets that module's limits (K6).
- K3 Stages per group, in config order: `module` (build the mutated module), `proofs` (each downstream module of the proof roots built alone, in topological then lexicographic order, so the first failing module is deterministic), `exes` (the test executables), `test:<name>` (one test command). A stage runs in a fixed environment (`env -i` + `PATH`, `HOME`, `LANG`; no `LEAN_*` overrides).
- K4 Witnesses: `killed` needs a recognized rejection — a Lean `error:` located inside a theorem, `example` or `#guard` (of the mutated module after line mapping, or of a downstream module), or a test command exiting exactly 1. Test commands follow the rc protocol 0 = pass, 1 = assertion failure, 2 = setup/infrastructure failure (missing tool, fetch, build, spawn), 3 = the program under test died by a signal; `fva difftest` reports an unrunnable wasmtime as rc 3, which the scripts map to 2.
- K5 Outcomes (first decisive stage wins): `unviable` = a located error in a non-theorem declaration of the mutated module (`downstream-unviable` when in a downstream module): the mutant is not a program, never a kill; `killed` (K4); `inconclusive` = a resource diagnostic (heartbeats, recursion depth, deep recursion, deterministic timeout, stack, memory), a test rc 3 (crash), a build whose Lean process died without a diagnostic (`INTERNAL PANIC`, e.g. a `Nat.pow` exponent past a machine word, or `Lean exited with code` with no located error) or a stage wall timeout — the pipeline continues with the stages that do not depend on the failed one, and the row stays `inconclusive` unless one of them kills; `survived` = every stage passes; `error` = anything else (any other unlocated build failure, test rc ∉ {0, 1, 3}, malformed diagnostics, a worker write outside its temp dirs, shared inputs changed) → the run fails.
- K6 Stage limit = max(60 s, 5 × the probe's wall-clock for that stage); a timed-out or crashed mutant reruns alone after the others finish, at 3 × the limit, before it may stay `inconclusive`.

## Results + cache (R)
- R1 Committed table `FVATest/Mutate/results.tsv` (generated, sorted by id, hidden from `rg` by `.ignore`): id, mutant key (hash of the module's bytes + the edits), outcome, killer (stage + module:line or test name), dependency digest.
- R2 Dependency digest = hash over the execution manifest + the deciding stages + the outcome's input files (path + sha256 each): manifest = the runner's sources (`FVATest/Mutate/*.lean`), the configuration minus per-group stage lists, test argv and outcome-neutral fields, `lean --version`, `lake --version`, sha256 of the pinned test tools (`.tools/bin/*`), `lean-toolchain`, `lake-manifest.json`, `lakefile.toml`; deciding stages = the group's stages up to the killer's (all of them for `survived`/`inconclusive`), each test with its argv; host-specific inputs stay out (binary bytes, unpinned system tools such as `jq`/`bash`/coreutils, Lake's dependency-config cache), so a committed row stays current on CI and every pool host — the unpinned tools are assumed behavior-stable for the scripts' use; inputs = `unviable`/killed in the mutated module: its upstream closure; killed or downstream-unviable at module P: P's upstream closure; killed by test T: the closures of T's executable roots + T's script + its declared helper scripts + data files; `survived`/`inconclusive`: every build root's closure + every test's inputs. Closures come from the files' `import` headers, so an added or removed module changes them.
- R3 Trust model: a row is a deterministic cache of one runner execution; it is reused iff its mutant key and its recomputed dependency digest match. Validity rests on identical inputs + determinism + the runner being correct (trusted infrastructure). `--fresh` regenerates every row ignoring both caches (once per phase, after its last scope or runner change). The spot-check (G1) is a cache-health canary, not validation of unsampled rows.
- R4 Local cache `.cache/mutate/` = one file per (id, mutant key) execution, same digests; a pool run's `--get .cache/mutate/exec/` merges its executions back.
- R5 Worker restoration after each mutant: the source file rewritten; `.lake/build` files changed since the mutant began (by ctime, which `cp -p` cannot preserve) restored from the snapshot, with a full copy when the file listing still differs; the rest of the tree compared by content hash (mismatch = `error`, worker re-forked).

## Rulings (L)
- L1 Every `survived` or `inconclusive` row needs a ruling in `FVATest/Mutate/rulings.tsv`: id, snippet, verdict (`equivalent` = no input distinguishes the mutant, argument given | `unspecified` = the governing contract leaves this behavior open, clause named | `resource` = an inconclusive row whose cost growth is the mutant's only effect, argument given), digest of the mutated declaration's source text, contract path + its digest (for `unspecified`), reviewer, reason (length as the argument needs). A survivor whose behavior a contract specifies gets a theorem or a test instead.
- L2 A ruling is stale when its id or snippet matches no current survivor/inconclusive row, or its declaration or contract digest changed → rc 1. Duplicate ids, `resource` on a non-inconclusive row and `unspecified` without a contract are rejected.
- L3 The reviewer differs from the author of the tests and proofs involved (Engineering law); MAIN-drafted rulings stay open `.agent/review.md` rows until the closing-diff reviewer rules them.

## Gate (G)
- G1 Full (`scripts/test-mutation`, in `scripts/gate`): exact inventory (no missing, extra or duplicate row); every row current (else rc 1: stale, run `--update`); no unruled `survived`/`inconclusive`, no stale ruling, no `error`; a current committed row whose execution in `.cache/mutate/` has another outcome → rc 1; spot-check: 3 rows seeded by the source tree's hash (generated files excluded) rerun fresh and must reproduce outcome + killer. Writes no tracked file (only its local cache under `cacheDir`). An ad-hoc selection (S4) must have a current row (table or cache) for every selected mutant.
- G2 Update (`scripts/test-mutation --update`; `scripts/gate --fast` runs it; heavy runs go through the offload pool): runs every stale mutant (local cache first), rewrites `results.tsv`, then applies G1's ruling and inventory checks. `--fresh` = update ignoring both caches.
- G3 Workers: default = cores ÷ 2 (minimum 1; `--workers 0` is a usage error), each a K1 fork; Lake and test parallelism inside a worker stay at their defaults unless the config caps them. A run that leaves any selected mutant without a result is a finding.

## Evidence (E)
- E1 Fixture battery `FVATest/Mutate/fixture/` (Lake package on Lean core alone) in `scripts/test-checks`, exact rc + outcome + killer per case, with clean positive controls: theorem kill; test kill; unviable; downstream-unviable; resource error → inconclusive; wall timeout → inconclusive; test rc 2 → error (run rc 1); missing tool before the baseline → rc 2; broken baseline → rc 2; unruled survivor → rc 1, ruled → rc 0; ruling with a changed declaration → stale rc 1; stale table → rc 1 in full mode; missing/duplicate row → rc 1; wrong killer in a sampled row → rc 1; a change to each dependency class (module, test script, data file, stage argv) reruns exactly the rows it covers; mutant A then B then the baseline reproduce clean results; shared inputs unchanged after the run; one positive per operator + spelling, each exclusion (comment, string, pattern, signature, `by`, ascription type) and the kept ascription term, Unicode offsets, a zero-site declaration in the inventory; neutering the check (forced `exit 0`) makes `scripts/test-checks` fail. Sampling limit: an erroneous unsampled row passes G1 (documented, asserted).
- E2 First full run over S1: counts per group × outcome; every survivor and inconclusive row killed by a new theorem or test, or ruled; `results.tsv` + `rulings.tsv` committed.
- E3 Cost: cold wall-clock + CPU per group and stage order; incremental cost after a one-line edit to `FVA/Impl/Exec/Ref.lean` and after an edit outside the scope; G1 wall-clock in the gate.

## Sources (verbatim excerpts)
- mCoq, Celik et al., ASE 2019 (`CelikETAL19mCoq.pdf`), Table I: "GIB Reorder branches in if-else expression"; "GME Replace expression in the second match case with the expression from the first match case"; "LRT Replace list with its tail"; "LRE Replace list with empty list"; "LAR Reorder arguments to the list append operator"; "LAF Replace list append expression with first argument"; "LAS Replace list append expression with second argument"; "NPM Replace plus with minus"; "NZO Replace zero with one"; "BFT Replace false with true"; "BTF Replace true with false". mCoq README: "If all proofs of a mutant are successfully checked, a mutant is declared live; otherwise it is declared killed". Paper: "proof checking in proof assistants is deterministic, which increases the potential for parallelization"; "we can use change impact analysis to perform selective proof checking during mutation proving".
- tollgate PR #23 body (MorphIQ-Labs, merged 2026-09-28, `gh pr view 23 -R MorphIQ-Labs/tollgate`): "The operators swap `≤`/`<`, `≥`/`>`, `+`/`-`, `=`/`≠`, `∧`/`∨` and `&&`/`||`, flip `true`/`false`, swap `min`/`max`, and drop `!`"; "It does not mutate signatures, which are types and preconditions, or definitions of type `Prop`. Those are specifications: weakening one always survives, because a stronger theorem still proves the weaker claim"; "**killed**: the error is in a theorem. **unviable**: errors only outside theorems, meaning the mutant doesn't typecheck. **survived**: no errors at all"; "Each original module must check clean first, so a broken setup can't make every mutant look killed"; "An allowlist entry that no longer matches a survivor also fails, so the list can't go stale"; result "225 killed, 7 unviable, and 1 equivalent" of 233.
