# U20 contract — proof-scaling method (IMPLEMENT orientation; costly to reverse)

Tiers: the method ruling = a `Decisions` entry resting on measurements → `scientist` (this design before the runs, the results before the ruling) + ≥ 5 `consultant`s on the draft ruling + advisor. Spike statements S1–S4 = proof-side, kernel-checked (`fva trust` later replays them through the decoder claims). Proof-library code an arm adds = untrusted tooling: its soundness is kernel-checked, so it adds nothing to the trusted base or the review surface.

Purpose: choose how the full R1–R3 proof of `LZ4_decompress_safe` (func 2: 550 instructions, 7 loops, 11 calls; callees `memcpy` func 3 = 93 instructions, 2 loops; `memmove` func 4 = 191, 4 loops) scales. Candidates (user request): (D) hand stepping — the small-step machinery (`wasm_cstepu`, `until_context_seq`, `Context`), provisional since U19; (R) refinement to a Lean model — model functions, a simulation lemma per model step, model-level theorems; (C) automated block summaries — a verified evaluator or decompiler proven against the stepper (D9: "a per-block evaluator (`decide`/`cbv` over straight-line blocks) proven against the stepper"), proofs then about its output. The slice = the user's I4 start (U19 inventory): separate ordered-copy contracts for `memcpy` and `memmove`, plus wildcopy loops composed with them.

## Spike design
- Arms = the finalists among D, R, C (ruled by MAIN from the method research before the first spike, recorded here); one fresh teammate per arm (sol lane, equal effort), each in its own worktree from one base commit; no arm sees another's work. Carryover between arms = none; author variation = one author per arm (a confound, recorded, not removable at this size).
- Order within an arm: S1 (first use), S2, S3 (composition with S1), S4 (reuse of S3's pattern), S5 (func 2's own code). An arm reuses its own earlier work freely.
- Mechanism boundaries (scientist-1 C9a): D+ steps through `Ref.seq` (`until_context_seq` & co.) with any tactic automation, no evaluator over instruction lists; V discharges the stepping by `vcgen` over its WP instance, direct stepping only inside the WP's soundness proof; C rewrites a verified evaluator, direct stepping only inside the evaluator's soundness proof. Each arm records which mechanism discharged each statement.
- Allowed: new proof-library code (tactics, lemmas, evaluators) in new files under `FVA/Proof/Lib/` + the arm's files under `FVATest/Subjects/Lz4C/Spike<Arm>/`; forbidden: edits to `FVA/Spec/**`, `Copy.lean`, `Ext.lean`, `Code.lean`, `Instance.lean`, the checkpoint-1 proofs, `sorry`, `native_decide`, `bv_decide`, `implemented_by`, new axioms.
- Budget per arm: 8 h wall-clock from its start, waits included; a teammate near its context limit writes a handoff note + commits, and MAIN may start a successor on the same branch within the same 8 h (initial context, compute and wait time recorded per arm). Exhaustion = "not completed under these conditions" + the last failed obligation + command/rc + failure class (ill-posed statement | missing reusable lemma | unresolved invariant | elaboration limit | exporter/checker limit | budget exhausted).

## Selection rule (frozen before the first spike; scientist-1 C3/C4/C9d repairs)
1. Eligibility: S1–S5 proven, standard axioms only, both default checkers accept, every theorem root type-checked against the frozen statement by MAIN's acceptance file (`example : MemcpyS1 := …`).
2. Cost vector per arm, every coordinate from committed per-stage checkpoints (one commit per statement): (a) new + changed hand-written code lines of the whole arm, stage by stage (infrastructure built while proving Sk counts in Sk; final roles reported beside); (b) M0 per stage; (c) fresh build time of all the arm's new modules; (d) export bytes of the cumulative S1…Sk roots minus the baseline export; (e) replay time per default checker of that cumulative closure, 3 repeated runs at the end (S1–S5). Vectors, never one number.
3. Dominance: arm X dominates Y when X ≤ Y on (a) total and (a) for S5 (the decoder-shaped stage) and is not worse than 2× on (b), (c), (e) (for (e): `min(X) ≤ 2 × max(Y)` fails = worse); a lone dominant arm wins provisionally. No dominance → inconclusive; the ruling argues the qualitative criteria (I7 fit at S5's exits + the prefix adapter, agent fit, maintainability, infrastructure cost against the remaining decoder) for the consultants + advisor, then the user.
4. Resource bound (eligibility): S1–S5's incremental replay ≤ 10 min per default checker and every arm module builds in ≤ 10 min; above = noted, eligible only if no arm is under it.
5. A single eligible arm = bounded readiness on this slice, not method superiority (scientist-1 C4); n = 1 author per arm (author × engine confounded, C2).

## Finalists (MAIN ruling from `.scratch/u19c2/researcher-{1..4}.md`, before the first spike)
- The four surveys agree that the three named options are composable layers, not exclusive pipelines: large compiled-code proofs pair a functional model (abstract valid prefix + a concrete-memory relation for scratch bytes) with automated stepping and callee contracts proven once, and their bulk is invariant reconstruction, not instruction stepping (researcher-2 R2.1/R2.2/R2.7, researcher-4 R4.5/R4.6, researcher-3 R3.1/R3.6, researcher-1 R1.1/R1.3). The architecture under test is therefore: refinement to a decoder model at the top (`FVATest/Subjects/Lz4C/Model.lean`, built by MAIN alongside, see I7 below) + one stepping engine underneath. The spike ranks the engine.
- Arm D+ (hand stepping, automated): the small-step machinery (`wasm_cstepu`, `until_context_seq`, `Context`, `wasm_access`) extended with whatever automation the arm builds (multi-step stepping to the next branch, automatic `Within` discharge for non-memory steps, concrete local lists, cached block lemmas, call contracts as `Until` lemmas).
- Arm V (VC generation): Lean 4.35's `vcgen` over `Std.WP` (release notes: "verifies deeply embedded languages, such as that of x64 assembler or WebAssembly"; `tests/elab/vcgenImp.lean`: callee contracts proven once, loop invariants), instantiated by a WP whose soundness the arm proves against FVA's `Until`/`Within` (and so `Step`): per-instruction specs, call specs, loop invariant rules, VCs discharged by `simp`/`omega`/`grind`.
- Arm C (verified block evaluator, D9): a big-step or symbolic evaluator over the structured fragment the code uses, proven sound against the stepper (`Ref.step`/`walk`, and so `Step`) with per-step footprints; proofs then rewrite the evaluator on symbolic state; the arm chooses its extent (straight-line blocks only, or structured control too).
- R as a separate S1–S4 arm: dropped. At the copy level the model is the statement itself (`fwdCopy`, `move` = the ascending and the snapshot copy); a model of the 4-byte-unrolled loop would add a layer, not discriminate (checkpoint 1 already compared D vs R at one loop, inconclusive). R's distinct value is at the decoder level (R2/R3), where it is adopted by design (top layer above), its model differentially tested against the binary before any simulation proof (I7).
