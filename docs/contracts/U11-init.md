# U11 contract — `fva init`, base manifest, agent guide, README (tier: docs + trust glue)

Purpose: Decisions "Distribution" (a project vendors the pinned FVA package, requires Mathlib at FVA's pin, works offline once Mathlib's oleans are cached) and "Human-review surface" (FVA base = vendored sources whose content hashes match the set the CLI pins, never by module name); the agent guide the bench's fva arm starts from; the human README.

## Built
- `FVA/Tool/BaseManifest.lean` = `(path, sha256)` of every FVA library source, generated by `scripts/make-base-manifest`; gate step `base-manifest` (`--check`, rc 1 when stale). `fva trust` counts an imported module as base only when its source is byte-identical to the manifest entry of its path (`FVA.Tool.Trust.baseModules`); an edited or unknown `FVA` file is project code in the review surface (not a FAIL: the reviewer reads it). The verdict that counts comes from an `fva` built outside the project (a project can edit its vendored copy, binary and manifest included).
- `fva init <dir> [--lib Name] [--wasm file]` (`FVA/Tool/Init.lean`): vendors `FVA/`, `FVA.lean`, `Main.lean`, the toolchain, manifest, canary tables, fetch scripts, LICENSE, README, AGENT.md into `fva/` with a lakefile of the library + CLI alone; the project lakefile requires `fva` by path; the project manifest = the vendored package by path + FVA's pins inherited (offline builds once Mathlib is present); `Spec`/`Proof`/root templates; with `--wasm` the artifact + its `Lifted.lean`.
- `AGENT.md` (agent-read: workflow, claim forms, proof method, kernel-cost rules, defect reporting, trust tags, certificates), `README.md` (human-facing).

## Evidence
- `scripts/test-init` (full gate): `fva init --wasm toy.wasm` + the toy claims/proofs → `lake build` → `fva trust` (outside binary) PASS with a 14-line surface; one vendored spec file edited → that file enters the surface (`FVA.Spec.CAbi: … lines`).
- Usage cases: an existing non-empty directory and a lower-case `--lib` → rc 2.
