# U6 contract — validation + type soundness (tier: kernel)

Purpose: "validated modules never get stuck" (Decisions: Self-verification, user ruling: type soundness proven this phase). A claim's `Must` already fails on a stuck configuration, so a stuck program is never mis-verified; U6 adds the guarantee that FVA's execution spec has no rule gap for valid modules, and a verified validator a project runs on its artifact. Not on the bench path (blocks U18 only). Type soundness proves neither termination nor the absence of specified traps (`Final` includes traps; host divergence is a self-step).

## Reviewed once (base, `FVA/Spec/Valid/*.lean`; oracle = Wasm `wg-2.0` §3 + appendix "Soundness", minus SIMD, transcribed rule by rule with § references)
- T1 Static typing: `OpType` = a value type or `⊥` (bottom) with matching (`⊥ ≤ t`, `t ≤ t`, pointwise on stacks); stack types over `OpType`, module/function signatures over concrete `FuncType`; `Context` (types, funcs, tables, mems, globals, elems, datas, locals as runs + lookup, labels, return, refs); `InstrT C i st`, `SeqT C es st` with the spec's composition by matching (`valid/instructions.rst` "Instruction Sequences") + a proved frame/subsumption presentation; stack-polymorphic instructions keep each real operand (`br_table` its `i32` selector; `br_if` consumes and restores its label arguments); representation well-formedness inside typing: constant literals `< 2^N`, legal width/operator combinations (raw `Module` inputs, so `validate : Module → Bool` needs no decoder premise); constant expressions (constants, `ref.null`, `ref.func`, `global.get` of an immutable imported global).
- T2 Module validity (§3.4): functions, tables, memories (imported + defined ≤ 1 in the profile: the combined index space), globals, element + data segments + modes, start (`[] → []`), imports, exports (distinct names), segment payloads under `2^32` elements (§2.2.5 vector bound, absent from the AST lists; `initCode` materializes both lengths as `i32` constants: prover-2 S2 witness = a valid module with a `2^32`-byte data segment whose init code is untypable); `C.refs` = the function indices occurring in the module outside function bodies and the start field (`valid/modules.rst` §3.4.10).
- T3 Runtime typing (appendix "Soundness"): `StoreOK s` (function instances typed against their module instance's context; tables: reference typing, `min = elem.length`, limits; memories within limits; globals typed; element/data instances typed); `InstanceT`, `FrameT`; administrative instructions (`trap` any type; `invoke a` the function's type; `label n cont body`; `frame n f body` with its return type) and thread typing with a return parameter; top-level `ConfigOK (c : Config) ts` = `StoreOK c.store` ∧ the thread typed with no pending labels and no return type (a free `br`/`return` at top level is ill-typed); `Context.Extends` for growing tables/memories (exact current minima).
- T4 Hosts: `HostPreservesStore H` (every returned/trapped outcome of a well-typed host call from a valid store has a valid store; divergence needs nothing) and `TypeSoundHost H := ValidHost H ∧ HostPreservesStore H` — extension (`Store.Extends`) is not validity (consultant-7 witness: a valid host appending an `i32` global holding an `f64`).

## Verified implementation
- V1 Validator `FVA/Impl/Valid.lean`: the appendix algorithm's operand/control-stack invariants by structural recursion over the nested AST (no flattening), checked lookups (label index = control depth rejected), compressed local runs (a run of 2^32 − 1 locals stays one entry), kernel-evaluable (decoder cost rules). `validate_sound : validate m = true → ModuleValid m`. Completeness deferred: row with acceptance `∀ m, ModuleValid m → validate m = true` on the profile.

## Theorems (proofs never read; teammate slices)
- S1 Preservation: `TypeSoundHost H → ConfigOK c ts → Step H c c' → Store.Extends c.store c'.store ∧ ConfigOK c' ts`, proven through typed-fragment preservation (arbitrary operand prefixes, label contexts, return types, locals, updated frames) — the closed statement is no induction hypothesis inside labels and frames.
- S2 Progress: `ValidHost H → ConfigOK c ts → (∃ o, Final c o) ∨ ∃ c', Step H c c'`, through fragment progress whose results are values, a trap, a typed pending branch/return with its block context, or a step.
- S3 Instantiation: allocation bridge (a valid module + matching imports in a valid store: typed constant-initializer values from the restricted initialization context — never assuming `StoreOK` of the store being justified — and a well-typed `initCode` configuration; initialization may still trap or diverge) + `TypeSoundHost H → StoreOK s → Instantiated H m s imports s' inst → StoreOK s' ∧ Store.Extends s s'` + an instance typing witness giving the export types; invocation lemma: a typed function lookup + `Forall₂ (Val.HasType s') args ft.params` → `ConfigOK (invokeConfig s' a args) ft.results`.
- S4 Corollary (`FVA/Self/Spec.lean`): `validate m = true`, `TypeSoundHost H`, `StoreOK s`, `Instantiated H m s imports s' inst`, an exported function `a` of type `ft`, well-typed arguments, `Steps H (invokeConfig s' a args) c` → `ConfigOK c ft.results ∧ ((∃ o, Final c o) ∨ ∃ c', Step H c c')`. Plus `validate_sound`.
- Obligations on the existing reductions (kept as reviewed): every allowed numeric result typed (`r ∈ numResults … → typed (numOut r)`) + nonempty for typed operands (reuse `FVA/Proof/Numerics/Total.lean`, `ofBits_wf`); `memory.grow`/`table.grow` success and failure; bulk instructions by their emitted element steps; the combined memory index space.
