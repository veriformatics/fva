## Vocabulary additions (FVA base, reviewed once; `FVA/Spec/CAbi.lean`)
(consultant-9 K1/K2: a fresh `Instance` keeps the module's declared page count, and `Fits` only reads the extensional `byte` field past `mem.size`; the lz4-wasm codec declares 1 page but needs a 17-page workspace, so a `Returns`/`ReturnsAfterWrite` over a fresh instance cannot state S2(a). The caller preparation is first class, and one admissibility predicate serves both the existence witness and the universal call.)
- V1 Caller preparation: `Prep` = `grow k` (memory 0 grows by `k` pages, the embedder's `memory.grow`/`Memory.grow` = `MemInst.grow`) | `write p bs`; `Store.prep : Store → List Prep → Option Store` applies them in order (`none` when a growth fails or a write would leave memory 0). `Prepared m ps s inst` = a fresh `Instance m H s0 inst` with `Store.prep s0 ps = some s`. One admissibility predicate `Adm` per claim names the room the result needs.
- V2 `ReturnsOut m ps name args results q out`: under every `H`, some `Prepared m ps s inst` with `Adm` holds; and from every such prepared instance, every execution ends, none traps, the results are exactly `results`, and the final memory 0 holds `out` at `q` (bounds asserted; this is a statement about final contents, not a record that a write happened — a call that leaves bytes already equal to `out` satisfies it, named in the claim's docstring).
- V3 `TrapsAfter m ps name args`: the same existence clause; and from every such prepared instance, every execution of the call traps.
- V4 (S4 only) a loader-prepared instance of a side module (imports supplied, `LoaderReady` = U4's relocation + constructor protocol, open review row L1) + contracts on named imported functions; shape fixed before S4's proof, reviewed with S4's claim.

## Pieces
- S1 LZ4 block format (tier kernel: the subject spec a reader trusts): `Lz4.Seq` (token, literals, optional 2-byte little-endian offset + match length with the 255-run extensions), `Parses b seqs` over byte lists, `Decodes b c` (sequential copy semantics, overlapping matches byte by byte, offset 0 invalid, offset past the output start invalid), `EndOk b` = End-of-block conditions 1–3 of `lz4_Block_format.md` (the format text quoted per clause: last sequence = literals only; last 5 bytes literals; last match starts ≥ 12 bytes before the end), `Valid b c` = parses + decodes to `c` + `EndOk`. Target surface ≈ 25 code lines. Evidence: a `reviewer` audits the transcription clause by clause against the pinned `lz4_Block_format.md`; differential = the committed reference decoder (`LZ4_decompress_safe`, lz4 C wasm) on a fixed vector set through `fva difftest`-style runs (exact-size outputs), each vector's `Valid` decided in Lean.
- S2 lz4-wasm codec counterexamples (tier data: concrete kernel runs; the claims are what a reader reviews): (a) from a prepared instance (`grow 16`, the hash workspace filled, the 13 input bytes at 262144 — the embedder setup the interface README states, matching the pilot witness `.scratch/u4/lz4-wasm-witness.lean`) `lz4BlockEncode` returns 12 and leaves `316162610100506161616261` at the output address (V2), and `¬ EndOk` of that block (consultant-9 K6: its last match starts at output offset 3, ten bytes before the end of 13 — the clause is "≥ 12 bytes before the end", so condition 3 fails; the "3 bytes" wording was wrong); (b) from a prepared instance whose input region holds the one-byte block `00` (which `Valid [0] []` accepts) followed by a fixed stale byte, `lz4BlockDecode` traps (V3), the stale byte the minimal witness from an `fva difftest`-style search, never claimed for every memory state. Both via `runDet` + `must_returned_of_runDet`/its trap analogue (433 stepper steps for (a); kernel ≈ 1.5 s, U4 E5).
- S5 GLM `glm::iround<double>` (tier data): the 66-byte module returns 1 on `0.49999999999999994` (`Returns`), whose nearest integer is 0; the claim "every finite x in [0, 2147483647] rounds to its nearest integer (either neighbor at an exact half)" is refuted by that instance (a theorem `¬ NearestAll`).
- S4 edgeR `calc_cpm_raw` (tier kernel: claim + V4 vocabulary reviewed; proof never read). Correctness notes from consultant-9 (compute_cpm.c:102–150, func 160) folded in: the counts are read from the caller's `cpm` buffer in place and scaled there (`(*cptr) = (*cptr)*1e6/lptr[lib]`); `y` supplies only `nrow` (offset 8) and `ncol` (offset 12). It makes two live allocations through the import — a pointer table (`R_Calloc(nth, ·)`) and one `nlib`-double row buffer — so the contract must give fresh regions disjoint from each other, from the inputs and from the output, and `R_chk_free` must preserve the output too. Claim: for every `cpm` buffer, library-size vector (read by `get_row`: full matrix with row stride + optional row selection, row-constant, column vector, scalar) and dimensions, under contracts on imports 12/13 (`R_chk_calloc(n, size)` → the address of `n·size` zero bytes in memory 0, fresh and disjoint; `R_chk_free(p)` → every byte outside `[p, …)` unchanged), from a loader-prepared instance (V4), `calc_cpm_raw` returns with every output entry in the IEEE f64 result set `fdiv (fmul cpm[i] 1e6) L` (membership, not bit equality: FVA's float ops are `Set FVal`, so NaN inputs give a set of allowed NaNs — consultant-9 K4) and every non-output input byte unchanged. Domain restricts to the scientifically meaningful inputs (finite counts, positive finite library sizes) where the result set is a singleton, so the claim reads as an equation; the NaN/∞ cases state set membership. Plus the filterByExpr boundary instance: at `count = min.count = 10` and a median library size `L` from the T4 evidence, the binary's CPM is below R's cutoff `10/L·1e6` (both IEEE double) — the filter drops a gene the documented rule keeps. Feasibility risk = high (nested loops over memory, two host calls, dynamic-linking context): consultant review of V4 + the claim before code; if the all-input proof stalls past two attempts, the boundary instance alone (concrete run) ships and the all-input proof becomes a deferred row.
- S3 TMM relation + certificates for the T5 outputs: proposed deferral (no outcome sentence rests on it; exact-arithmetic TMM needs rational log enclosures in the kernel) — user ruling pending.
