## Vocabulary additions (FVA base, reviewed once; `FVA/Spec/CAbi.lean`)
(consultant-9 K1/K2: a fresh `Instance` keeps the module's declared page count, and `Fits` only reads the extensional `byte` field past `mem.size`; the lz4-wasm codec declares 1 page but needs a 17-page workspace, so a `Returns`/`ReturnsAfterWrite` over a fresh instance cannot state S2(a). The caller preparation is first class, and one admissibility predicate serves both the existence witness and the universal call.)
- V1 Caller preparation (`FVA/Spec/CAbi.lean`, reviewed once, base): `Prep` = `grow k` (memory 0 grows by `k` pages = `MemInst.grow`) | `write p bs` (explicit bytes) | `fill p n f` (a region memset from a function `f : Nat → UInt8`, read in O(1) — a constant or periodic pattern such as the −65536 hash table; a 262144-byte `write` of a `List` makes every kernel memory read O(n), so the fill uses a function). `Store.prep : Store → List Prep → Option Store` applies them in order (`none` when memory 0 is missing, a growth fails, or a write/fill does not fit). `Prepared m H ps s inst` = a fresh `Instance m H s0 inst` with `s0.prep ps = some s`. `Fits s q n` (room) and `Holds s q bs` (memory 0 holds `bs` at `q`) state the result's region.
- V2 `ReturnsOut m ps name args results q out`: under every `H`, some `Prepared m H ps s inst` with `Fits s q out.length`; and from every such prepared instance, every execution ends, none traps, the results are exactly `results`, and the final memory 0 `Holds out` at `q` (a statement about final contents, not a record that a write happened — a call that leaves bytes already equal to `out` satisfies it, named in the claim's docstring).
- V3 `TrapsAfter m ps name args`: the same existence clause (no `Fits`); and from every such prepared instance, every execution of the call traps.
- V5 proof support (`FVA/Proof/Lib/Instance.lean`, not reviewed): `instance_alloc_self` (the canonical fresh instance), `must_returned_of_runDet_get` + `must_trapped_of_runDet_get` (a long `runDet` run kept as `Option.get` so `decide +kernel`/`kernel_rfl` close the return/trap + memory facts on the concrete final configuration, without writing the store out; the prepared and final stores are top-level constants so the kernel, never the elaborator, reduces them).
- V4 (S4 only) a loader-prepared instance of a side module (imports supplied, `LoaderReady` = U4's relocation + constructor protocol, open review row L1) + contracts on named imported functions; shape fixed before S4's proof, reviewed with S4's claim.

## Pieces
- S1 LZ4 block format (tier kernel: the subject spec a reader trusts; `FVATest/Subjects/Lz4/Format.lean`, 26 surface lines): `Lz4.Seq` (literals, 2-byte little-endian offset, match length), `ext`/`head` (the 4-bit token fields + 255-run length extensions), `Seq.bytes`, `Parses b ss last` over byte lists (sequences then the last literals; offset 1 … 65535, match ≥ 4 — minmatch folded into `Seq.len`), `copy`/`decode` (sequential copy, overlapping matches byte by byte, offset reaching before the output start = `none`), `EndOk ss last` = End-of-block conditions 2 + 3 (last 5 bytes literals; last match covers ≥ 12 bytes with the trailing literals), `Valid b c` = parses + decodes to `c` + `EndOk` (condition 1 = the `Parses` shape, a last all-literal sequence). `Lz4/Parse.lean` (proof support, outside the surface) is a fuelled parser proven to return every parse, giving `Parses.unique`. Evidence: a `reviewer` audits the transcription clause by clause against the pinned `lz4_Block_format.md` (E3); `.scratch/u14/format-check.lean` decides the document's length examples + the codec block + the empty/overlap/offset cases.
- S2 lz4-wasm codec counterexamples (tier data: concrete kernel runs; the claims are what a reader reviews; `FVATest/Subjects/Lz4Wasm/`, Spec 20 surface lines): one combined claim per broken requirement, each mentioning the subject so `fva trust` accepts it. (a) `encode_breaks_r1`: from the prepared instance (`grow 16`, the hash table at 0 filled with −65536 via `Prep.fill`, the 13 bytes `abaaaaaaaaaba` at 262144 — the interface README's embedder setup) `lz4BlockEncode` returns 12 and leaves `316162610100506161616261` at the output (`ReturnsOut`), and that block is not a valid LZ4 block of any content (`∀ c, ¬ Valid …`, via `Parses.unique`: its one parse fails End-of-block condition 3, the last match covering 10 bytes, not ≥ 12 — consultant-9 K6's "10 bytes before the end" folded in). (b) `decode_breaks_r3`: `Valid [0] []` holds, yet the empty block `00` written as the **last byte of the module's initial 1-page memory** makes `lz4BlockDecode last 1 0` read past its one input byte, off the end of memory, and trap (`TrapsAfter`) — a decoder obeying R3 returns 0 (as it does at any lower address). This boundary witness replaces the draft's "stale byte" idea: a search (`.scratch/u14/s2b*.lean`) found no stale byte traps while memory has room, so the faithful R3 witness is the memory edge, needing no grow. Both via `runDet` + `must_returned_of_runDet_get`/`must_trapped_of_runDet_get` (encoder 433 steps, `n = 600`; decoder `n = 200`; instruction equalities by `kernel_rfl` since `AInstr` has no `DecidableEq`; `test-subjects` ≈ 2.5 min, kernel-replay dominated).
- S5 GLM `glm::iround<double>` (tier data; done; `FVATest/Subjects/GlmIround/`, surface 10): `iround_breaks` = `Returns Lifted.module "iround" [.f64 belowHalf] [.i32 1]` ∧ the real value of `belowHalf` (= `0.49999999999999994`, bits `3fdfffffffffffff`) ∈ `(0, 1/2)` — so the nearest integer is 0, not 1. The module is `x + 0.5` then truncate; `x + 0.5` rounds up to `1.0` here. One combined claim mentioning the subject (the draft's standalone `¬ NearestAll` would not mention it); the real bound reduces `ofBits belowHalf` to `normal false (2^52-1) (-2)` then `norm_num`.
- S4 edgeR `calc_cpm_raw` (tier kernel: claim + V4 vocabulary reviewed; proof never read). Correctness notes from consultant-9 (compute_cpm.c:102–150, func 160) folded in: the counts are read from the caller's `cpm` buffer in place and scaled there (`(*cptr) = (*cptr)*1e6/lptr[lib]`); `y` supplies only `nrow` (offset 8) and `ncol` (offset 12). It makes two live allocations through the import — a pointer table (`R_Calloc(nth, ·)`) and one `nlib`-double row buffer — so the contract must give fresh regions disjoint from each other, from the inputs and from the output, and `R_chk_free` must preserve the output too. Claim: for every `cpm` buffer, library-size vector (read by `get_row`: full matrix with row stride + optional row selection, row-constant, column vector, scalar) and dimensions, under contracts on imports 12/13 (`R_chk_calloc(n, size)` → the address of `n·size` zero bytes in memory 0, fresh and disjoint; `R_chk_free(p)` → every byte outside `[p, …)` unchanged), from a loader-prepared instance (V4), `calc_cpm_raw` returns with every output entry in the IEEE f64 result set `fdiv (fmul cpm[i] 1e6) L` (membership, not bit equality: FVA's float ops are `Set FVal`, so NaN inputs give a set of allowed NaNs — consultant-9 K4) and every non-output input byte unchanged. Domain restricts to the scientifically meaningful inputs (finite counts, positive finite library sizes) where the result set is a singleton, so the claim reads as an equation; the NaN/∞ cases state set membership. Plus the filterByExpr boundary instance: at `count = min.count = 10` and a median library size `L` from the T4 evidence, the binary's CPM is below R's cutoff `10/L·1e6` (both IEEE double) — the filter drops a gene the documented rule keeps. Feasibility risk = high (nested loops over memory, two host calls, dynamic-linking context): consultant review of V4 + the claim before code; if the all-input proof stalls past two attempts, the boundary instance alone (concrete run) ships and the all-input proof becomes a deferred row.
