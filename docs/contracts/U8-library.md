# U8 contract — proof library, C-ABI + host-math vocabulary, worked examples (tier: shallow; the two vocabulary specs = reviewed once, audited at close)

Purpose: claims about lifted artifacts (U14 bench subjects, U16 PFlog, the README examples) are proven with reusable lemmas instead of per-proof stepper unfolding; the vocabulary the claims are stated in (buffers, pointers, host math) is reviewed once and shared (Decisions: Trusted base "C-ABI vocabulary", Direction "reviewed-once shared patterns + base modules shrink the per-project surface"). Every library theorem is kernel-checked: a wrong lemma cannot prove a false claim, so the library itself needs no review (shallow); the two specs it states claims in do (they enter every surface's trusted base).

## Library (`FVA/Proof/Lib/**`, imported by `FVA/Proof/Lib.lean`; never by `FVA.Tool.*` or `FVATest.Main`)
- L1 Symbolic execution: `walk k c` (k unique reference-stepper steps) + `must_of_walk`, `may_of_walk`; a simp set `wasm_step` (stepper equations + `toVal`/`isTrapOnly` facts) so a straight-line block closes by `simp only [walk, wasm_step]`; cost per instruction measured (E1).
- L2 Lifted module → run: from `Lifted.module` + concrete imports, `Ref.instantiate` evaluated (`decide`/`rfl`) to `(store, inst)` with `Instantiated` by `instantiate_sound`; `inst.exportFunc name` resolved; `CallMust`/`CallReturns` from a `Must` of the invoke configuration. For edgeR-scale modules: instantiation as a hypothesis (`Instantiated …` → the store facts a proof needs), never evaluated (U4 E5 ruling).
- L3 Loops: a structured-loop rule — an invariant `I` on locals + store, a measure, the body's walk from `I ∧ continue` back to the loop head with `I` and a smaller measure, and the exit walk from `I ∧ exit` → `Must` of the loop entry (generalizes `Spike.loop_must`).
- L4 Memory: `read`/`write` frame lemmas (disjoint ranges, same range, overlap-free sequences), `iN.load`/`store` ↔ little-endian `Nat`, sign extension, page bounds (`ea + k ≤ size`) side conditions in `Nat`, bulk `memory.copy`/`fill` effects as functions of the input store.
- L5 Arithmetic: `BitVec 32/64` ↔ `Nat`/`Int` under no-overflow side conditions (add, sub, mul, shifts, comparisons, `eqz`), wrap-around forms where the claim needs them.
- L6 Calls: a callee `Must` for its body composes into the caller (frame push/pop, results as values); `call_indirect` through a known table entry.
- L7 Hosts: `must_host` — when every outcome a host contract allows continues to `Must`, the host call does (U4 S4 `HostSem`/`Implements`).
- L8 Floats (U14 edgeR `cpm`, U16): the verified f64 operations' results as exact real operations + one rounding, error bounds `|fl(x op y) − x op y| ≤ ulp/2` on normal results, monotonicity of rounding.

## Reviewed vocabulary (audited at U8 close by a fresh `reviewer`; `FVA/Spec/CAbi.lean`, `FVA/Spec/HostMath.lean`)
- C1 Claim forms + buffers (C ABI on wasm32, `FVA/Spec/CAbi.lean`): `Instance` (a fresh instance of an import-free module), `Instantiable` (a successful initialization exists under every host semantics), `Returns` (instantiable + every call from every fresh instance ends, never traps, exact results), `Fits` / `MemInst.withBytes` / `Store.withBytes` (the caller writes bytes into memory 0), `le32` / `le32s` (little-endian `int32_t` arrays), `ReturnsAfterWrite` (a fresh instance with room for the bytes exists, and every call after the write returns the results). Buffer predicates over a call's final store (`BufBytes`, `Disjoint`, `Unchanged`) and `i64`/`f64` arrays → their first consumer (U14: the lz4-wasm codec writes its output, edgeR reads `double` arrays). No allocator model (the subjects take caller-provided buffers); allocator freshness/zeroing/failure (U4 S6) → D-row if a subject needs it.
- C2 Host math (U4 S7, shared with U16): `HostLogContract bound` / `HostLog1pContract bound` = exact real target, error metric (ulps of the f64 result), special values (±0, NaNs, ±∞, negatives), termination, no store effect; `bound` stays a parameter until a resolved implementation's documented accuracy discharges it. An import name proves nothing about accuracy.

## Examples (`FVATest/Examples/<Name>/` in-package projects like the cheats; sources + build + committed `.wasm`; consumer-project form = U11)
- X1 Toy C (`clang --target=wasm32 -O2`): `clamp`, `gcd` (loop, ∀ inputs), `sum_to` (loop with a closed form) — the prototype's toy claims, proven on the new semantics.
- X2 Memory + calls + `br_table` C: `array_sum(p, n)` over a caller buffer (C1), a recursive call (`fib` or `fact` with a bound), a `switch` lowering to `br_table`.
- X3 Rust `#![no_std]` (`rustc --target wasm32-unknown-unknown -O`): the same `clamp`/`gcd` claims as X1 (D7: identical trusted base, two languages).
- Each example: `fva trust` PASS (default run set), surface reported (lines + definitions), kernel check time + replay time recorded; X1–X3 pinned in `scripts/test-trust`.

## Evidence (E)
- E1 Budgets: per example, `lake build` time of its proof module and `fva trust` replay time; walk cost per instruction (L1) on the largest straight-line block.
- E2 The library proves the X1–X3 claims with no per-example stepper unfolding beyond `walk`/`wasm_step` + L3–L8 lemmas (the measure of reuse: lines of example proof vs lines of library).
- E3 Vocabulary audit (C1, C2) by a fresh `reviewer` against the C ABI (tool-conventions BasicCABI.md, pinned) and IEEE-754/C99 Annex F for log/log1p special values; findings → `.agent/review.md`.
- E4 A planted false claim per example (off-by-one bound, swapped operands) fails to prove (kept as a comment-free `#guard_msgs`-style failing `example` is impossible to keep green → recorded once in the commit body: build red on the planted claim).
