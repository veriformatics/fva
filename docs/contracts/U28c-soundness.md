# U28c contract — P′ validation, validator, type soundness (tier: kernel)

Purpose: validation of profile P′ (Decisions: D29 profile P′; `docs/contracts/U28a-profile.md` A2, A4, A6) as a reviewed declarative spec, the validator proven equivalent to it, and U6's soundness theorems (`docs/contracts/U6-soundness.md` S1–S4) over P′, so P′ execution ships behind its soundness extension (Decisions: stop rule). Consumers: U28d (machine over P′: its invariant reads runtime typing), U28e (runner: `assert_invalid` on P′ modules, in-profile test), U28f/U28g (C++ EH subject), U29 (WASI system claims over validated modules), the self claims (`FVA/Self/Spec.lean`: `NeverStuck validate`, `ValidateComplete`). Normative pins: Wasm 3.0 SpecTec `859d3232` — `2.1` (type validity), `2.2` (subtyping), `2.3` (instructions), `2.4` (modules), `4.1` (`Ref_ok`, `Val_ok`, `Externaddr_ok`, `$default_`), `4.4` (instantiation, X7), `7.1` (administrative typing, instances, `Store_ok`, `Extend_*`, `Config_ok`); `document/core/appendix/algorithm.rst` @ `859d3232` (validation algorithm sketch: `Bot`, `pop_ref`, init stack; SpecTec authoritative where the sketch errs); testsuite `44f1503f`; oracle = `wasm-tools validate` with the support manifest's flags (`FVA/Profile.lean`).

Shape: one unit, checkpoints C1 (static: spec V1–V5 + validator + `validate_iff` + E1–E3) and C2 (runtime: V6–V7 + S1–S4 + instantiation + self claims + E4–E5), one landing; C1's WIP may leave runtime proofs unported; the widened validator never ships before S1–S4. Profile reading: P′ uses 3.0 validation restricted to P′ syntax, including sequential immutable-global initialization and full-global contexts for element/data segments. GC heap types/instructions and declared supertypes remain excluded; closed defined-type subtyping is equality.

## Spec (reviewed once, `FVA/Spec/Valid/*`, `FVA/Spec/Types.lean`, `FVA/Spec/Claims.lean`)
- V1 Types (2.1, 2.2): validation accepts arbitrary raw `Module` inputs without a decoder premise. Source heap annotations are `abs a` or `idx x` with `x < |C.types|`; source positions reject `rec_` and `def_` (`HeapType.Src`). Validate source forms before closing each entry-point annotation with `closeHeap C.types`. Context and runtime metadata use closed well-formed types. U28b T6's closed-domain definitions (`HeapType.Closed` … `DefType.Closed`) and the source domains (`HeapType.Src` …, `TypesSeq`) move without semantic change into `FVA/Spec/Types.lean` (lemmas stay in `FVA/Proof/Valid/Closed.lean`); E7 counts them as reviewed base growth. Their domain is `Reftype_ok {} ⊢ rt` restricted to P′. Subtyping = `ValType.Sub` (U28b): numbers by equality; `ref n₁ h₁ ≤ ref n₂ h₂` ⇔ `n₁ → n₂` ∧ (`h₁ = h₂` ∨ `h₁ = def _ ∧ h₂ = func`) (`Heaptype_sub/refl`, `/func`, `/def` with `Deftype_sub/refl` on closed terms; P′ has no `/super`); result types pointwise (`Resulttype_sub`).
- V2 Operand types: `OpType` = `val t` | `bot` (3.0 valtype `BOT`) | `refBot` (3.0 `REF BOT`: a non-null reference whose heap type is the bottom, produced only by `ref.as_non_null` / `br_on_null` on an unknown operand = the algorithm's `pop_ref` on `Bot`, which returns `Ref(Bot, false)`; no source annotation or reachable state of the P′ validation algorithm produces nullable heap-bottom; arbitrary declarative derivations and runtime null typing are outside this representation claim). Matching = `Valtype_sub` + `Valtype_sub/bot` + `Heaptype_sub/bot`: `bot ≤ o`; `refBot ≤ refBot`, `refBot ≤ val (ref n h)`; `val t ≤ val t'` ⇔ `t.Sub t'`. The rules of `ref.as_non_null` / `br_on_null` take the heap type as `Option HeapType` (`none` = bottom: operand and result `refBot`). Without `refBot`, `unreachable ref.as_non_null i32.const 0 br_table 0 1` over labels `[(ref $a)]`, `[(ref $b)]` is valid in 3.0 and in wasm-tools but untypable (no single heap type is below both), so the validator would accept what the spec rejects.
- V3 Contexts (`Context`, 2.4 `C`): `types`, `funcs`, `tags : List DefType`; tables/globals/elems and label/return signatures use closed types; other fields as U6. Locals are compressed runs `(count, LocalType)`, `LocalType = { set : Bool, type : ValType }`: parameters and defaultable locals start set; non-defaultable declared locals start unset (`Local_ok/set`, `/unset`). `sets : List Nat` records additional initialization visible at the current point; effective status = `base.set ∨ index ∈ sets` (membership, not order or multiplicity, decides). Entered bodies inherit the caller view; block/loop/if/try_table exit restores it. Runs keep a 2^32 − 1-local declaration one entry (U6 T1).
- V4 Instruction typing (2.3, rule by rule; SIMD and GC rules absent): an instruction's initialization effect is determined by its syntax (`Instr.sets`: `local.set x`/`local.tee x` ↦ `[x]`, every other instruction ↦ `[]`, a block's effects ending with it = 3.0 `Instr_ok`'s `->_(x*)` for single instructions); stack types carry no effect component; `SeqT.snoc` types the next instruction in the context extended by the effects of the sequence before it (`Instrs_ok/seq`); block, loop, if and try_table bodies are typed in the enclosing view and their effects do not escape; `ExprT`, function and frame bodies need no effect hiding (judgments carry none). `SeqT.sub` covaries results alone (input contravariance arises from `snoc`'s matching); `local.get x` needs an effectively set local (`C.LOCALS[x] = SET t`); `local.set x`/`local.tee x` any local; new rules: `throw x` (`C.tags[x]` expands to `ts → []`; `t₁* ts → t₂*`), `throw_ref` (`t₁* (ref null exn) → t₂*`), `try_table bt cs body` (block typing + `Catch_ok` per clause under the enclosing `C`: `catch x l` ⇒ `ts ≤ C.labels[l]`, `catch_ref` ⇒ `ts (ref exn) ≤ …`, `catch_all` ⇒ `[] ≤ …`, `catch_all_ref` ⇒ `(ref exn) ≤ …`), `return_call x` / `return_call_indirect x y` / `return_call_ref y` (callee results ≤ `C.return_`, `t₃* t₁* (…) → t₄*`), `call_ref y` (`t₁* (ref null y) → t₂*`), `ref.as_non_null` (`ref null h → ref h`, `h` possibly bottom), `br_on_null l` (`t* (ref null h) → t* (ref h)`, `C.labels[l] = t*`), `br_on_non_null l` (`C.labels[l] = t* (ref null? ## Theorems (kernel-checked, standard axioms)
- T1 closure: a valid module's `defTypes`, context and every annotation it closes are closed well-formed (consumes U28b T6; supplies `Module.SourceOK` from validity).
- T2 static: typing is monotone under effective-local initialization (larger `sets` or more base flags set, local types equal) and in `dead` (`false` → `true`, X9), respects equal local views, and admits the required operand input-contravariance/result-covariance. Prove validator conformance jointly over a principal operand stack, equal closed underlying context/local types, and an algorithmic initialized-local set equal (by membership) to the declarative effective set (both syntactic under X1); restore entry views at body boundaries. Prove `pop_ref`/non-null refinement and actual-operand preservation for `br_table`; conclude `validate_iff`. Runtime preservation may strengthen initialization as `none` becomes `some`; transport typing under the larger effective local view while preserving local value types. Store extension preserves closed value typing and existing tag/exception identities.
- S1 Preservation, S2 Progress (thrown = final; fragment results += a pending throw in a handler-free context, a pending `returnInvoke` with its context), S3 Instantiation (tags, table initializers, non-null initializers, sequential globals) + Invocation, S4 `NeverStuck validate` — U6's statements, unchanged in form, over P′.

## Stop rule
- P′ soundness or `validate_complete` blocked after a reproducible attempt ⇒ stop and ask the user with the failed obligation, attempt ledger and discriminating evidence. Current landing requires P′ `validate_iff` and S1–S4. A user-approved completeness-only fallback may retain P′ validation soundness + S1–S4 while replacing the self completeness claim by an explicitly named restricted proposition `∀ m, LegacyP2 m → ModuleValid m → validate m = true`, with the legacy predicate fixed and checked against former admitted modules; reports disclose the absent P′ completeness theorem. It does not permit P′ execution without type soundness or a silent narrowing of `ModuleValid`. A C1 spec choice refuted by review/E1–E3 requires a contract amendment before C2.

## Representation choices and deviations from SpecTec (pre-registered; E5 rules each independently)
- X1 Effects are syntax-determined (V4): `Instrtype_sub`'s effect-forgetting and addition of already-set locals are omitted and stack types carry no effect list, so expression, function and frame boundaries need no effect hiding. Whole-module equivalence to SpecTec rests on weakening under a larger effective initialized-local set (including base-flag changes) and congruence under equal effective views; exact intermediate effect lists are not claimed equivalent. E5 checks the argument.
- X2 Some arbitrary intermediate stack choices omit well-formedness premises, including control-transfer rules (`unreachable`, `br`, `br_table`, `return`, `throw`, `throw_ref`, `return_call*`), `drop`, sequence identity/framing, administrative `trap`, the heap choices of `ref.is_null`, `ref.as_non_null`, `br_on_null` and `br_on_non_null`, and `refNullAddr` at any heap type. This broadens individual judgments. E5 checks that, at closed well-formed source-module boundaries, ill-formed intermediate choices can be normalized away (to `bot`) without changing accepted modules; source annotations themselves always retain V1 validity checks. Do not infer equality of unrestricted judgments from this normalization argument.
- X3 Exception acyclicity (`NotImmutReachable`) is absent from `StoreOK`. Value typing is address-based and each catch reads one finite payload, so preservation/progress need payload typing and valid tag/address lookups, not recursive acyclicity. This admits more initial/host-produced stores than SpecTec, including cyclic exception payloads; no store-set equivalence or termination guarantee follows. Reassess before GC operations are added.
- X4 `refBot` represents non-null heap-bottom in normalized source typing. Establish the validator-stack representation invariant; E5 judges equivalence at closed, well-formed source-module boundaries rather than requiring every intermediate SpecTec operand type to be represented. V6 types runtime null at every closed well-formed nullable source type.
- X5 Faithful side condition: administrative `handler n` leaves `n` unconstrained, exactly as SpecTec `Instr_ok2/handler`.
- X6 Opaque external references: FVA's `Ref.extern a` represents a non-null opaque extern token; SpecTec 4.1 uses `REF.EXTERN ref` wrapping a non-null `any` reference. P′ has no extern/any conversions or GC inspection, so the boundary maps opaque tokens consistently; no equivalence for arbitrary unchanged host relations is assumed.
- X7 Allocation convention: FVA allocates one permanent instance per defined global, matching the reference interpreter. SpecTec 4.4's `$evalglobals` additionally leaves temporary globals before `$allocmodule`. Compare guest-visible values/exports under an explicit representation map; stores are not equal, and host contracts are interpreted on FVA stores. This convention already applies to 2.0 modules, independently of R1.
- X8 Runtime-context normalization/inherited differences: E5 records the chosen forms of `ModuleInstT` (maximal function-reference declaration set, table/memory context types, export-address membership) against `Moduleinst_ok`, and the U6 raw-format/vector/profile side conditions. Each retained strengthening/weakening receives its own safety or admitted-module-equivalence justification.

- X9 Dead tails (runtime only): `Context.dead` marks the context after a `trap` or `throw_ref` in an administrative sequence (`Context.after`); a dead context reads every local (`local.get`: `lt.set ∨ x ∈ C.sets ∨ C.dead`). Source typing never sets it (`ModuleInstT.noDead`; function and expression bodies start live), so module validity and the validator are unchanged. Reason (SpecTec gap, `859d3232`): 4.3 `Step/ctxt-instrs` reduces the sub-sequence `TRAP (LOCAL.SET x)` by `Step_pure/trap-instrs`, so `TRAP (LOCAL.SET x) (LOCAL.GET x)` ↦ `TRAP (LOCAL.GET x)`, reachable from the valid body `unreachable local.set x local.get x` with a non-defaultable local `x` (likewise `Step_read/throw_ref-instrs`); 7.1 types `TRAP` (and `THROW_REF`) without effects, `Instrtype_sub` adds only locals already set, and `Instrs_ok2/seq` types `LOCAL.GET x` under the prefix's effects alone, so the successor is untypable and 7.1 preservation fails there. The dead flag types such tails; outcomes are unchanged. Report draft: `docs/reports/spectec-trap-tail-preservation.md`.
- X10 Encoded local runs (source only): `FuncT` checks the value type of every compressed local run, a zero-count run included (`∀ l ∈ f.locals, l.2.Src C.types.length`); SpecTec 5.4 `Blocals` (`n:Bu32 t:Bvaltype => (LOCAL t)^n`) erases a zero run before `Func_ok`, so a module whose zero-count run names an out-of-range type (`0061736d01000000010401600000030201000a070105010063010b`: one `[] → []` type, a zero run of `(ref null 1)`) is valid in SpecTec and invalid here. Stricter = sound (the soundness theorems cover a subset); kept because the pinned in-profile oracle agrees (wasm-tools 1.262.0: `unknown type 1: type index out of bounds`) and the runner's in-profile set (D29: oracle flags + classifier + static profile) excludes the module anyway. Pinned: `FVATest/Valid.lean` (X10 guards).
