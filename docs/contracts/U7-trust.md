# U7 contract — `fva trust`: verdict, review surface, checker trust (tier: kernel)

Purpose: the one verdict FVA's claims stand on (Decisions: `fva trust` FAIL set, Human-review surface, Trusted base, Checker trust, Self-verification, Distribution). A PASS says: every claim of the spec module is proven, with standard axioms only, by declarations that independent kernels re-check from an export, about the exact bytes of the pinned artifact (or a declared Lean-native subject), and the human-review surface is exactly the reported files. No downstream re-check exists for a false PASS, so every unknown state FAILs. Research notes + verbatim sources: `.scratch/u7/research.md` (K-1…K-7, MAIN-only security work).

## Verdict spec (reviewed once, `FVA/Spec/Trust.lean`)
- V1 Report = the facts below as a Lean structure (claims with their proofs + axioms + subjects, flags, review modules, link results, replay results per kernel, canary results per kernel, budget). `Pass : Report → Prop` = every FAIL rule below is absent; the verdict function `verdict : Report → Verdict` is proven `verdict r = .pass ↔ Pass r` (`FVA/Proof/Trust.lean`), and every FAIL issue it lists names its rule.
- V2 FAIL rules (each a `[tag]` in the output): `[unproven]` a claim without a proof; `[axiom]` a proof's axiom closure outside {propext, Classical.choice, Quot.sound} (`sorryAx`, `Lean.ofReduceBool`/`trustCompiler` from `native_decide`/`bv_decide` included); `[vacuous]` a claim whose statement closure mentions no subject; `[syntax]` a review module, or a subject module the spec module imports (unreviewed text), that declares syntax, macros or elaborators; `[override]` `implemented_by`/`extern`/`unsafe`/`partial`/`opaque` anywhere in the non-core closure of a proof or claim; `[layout]` a claim proven inside the spec module (its proof text would join the surface); `[prelude]` a constant of the kernel's fixed bundle (Lake `Check.lean` primitive + builtin targets: `Nat` + its kernel-accelerated operations, `String`, `String.mk`, `String.ofList`, `Char`, `Char.ofNat`, `List`, `eagerReduce`, `optParam`, `autoParam`, `semiOutParam`, `outParam`, `Quot` + `mk`/`lift`/`ind`) originating outside the Lean sysroot, or an audited non-sysroot module without `Init` in its import closure (the kernel assumes the official prelude: upstream ruling on lean4#15704; Lake's comparator guards the same bundle); `[link]` lifted literal ≠ file bytes, `len` ≠ file size, `decode_eq` missing or of another type, the `.wasm` absent or outside the project, the lifted file not byte-identical to `fva lift`'s output for that `.wasm` (an added declaration or notation would otherwise go unreviewed); `[replay]` an export failure, or a run-set kernel rejecting, crashing or timing out on the export (timeouts fail: the trust direction; budgets sized for 4-core CI), or no independent-lineage kernel accepting it (a decline, rc 2 = "cannot handle", is recorded and blocks only when it leaves no accepting kernel of another lineage than Lean's own); `[checker]` no pinned canary set, a run-set kernel without a run on some pinned canary (missing or altered file: never run), or a run-set kernel accepting a canary that is not a known acceptance covered by another run-set kernel's reject; `[claims]` the spec module declares no claim; `[surface]` a review module whose source file is not found (its lines would count as zero), or the review surface above the budget; `[build]` the project does not build.
- V3 Kernel run set: default = Lean's kernel (`leanchecker`) + con-leche (independent lineage; its default `--verified` mode carries the machine-checked theorem `ConLeche.no_False_declaration`: no file declaring a theorem of `False` is accepted; E2 picks it over con-ron, same statuses, slower, and nanoda); `--paranoid` = every bundled kernel (leanchecker-paranoid, lean4lean, nanoda, con-leche, con-ron) + leanchecker. A PASS needs every run-set kernel to accept the export and reject every canary it is run on; a kernel known to accept a canary (e.g. Lean's own on the #15704 prelude export) never stands alone.

## Facts (trusted glue, `FVA/Trust/*.lean` + `fva trust`)
- F1 Environment facts (one process, imports the spec module + the library root without running any initializer of the project: `loadExts := false`; builtin extensions such as `implemented_by`/`extern` still read their imported entries): claims = definitions in the spec module whose type is `Prop` up to unfolding (a `def MyProp := Prop` hides no claim) (D13 `@[fva_claim]` = deferred unless the cheat suite needs it); proofs = theorems whose type is a claim constant; axiom closure per proof (`collectAxioms`); statement closure (claim meaning, stopping at subject/base/core); audit closure (types + values of everything non-core reachable from proofs + claims); flags; syntax-extension constants in review modules; import closure of the spec module.
- F2 Origin classification by file, never by name: core = `.olean` under the Lean sysroot; Mathlib = under a trusted package directory: a package the project's `lake-manifest.json` pins at the URL + revision FVA's own manifest pins, its checkout's detached `.git/HEAD` at that revision (read as a file: `git` in a package can run repository-configured commands); any other package (local, forked, re-pinned) = project; FVA base = this unit: the FVA package's own spec set (`FVA/Spec/**` + the modules they import inside FVA), for the self package and the in-package cheat projects; the consumer path (vendored FVA sources matched against a committed sha256 manifest, its generator + currency check) moves to U11 `fva init` with that acceptance check; subject = lifted modules (`Lifted.lean` = `fva lift` output) or declared Lean-native subjects (`--subject <module>`, D8); everything else = project (reviewed).
- F3 Review surface = every project module in the spec module's import closure, read whole (source = under the package its `.olean` belongs to, in a `LEAN_SRC_PATH` directory): code lines = lines with a non-blank character outside comments + docstrings, by a lexer of Lean's comment rules (`--`, nested `/- -/`, neither inside a string, raw string, char literal or `«…»`; a misread only overcounts; D11 stricter form = Lean's own tokenizer); per module the declarations; the core definitions the statements use, with their docstrings (D10). Budget = `--surface-budget N` / project config (D23).
- F4 Link: per `Lifted.lean`: `source` = the `.wasm` path, relative + inside the project after symlinks (else `[link]`); `bytes` numeral = the file's bytes (packed little-endian), `len` = its size, `decode_eq : decode bytes len = .ok module` present with exactly that type; re-lift identical (determinism).
- F5 Replay (export in a private temp dir, deleted after the run): `leanexport` (the toolchain's bundled exporter) of the closure of claims ∪ proofs ∪ the fixed bundle of V2 `[prelude]` (independent kernels need the bundle: an export without `Char.ofNat` is rejected by lean4lean) from the built `.olean`s; each run-set kernel invoked directly on the export, three at a time (not through `lake check`, which labels every nonzero rc "rejected"): rc 0 accept, 1 reject, 2 decline, other/signal = crash, wall limit = timeout; a kernel's listed limit messages turn its rc 1 into decline (lean4lean export mode: `deep recursion detected` = its recursion limit, FVA's self export at `instrStep_sound`; `unknown constant` = a constant it needs before the export introduces it, `Char.ofNat` under any string literal (every lifted project: the decoder's messages), `Decidable.intro` under `Nat.mod` (6 arena positive controls); a decline never counts as acceptance); per-kernel status + seconds reported. A declaration added without kernel checking (`debug.skipKernelTC`, `addDeclWithoutChecking`) is rejected here.
- F6 Canaries per pinned toolchain: `trust/canaries/set.tsv` (name, sha256, `bad`|`good`; `scripts/fetch-canaries --pin` after a tarball pin change) = the Lean Kernel Arena closed round `round-2026-09` (71 bad = canaries, 122 good = positive controls; files fetched + tarball sha256-pinned into `.cache/canaries/`) + the lean4#15704 prelude-replacement export (gersh/lean-kernel-bug `exploit.export` at commit aa5157ea, sha256-pinned, fetched only: no license): leanchecker, leanchecker-paranoid + lean4lean accept it (documented: Lean's kernel assumes the official prelude), con-leche + con-ron reject, nanoda panics — the arena excludes prelude replacements, so this canary alone exercises a known acceptance covered by another kernel's reject. Every run-set kernel runs on every bad canary whose file matches its sha256 (cached per kernel-binary + canary sha256 under `.cache/canaries/results`; 4 at a time, `--canary-limit` s each); `trust/canaries/known.tsv` (kernel, canary, reason) = acceptances by a kernel's documented design. Custom axioms + `native_decide` are no kernel canaries (kernels accept axioms by design; `[axiom]` judges them); a skipped-kernel theorem = the arena's ill-typed exports + the SkipKernel cheat. `fva trust-matrix` = every bundled kernel × every pinned canary, both kinds (E2).
- F7 Build: `lake build` of the project's default targets (outside any sandbox this unit; D12 sandboxing + D19 nested-sandbox detection stay deferred with their acceptance checks); `lake build` success alone never yields PASS.

## CLI + report
- Plain report: project-derived names and paths with control + bidi-override characters escaped (no forged report lines); declared subjects listed.
- `fva trust <lake-dir> [--spec-module M] [--root-module R] [--subject M]… [--paranoid] [--surface-budget N] [--kernel-limit S] [--canary-limit S] [--canary-set F] [--known F] [--json]` (`--canary-set`/`--known` = planted inputs; the report names the set used): rc 0 PASS, 1 FAIL, 2 usage/setup. Human report: verdict + issues by tag, claims (proof, axioms, subjects), link, replay per kernel, canaries, the review surface (files, code lines, declarations), trusted base, never-read list, boundary table (Self-verification). `--json` = the Report.
