# U9 contract — per-output certification (tier: kernel)

Purpose: a link for components unfit for program verification (compilers, interpreters, generators, programs in managed languages, LLM pipelines): FVA certifies each output they produce, bound to its exact bytes (Decisions: Link paths, Managed-language link, Language reach). A certificate = a theorem `R input output` about the bytes of two files, `R` a reviewed relation, the proof a kernel-evaluated checker proven sound once. A new producer language needs nothing: the producer runs unchanged and FVA keeps the bytes it wrote ("a capture runner" = run the program, keep its output file). Proof generation is untrusted; the kernel and replay check the proof; the reviewed relations and the tested exact-file binding glue stay in the trusted base (a kernel has no filesystem view).

## Reviewed once (base)
- B1 `FVA/Spec/Cert.lean`: blob values (`bytes` numeral + `len`) read back by the decoder spec's own projection `Binary.leBytes len bytes` (`leBytes bs.length (pack bs) = bs`: exact bytes, trailing zero bytes included); the claim form `Accepted (R : List UInt8 → List UInt8 → Prop) (i o : Blob)` := `R (leBytes i.len i.bytes) (leBytes o.len o.bytes)`; docstring: "the output file's bytes stand in relation `R` to the input file's bytes". A claim mentioning its blobs passes `[vacuous]`, which says nothing about `R`'s adequacy: `R` itself is reviewed.
- B2 Relations (`FVA/Spec/Rel/*.lean`), each a short reviewed definition over byte lists:
  - `IntLines xs` = each integer of `xs` in canonical decimal (`toString` of `Int`: `-` sign, no leading zeros, no `+`) followed by `\n`; `SortedPerm i o` := `∃ xs ys, i = IntLines xs ∧ o = IntLines ys ∧ ys.Pairwise (· ≤ ·) ∧ ys.Perm xs` ("the output lists the input's integers in nondecreasing order, one per line"; duplicates and the empty list allowed; other decimal spellings are outside the relation by design).
  - `Compiled i o` (toy compiler): `∃ e body, i = Expr.text e ∧ ModuleB (toyModule body) o ∧ ToyValid body ∧ ∀ x : BitVec 32, Returns (toyModule body) "f" [.i32 x] [.i32 (e.eval x)]`. `Expr` = `x | const n | e + e | e - e | e * e` (32-bit wrapping), `Expr.text` its fully parenthesized ASCII printing; `toyModule body` = exactly one type `[i32] → [i32]`, one function of type 0 with no declared locals, one export `f` → function 0, every other module field empty; `ToyValid body` = the body uses `local.get 0`, `i32.const`, `i32.add/sub/mul` alone, with the stack-height discipline (a push adds one, an operator needs two and leaves one, the final height is one), which is what Wasm validation asks of this profile (an engine accepts the module). `ModuleB` = the binary grammar (U2), `Returns` = U8's claim form. A compiler output certificate is a ∀-input theorem about one artifact; profile → general validity = a U6 obligation.
- B3 Blob modules: `fva blob <file> <Out.lean> --ns <Ns>` writes `bytes` (packed numeral, `wasm_bytes%`), `len`, `source` (project-relative path, U7 F4 policy: no `..`, inside the project after symlinks), `blob : Blob := ⟨bytes, len⟩`; no decode.

## Verified implementation (subjects of the self package)
- C1 Checkers on packed input (`FVA/Impl/Cert/*.lean`, kernel-evaluated: `Nat.land`/`shiftRight`, `bif`, structural recursion on fuel, per the decoder's kernel-cost rules): `SortedPerm.check` (strict parse of both files, sortedness, permutation by insertion sort of the input); `Compiled.check` (strict expression parse; `decode`; the toy profile shape + `ToyValid`; symbolic evaluation of the body to an `Expr`, structurally equal to the parsed one). Both are sound and intentionally incomplete: a rejection gives no certificate, never a refutation (`x + 0` compiled to `local.get 0` is rejected).
- C2 Soundness, proven once: `check … = true → R …` for both (strict parser soundness + the packed-byte bridge; for `Compiled`: decoder soundness, a straight-line total-return lemma — a `ToyValid` body whose symbolic evaluation is `t`, run from locals `[x]`, returns `t.eval x` under every host semantics). Both join `FVA/Self/Spec.lean`.
- C3 A certificate's proof = the soundness theorem applied to a kernel-evaluated `check … = true` (`decide +kernel` / `kernel_rfl`).

## Glue (trusted, tested)
- G1 `fva certify <project> --relation <R> --input <file> --output <file> --ns <Ns>`: writes the two blob modules (B3), `<Ns>/Spec.lean` (imports the relation module + the blobs; `def claim : Prop := Accepted R In.blob Out.blob`, docstring naming the relation and both files) and `<Ns>/Proof.lean` (imports the spec + the checker's soundness module; `theorem claim_holds : claim := …`); prints "Certificate files written; acceptance requires fva trust." (rc 0 = written; the verdict comes from `lake build` + `fva trust`). Relation convention: `--relation Mod.R` = a relation `R` in module `Mod`, its checker `Mod.R.check` and `Mod.R.check_sound : R.check … = true → R …` in `Mod.Check` (the theorem's type ties the checker to that exact relation); a project-defined relation follows the same convention and enters the project's review surface, FVA's own ones are base.
- G2 `fva trust`: tagged links — common obligations for every link (file present inside the project, numeral = file bytes, `len` = size, regeneration identity of the whole module incl. `blob`), `decode_eq` for Wasm links alone; every blob a claim mentions has its own link result; each claim lists its attachment kinds (artifact: lifted Wasm, accepted output: blob, both for a mixed claim) with the relation name and both blob sources, in text + JSON. The verdict spec + its proof extend accordingly, existing Wasm obligations unchanged.

## Producers + certificates (`FVATest/Certs/<Name>/`, in-package like the cheats; one aggregate spec module per project, since `fva trust` collects the spec module's own claims)
- P1 Sort: one input (200 integers incl. negatives, zero, duplicates, 100000) sorted by unchanged programs in Python (`sorted`), R (`sort` + `sprintf("%d")`, `Rscript --vanilla`), Java (`Arrays.sort`), TypeScript (`node` type stripping, numeric sort): four certificates → PASS; each producer rerun at unit close, its bytes compared with the committed output.
- P2 Exact-byte binding: the naive R producer reads doubles (`scan()`) and prints `as.character(sort(x))` → `1e+05` (`Rscript --vanilla`, R 4.6.1) → `fva certify` writes a proof that fails to build (the expected honest result; its captured output stays as captured).
- P3 Toy compiler (`compile.py`, untrusted Python: expression text → `.wasm`): three expressions certified (∀ x); a tampered output of `x + 1` (`i32.add` byte → `i32.sub`) → proof fails; the unused-invalid-function binary (consultant-6 K3 witness) → proof fails (not `ToyValid`).
- P4 Negative sort fixtures (exact original bytes): wrong multiplicity (`2\n1\n1\n` → `1\n2\n`), unsorted permutation (`2\n1\n1\n` → itself; positive control `1\n1\n2\n`), JS rounding past 2^53 (`9007199254740992\n9007199254740993\n` → `9007199254740992\n9007199254740992\n`, Node's real output) → each proof fails; empty + trailing-zero blobs (length independent of the numeral) → PASS where `R` holds.
- P5 Link: input file edited after certification → `[link]`; output file edited → `[link]` (buildable certificates, failing link).
- Fixture tests pin rc + stage (generation, build, trust) + tag/diagnostic per case in isolated test files, the package build staying green. `scripts/make-certs` regenerates outputs + blobs (host-dependent producers, like `make-examples`); `scripts/test-trust` runs the committed certificates.
- P6 Project-defined relation: a small relation in an `FVATest/Certs/Custom` project through the same generator: its source in the review surface; a too-small `--surface-budget` → `[surface]`.

## Evidence (E)
- E1 Kernel cost: `decide` + default independent replay seconds per certificate by encoded size (bytes, digits) for 200 and 2,000 integers in worst order (reverse sorted: insertion sort's n(n−1)/2 comparisons, 19,900 / 1,999,000) and duplicate-heavy inputs; compiler outputs; blob numeral elaboration. A size cap follows if a case exceeds the budget.
- E2 Planted: removing (negating) the checker's nondecreasing-order guard, with the permutation check intact → `check_sound` breaks and the unsorted-permutation fixture certifies wrongly under the mutant build (both recorded).
- E3 Mutation: `FVA/Impl/Cert/**` = `FVA/Impl/**` scope (joins the config at the phase-close `--fresh` run, U12 S1); ad-hoc run now.
- E4 Each certificate PASS; the report lists attachments per claim.

## Moved
- TMM relation (exact ties, interval-bounded log2, original-byte numeric parsing) + edgeR/RNAnorm certificates → U14, beside filterByExpr: a relation module on this mechanism, no new producer or link path.

## Out of U9 (later units or rows)
- Floating-point text formats (`%.17g` round trip) beyond integers → U14 (TMM); large outputs past the kernel budget (E1 decides a cap); producer provenance (which executable produced the bytes: a certificate binds bytes, not producers).
