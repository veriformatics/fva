# U28e contract — the public runner over P′ (tier: kernel)

Purpose: `fvatest spec` (`FVATest/Spec.lean`) runs P′ scripts on the U28d machine — the 15 official P′ scripts at the corpus pin (EH `tag`, `throw`, `throw_ref`, `try_table`; tail calls `return_call`, `return_call_indirect`, `return_call_ref`; function references `call_ref`, `br_on_null`, `br_on_non_null`, `ref_as_non_null`, `local_init`; rec types `type-canon`, `type-equivalence`, `type-rec`) beside the pinned 2.0-named scripts — with per-script pins in `scripts/test-spec`, so the request's "the official exception-handling spec tests pass" holds on the public runner in the gate (fast + full). One runner, two engines, for the official, acceptance and blind suites. Consumers: D29 acceptance (tester-1, 20 checks), `scripts/test-p2exec` (tester-3's blind P′ suite, both engines), `scripts/test-char` (characterization goldens), U28f (C++ EH on the machine).

Tier `kernel`: the runner's verdicts grade D29's shipped claim and no downstream check re-reads them (a runner that passes a failing command reaches the user unseen).

Review: consultant-12 (7 sound / 9 change / 1 reject; every change adopted below; `.scratch/lwr/cons/c12/verdicts.md`); advisor: E6 flag clause dropped (cannot fail), skip → fail rule, I4 scoped to the scripts' literal forms, fuel measured before mode placement, controls credited through plants.

## Interface (FVATest glue, unproven: pins, acceptance checks, goldens + plants grade it)

- I1 In-profile test for positive payloads (`module`, `assert_unlinkable`, `assert_uninstantiable`) = U28a's boundary, moved from `FVATest/P2.lean` `outsideP2`: `wasm-tools validate --features=<FVA.Profile.wasmToolsFeatures>` + the syntax classifier over `wasm-tools print` of the stripped binary (no excluded class) + ≤ 1 memory; else `skip: outside P′: <excluded: <class ids> | oracle rejects | more than one memory>`. The `wasm2,-simd` baseline retires (Q3: one profile for every script). A strip/print/oracle setup failure = runner rc 2, never a skip. A payload in profile that FVA's decoder reports `unsupported` = a failure. Negative payloads unchanged (U25, U28c): `assert_invalid` decoded + validated (decoder `unsupported` → `skip: outside P′: decoder …`), binary `assert_malformed` must fail the decoder, text = `skip: text format`.
- I2 Initialization, one path per engine for `module` and `assert_uninstantiable` (machine = `Machine.initRun`, U28c shared candidates `Ref.initCandidates` + `Ref.initAgrees`; reference = the same candidates + `allocModule` + reference steps; the placeholder `runInit` retires). Result matrix (upstream `runner.ml:559–566` at `859d3232`: `AssertUninstantiable` accepts `Trap` or `Exception`):

  | ending | `module` | `assert_uninstantiable` |
  |---|---|---|
  | returns no values | pass, instance published | fail |
  | returns values | fail | fail |
  | trap | fail | pass |
  | uncaught exception | fail | pass |
  | stuck / fuel exhausted / initializer failure | fail | fail |

  The reached store survives every obtained ending (§4.5.4); only a passing `module` publishes an instance; a failed `module` clears `current` (never reuses an older instance).
- I3 `assert_exception` passes iff the action ends `.thrown a` (uncaught at the top: `Ending.thrown`); store effects kept, as for traps; every other ending = a failure. The script form carries no tag or payload (upstream `runner.ml:573–578` matches `Exception` alone).
- I4 Actions: before execution, the argument count and each literal's type must match the exported function's parameter types (`FuncType.params` of the export's closed type): a numeric literal = its exact type; an `externref`/`funcref` literal = a nullable reference parameter of that heap type; a null literal = any nullable reference parameter of its heap type; a typed-reference parameter routes through FVA's subtype decision only when a pinned script needs it. A mismatch = `fail: … wrong number of arguments | wrong type of argument` (upstream `runner.ml:411–416`). Expected values: `meets` unchanged; the 15 scripts need zero `unsupported expectation` / `unsupported action argument` skips.
- I5 Tags: `exported` + registration resolve `.tag` exports like every other kind; `Ref.importsMatch` decides tag imports by closed defined type (U25/U28a); `assert_unlinkable` passes iff resolution fails or matching fails; an unavailable dependency stays a skip.
- I6 Skip taxonomy (total; any other reason = a failure of test-spec's justification check): `text format` (JSON `module_type` text); `outside P′: …` on a positive payload whose `FVATest/Profile/commands.tsv` row has an excluded class; `outside P′: decoder …` on a negative payload whose row's decoder verdict is `unsupported:<class>`; `register rejected module`, `unavailable import`, `missing/rejected module` = dependency skips, each naming the command line that excluded its module (provenance: that command is itself a justified exclusion). The script state carries, per named/registered/current module, the line of the command that defined it or excluded it; lookup keeps absent and rejected modules apart (a script naming a module never defined = a failure).
- I7 Engines + CLI: `fvatest spec [--engine ref|machine] [--fuel N] SCRIPT…` (default `machine`; `ref` = the reference stepper, fuel = reference steps; default fuel 40,000,000 for both, so the official tail-call recursions run without an override); per script the existing 4-field line `<script> <pass> <fail> <skip>` stays byte-compatible (tester-1 `test-accept-lwr:205`, test-char), the engine + fuel on a separate `engine <name> fuel <n>` line; the machine path keeps the store in machine form across commands (no per-command `MStore.ofStore`). No scripts, an unknown or repeated option, a malformed fuel, a missing file and the retired `fvatest p2` = usage/setup failure (rc 2). `fvatest p2` + `FVATest/P2.lean` retire (Q1: the reference algorithm stays, behind the switch).
- Limit (M7): the runner grades result categories and values; upstream also matches trap/instantiation message prefixes, which FVA does not compare. Exclusions = text-format payloads + out-of-profile constructs (D29 P′) + their dependents; the 393/0/34 headline is stated with them.
