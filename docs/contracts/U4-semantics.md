# U4 contract — Wasm execution semantics + claim forms (tier: kernel)

Purpose: the meaning of running a decoded module (U2 `Module`) with the reviewed numerics (U3), so claims about a `.wasm` artifact are statements about its executions (Decisions: Trusted base, Link path, Self-verification). Reviewed spec = `FVA/Spec/Exec/**` + `FVA/Spec/Claims.lean`; verified impl = machine + fuel interpreter `FVA/Impl/Exec/**`; proofs `FVA/Proof/Exec/**`. Consumers: U5 (spec suite + difftest), U6 (type soundness over `Step`), U8 (proof library), U14 (bench claims), U16. Rulings below = consultant-4 review (C1–C6, D1–D8), all accepted.

## Spec (reviewed once) — Wasm 2.0 §4 for profile P
- S1 Runtime (§4.2): values = numeric bits (`BitVec 32/64`, floats as bits) + references (null t | func addr | extern addr). Store = function instances (module code | `HostId`), tables, memories, globals, element + data instances; module instances; frames (locals + module instance). Memory = `pages` + optional `maxPages` + extensional `byte : Nat → UInt8`, zero at and beyond `pages · 65536` (one convention, stated once). Effective address = `i32.toNat + offset` in `Nat`, bounds-checked against the access width before any access; alignment annotations never trap.
- S2 Administrative syntax (§4.2.13): `trap`, values, `invoke a`, `label n {cont} body`, `frame n {F} body` over the U2 nested `Instr`; block contexts (labels, never frames) + evaluation contexts as inductives with `fill`. Trap propagation guarded by `fill E [trap] ≠ [trap]` (the spec excludes `[_]` and `ε [_] ε`), so `trap` is irreducible. Frame congruence keeps the caller frame and updates the callee's inside `frame`.
- S3 `Step H : Config → Config → Prop` (§4.4): one rule per instruction of P. Numeric results from the U3 sets (all NaN choices). `memory.grow`/`table.grow` may fail even below the maximum (result −1, object unchanged) or succeed (zero-filled / init-filled growth). Control arities: block label = result arity, loop label = parameter arity; the function body's implicit label = function result arity; value order kept. `call_indirect`: null / out-of-bounds / type-mismatch traps.
- S4 Hosts (§4.4.10, appendix properties): `HostSem := HostId → Store → List Val → HostOutcome → Prop`, `HostOutcome = returned store vals | trapped store | diverged` (divergence = self-loop). `ValidHost H`: on every well-typed call a nonempty outcome set; returned stores extend the input store; result values typed. Behavioral contracts (`Implements H c`: pre/post/frame/termination) separate from validity; a contract never deletes executions outside its precondition. Re-entry effects are inside the host outcome (the spec subsumes callbacks).
- S5 Instantiation (§4.5.4), staged: validation premise (U6 interface; decoding alone never supplies it) + import matching → function addresses → constant-expression initializers → allocation (imported addresses kept; aliases never copied) → active elements + declarative drops, then active data, in order (passive segments retained until explicit drop; dropped = empty instance, same address) → start. Errors before allocation ≠ traps after writes (store effects kept). A diverging start never yields an instance.
- S6 Claims (`FVA/Spec/Claims.lean`): `Must step final post` (inductive: `done` on a final state satisfying `post`, or `next` = some successor exists and every successor satisfies `Must`) ⇒ `Returns`/`Traps` = total correctness over every admissible NaN, growth and host outcome; `MayReturn`/`MayTrap` (an execution exists) and `PartialCorrect` (every terminating execution satisfies) named separately. No fuel in public claims. Stateful `CallReturns H s inst name args Q` (Q over result store + values) separate from `Instantiated H m s₀ imports s₁ inst` and `LoaderReady` (dylink: `__wasm_apply_data_relocs` before any other export, then ctors). A claim binds `inst` to the exact decoded module. C-ABI vocabulary: byte footprints, pointer + length bounds, alignment where the ABI requires it, permitted aliasing, allocator freshness/zeroing/failure outcome, free's effects, preserved-frame facts.
- S6a Final states = `returned store vals` and `trapped store`; `post` ranges over both, so an honest total claim may be disjunctive (e.g. "returns X, or traps when the allocator contract's failure outcome occurs"). Counterexample form (U14 "the shipped binary is wrong") = `MayReturn` of a violating result + a determinism lemma for that call (no NaN-producing op, no grow, no host call on the path), which upgrades it to `Returns`.
- S7 Host math (shared with U16): `HostLogContract bound` / `HostLog1pContract bound` = exact real target, error metric, special values (signed zeros, NaNs, infinities), termination, store effects; the bound is a parameter until a resolved implementation's documented accuracy discharges it. An import name proves nothing about accuracy.

## Implementation
- I1 Machine = value stack + control zipper (labels + suspended frames off to the side) + executable memory = pure persistent sparse tree with packed leaf chunks (missing node = zero; chunk size + depth calibrated on the lz4-wasm/edgeR workloads; a `List` backend exceeds the kernel's memory cap at 10 KB / 64 writes, consultant-4 probe). Local runs stay compressed until first touch.
- I2 Nondeterminism: the interpreter consumes an oracle over a history-indexed request stream (NaN choice, grow success/failure, host outcome); `Admissible H ω` = every consumed choice is allowed. A canonical executable chooser serves the CLI + tests only. NaN choices come through a U3 classifier interface: allowed set = singleton (non-NaN, U3 `Det`) | canonical class | arithmetic class, proved to reflect `nans` (D6).
- I3 Results: `returned store vals | trapped store` (semantic) vs `outOfFuel state | invalid reason | needHost request` (tool control; never relabeled as a trap). Embedder resource exhaustion is outside the abstract claims (§ implementation limits).
- I4 Theorems: `Represents : Machine → Config → Prop`; `run_sound` (a returned/trapped run is a `Steps` reduction to that final state); `run_complete` (every terminating reduction is found by some admissible oracle + fuel); must-adequacy (divergence-sensitive simulation with a well-founded measure for administrative stuttering) so `∀ ω admissible, ∃ fuel, run = post` ⇔ `Must`. Instantiation impl ↔ S5 per outcome (error, trap with store, divergence, instance).

## Implementation route (slice 1 findings)
- Reference stepper `FVA/Impl/Exec/Ref.lean` (`seq`/`atInstr`/`instrStep`/`step`/`run`): a deterministic, spec-shaped reading of `Step` on spec configurations (first non-value redex; `br`/`ret` signals resolved by the enclosing label/frame; verified float ops as the NaN choice; growth when it fits; host calls stuck). Proofs: soundness (`step`/`run` ⇒ `Step`/`Steps`, prover-7) and determinism at non-choice redexes (`step_complete` ⇒ `must_of_step`, `runDet_must`, prover-8). Trap propagation is one-step nondeterministic in the spec (`E[trap] ↪ trap` for every non-trivial `E`) but confluent: it counts as a choice point, and `must_trap` closes it (ruling on prover-8's counterexample `[trap, nop, nop]`).
- E5 first number: lz4-wasm `lz4BlockEncode("abaaaaaaaaaba")` = 433 stepper steps; `decide +kernel` on the run's output bytes (`316162610100506161616261`) ≈ 1.5 s user above the import baseline, +0.26 GB peak RSS (memory as a closure chain over writes: fine at this size). The zipper machine (I1) is the performance layer for long runs (spec suite, edgeR), proven against the stepper or `Step`.

## Proof route (spike result, prover-8)
- `step_complete`: where `uniqueStep` holds (no NaN float result, no grow, no host call, no trap propagation), the stepper's step is the only `Step`; `must_of_step` + `must_trap` (trap propagation: every path keeps the store and ends at `[trap]`) + `runDet_must` turn a deterministic stepper run into `Must`.
- Spike `FVA/Proof/Exec/Spike.lean`: `sum 1..n` loop proven `Must` for every i32 input and every host relation by symbolic stepping (a 12-step iteration certificate) + induction: 165 lines (92 theorem lines; public proof 2 tactic lines), ≈ 3 s check; a synthetic 100-instruction prefix + the loop ≈ 24.6 s wall. Ruling: U8's library = symbolic stepping with the reference stepper + `must_of_step` (numeric-effect lemmas keyed on explicit `BitVec.ofNat` literals; staged `toVal_instr` before unfolding). `run_complete` + must-adequacy for the interpreter → deferred (only needed if a faster machine replaces the stepper in proofs).
