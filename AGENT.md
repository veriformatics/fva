# FVA agent guide

FVA = Lean 4.35 + Mathlib v4.35.0 package: proofs about the compiled WebAssembly artifact (`.wasm` bytes, not a model of the source) + per-output certificates for programs FVA cannot verify as code. The verdict = `fva trust`; its review surface (code lines a person must read) is the metric to keep small. Commands: `fva help`; arguments + options of one: `fva <command> --help`.

## Program verification (C, C++, Rust, Zig, … → core wasm)

1. Project: `fva init <dir> --lib <Lib> --wasm <artifact.wasm>` → `<dir>/fva/` (vendored FVA), `<Lib>/Lifted.lean` (the artifact as one numeral + `decode_eq`, kernel-checked; never edit), `<Lib>/Spec.lean`, `<Lib>/Proof.lean`. Existing project: `lake exe fva lift <artifact.wasm> <Lib>/Lifted.lean --ns <Lib>.Lifted` (path relative to the project root). Build: `lake exe cache get && lake build`.
2. Claims (`<Lib>/Spec.lean`, the only file a reviewer reads besides FVA's base): `@[fva_claim] def <claim> : Prop := …` (unmarked `Prop` defs = helpers: never proven, listed apart in the report), docstring = the intent in plain words. Import `<Lib>.Lifted` + FVA specs only (`FVA.Spec.CAbi`, `FVA.Spec.Rel.*`); never import proofs or define notation here.
   - `Returns Lifted.module "f" [.i32 x, …] [.i32 r]`: in every fresh instance, under every host behavior, `f` returns exactly `r`, never traps, never ends with an uncaught exception, always ends (instantiability included).
   - `ReturnsAfterWrite Lifted.module p bytes "f" args results`: same after the caller wrote `bytes` at address `p` (a fresh instance with room for them must exist); state the buffer domain in the claim (`p.toNat + 4 * xs.length ≤ 65536 → …`).
   - `CallWithin H s inst "f" args R W` (memory footprint, a safety claim beside `CallReturns` on the same prepared instance): every configuration of every execution reads only bytes `a` of memory `ma` with `R ma a` and writes only those with `W ma a` (`Reads`/`Writes` = the successful load/store the next step performs, callee frames + bulk instructions included; import-free modules only).
   - `le32s xs`: an `int32_t`/`uint32_t` array as bytes. Integers are `BitVec 32/64` (`.slt` signed, `.toNat` unsigned); C `int` wraps like `BitVec` arithmetic.
   - Attack each claim before you prove it (a proof can hold for a statement that says the wrong thing; `fva trust` checks proofs, not meaning): the quantifiers + the direction of each `→`; edge cases (empty input, zero, the largest values, overlapping or out-of-range buffers, traps); premises that can all hold at once — prove one instance, since an impossible premise proves anything; no premise that assumes the result; no `True` or other stand-in; each helper `Prop` a claim uses: one input where it holds + one where it fails (else it is impossible or says nothing); no assumption stronger than the requirement needs. A claim kept weaker than its requirement: say so in its docstring.
3. Proofs (`<Lib>/Proof.lean`, never read; one `theorem <claim>_holds : <claim>` each), library `import FVA.Proof.Lib`:
   - Fix the instance: `refine ⟨instantiable_alloc rfl rfl rfl rfl rfl rfl, ?_⟩; intro H s inst h; have ha := instance_alloc rfl rfl rfl rfl rfl h`; derive `s.funcs[k]? = some (.wasm ⟨[ft], 0⟩ inst Lifted.funcK)` (a function's defined type: the one-member group of its signature `ft`) and `inst.exportFunc "f" = some k` by `obtain ⟨rfl, rfl⟩ := Prod.mk.inj ha; rfl`, then `clear ha h` (keep the store abstract).
   - Execute: `refine ⟨k, he, ⟨_, _, hf, rfl, by simp [Val.HasType, FuncType.mapHeap, ValType.mapHeap]⟩, ?_⟩; unfold invokeConfig; wasm_run [hf, Lifted.funcK, facts…]` steps until a branch needs a fact; `wasm_step1 [facts]` = one step; close with `Must.done (o := .returned s [.i32 _]) ⟨rfl, rfl⟩ ?_`. Facts = hypotheses that decide branches (`hb : ¬ b.toNat = 0`, `hr : BitVec.ofNat 32 … = 0`), memory reads (`read_le32s`), loop heads.
   - Outcomes: `returned s vs` | `trapped s` | `thrown s a` (an uncaught exception, address `a`); postconditions `fun | .returned s vs => … | _ => False`, case splits `rintro (⟨s, vs⟩ | s | ⟨s, a⟩)`. A run on concrete inputs: `runDet N c = some c'` by `kernel_rfl`, then `runDet_must` (throws reach their handlers inside it: `FVA/Proof/Lib/EHExamples.lean`); a process: `sysMust_of_runDet`.
   - Loops: define the configuration at the loop head (locals as parameters, each frame local `some v`: `none` = an unset local of a type without a default), prove `Must` from it by strong induction on a measure, stepping one iteration with `iterate N wasm_step1 [...]` back to the head; enter it from the function start with `iterate M wasm_step1`.
   - Footprints: prove `MustW H R W Q c` (= `Must` + `Throughout (Within R W)`) with `wasm_cstepw [facts]` on `C.fill c` (callers in a `Context`); each step leaves its `Within` goal first, closed by `wasm_within [facts]` (no access) or a range goal from the invariant. Loop lemmas: `Until H (Within R W) Exit c` stepped by `wasm_cstepu`, handed over by `mustW_of_until`. Worked: `FVA/Proof/Lib/FootprintExamples.lean`, `FVATest/Subjects/Lz4C/ExtDirect.lean`.
   - Arithmetic: `iadd_eq`/`isub_eq`/`imul_eq`/`ishl_eq`/`ixor_eq`/`ieqz_eq_zero`/`iltS_eq_zero` turn FVA's integer ops into `BitVec`; then `bv_omega` (never `bv_decide`/`native_decide`: their axioms fail `fva trust`).
   - Large functions: cut the function at its join points (loop heads, branch merges, calls) into `Until` statements of exact post-states, prove each, compose with `Until.trans`. Blocks: `wasm_eval k [facts]` (`FVA/Proof/Lib/BlockEval.lean`) runs `k` stepper steps in one rewrite and leaves `TraceOK` (`wasm_trace [facts]`) + the `Until` from the block's end; `block not computed: <term>` names the missing fact (an instruction named by a constant needs its `≠ .br k`, `≠ .return_` and `≠ .throwRef` facts: `FVATest/Subjects/Lz4C/Eval/ShortCode.lean`). Keep i32 constants near 2^32 symbolic (`x + 4294967295` → `x - 1`), locals as an explicit list, loops as induction on a decreasing count. Worked: `FVATest/Subjects/Lz4C/` (`Seg.lean` statements, `Eval/` proofs, `Top.lean` composition).
   - Kernel cost: step through `wasm_step1`/`wasm_run` (propositional rewriting), never by `rfl`/`decide` on stepper terms with symbolic values (the kernel unfolds `Nat` arithmetic next to literals like `4294967295` by unary recursion: minutes). On a configuration without variables (a call on concrete inputs) `wasm_step1` evaluates a step its rewriting leaves open (float arithmetic, conversions); with variables its error names the instruction whose step needs a fact.
4. Defects: when a requirement fails on the artifact, prove the failure on the artifact: a concrete input where `Returns … [.i32 actual]` holds with `actual ≠ required`, or the negation of the requirement's claim. One call's result: `fva call <Lib>/Lifted.lean <export> <type>:<value>… --spec <file> --proof <file>` runs the call and writes the claim + its proof (no hand-written proof; arguments `i32:<n>`, `i64:<n>`, `f32:0x<bits>`, `f64:0x<bits>`; modules without imports, globals, element/data segments or a start function); move the claim into `<Lib>/Spec.lean` when the spec has other claims. Report it in the claim's docstring and VERIFICATION notes; never weaken a claim to make it provable without saying so.
5. Check: `lake build`, then `lake exe fva trust . --spec-module <Lib>.Spec --root-module <Lib>` (rc 0 = PASS) with the vendored binary. Never rebuild FVA or read its sources to re-check a verdict: a rebuild from the vendored copy proves nothing the vendored binary does not. The verdict that counts is the user's own `fva`, built outside the project (a vendored copy can be edited): say so in your report. Each `[tag]`: `unproven` (no theorem typed by the claim), `axiom` (sorry, native_decide, custom axioms), `vacuous` (claim mentions no artifact), `layout` (theorem in the spec), `syntax` (notation, macros, initializers or a listed command in a reviewed module — `#eval`, `run_cmd`, `#exit`, `set_option`, `include_str`, …: the reviewed text must be the spec), `subject` (an instance or coercion of a `--subject` module that a claim's statement uses: move it to a reviewed module), `override` (implemented_by/extern/unsafe/partial/opaque), `link` (lifted or blob file ≠ its numeral, missing `decode_eq`, edited generated file), `replay` (an independent kernel rejected the export), `checker` (a kernel accepted a known-false canary), `surface` (over `--surface-budget` or the project's `fva.json` `surfaceBudget`), `prelude` (a replaced prelude). The report lists the review surface; FVA's own files count only when byte-identical to the pinned base.
6. Plain English (optional, needs a signed-in `codex`): `fva explain . --spec-module <Lib>.Spec --root-module <Lib>` → per-claim explanation (model sees neutral names), examples computed by Lean and by wasmtime, each requirement of `<Lib>/requirements.md` (`## <id>` per requirement; draft it from the README/issues/source for the user to approve) checked against the claims stating it (else each claim vs its docstring); saved beside the spec.

## WASI commands (a `_start` program reading args, env, files, stdin; writing stdout, files)

1. Run: `fva run <cmd.wasm> [--dir HOST[::GUEST]]… [--env K=V]… [-- ARGS…]` = the verified machine + FVA's executable WASI host (the 20 preview1 calls of its model; another import stops the run); stdout, stderr, exit status and files as `wasmtime run` on the tested domain. Stdin is preloaded: give `</dev/null` when it carries no data.
2. Observe: the exact output bytes, the exit status, the run's length (`--fuel N`: the smallest `N` that finishes = its steps, host calls included = the `sysRun` fuel the proof needs).
3. Claim (`<Lib>/Spec.lean`, import `FVA.Spec.Wasi.World`): fix the start world, every input byte in the spec: `def start : State := State.init args env stdin [(guest, .dir [(name, .file bytes)])] clocks`; then `(∃ c mem, Launch Lifted.module "_start" [] c mem) ∧ ∀ c mem, Launch Lifted.module "_start" [] c mem → SysMust ((world Lifted.module mem).restrict (E Lifted.module mem)) true Q (start, c)` with `Q := fun o => ∃ τ s, o = .exited τ s 0 ∧ τ.stdout = <a spec function of the input>`. Prove `start.Wf` by `decide` (import `FVA.Proof.Wasi.WfRun`): the start is a well-formed world. Scope to state in the docstring: one start world, every execution under the reviewed WASI model restricted to `E` (in-profile calls return, stated clocks), fitting growth; not every input, not wasmtime itself.
4. Proof, one segment (`FVATest/Subjects/WasiGc/Proof.lean`: 1,655 steps incl. 5 host calls, ≈ 30 s, 3 GB): `instantiateU` + the exports by `decide +kernel`; `noncomputable def run := sysRun State.exited (wasiHost Lifted.module 0 none) N (start, MState.ofInvoke inst.1 a [])`; `run.1.exited = some 0` + `run.1.stdout = …` by `decide +kernel`; the launch by `launch_of_instantiateU`; close with `launch_sysMust … (sysMust_exited he ⟨run.1, _, rfl, hout⟩)`. Keep `run` unevaluated during elaboration: pass `run` through an eta lemma on a variable triple, and rewrite the restricted world's `exited` to `State.exited` as a function before using `run.1.exited`. A run past one declaration's kernel budget → U29d's checkpoints (segments composed by `machineRun_sysMust`).
5. Check: `fva trust` in default and `--paranoid` mode; the whole recipe in a fresh project = `FVATest/Subjects/WasiGc/recipe DIR`.

## Per-output certificates (programs in Python, R, Java, TypeScript, compilers, generators)

- `fva certify . --relation <R> --input <in> --output <out> --ns <Ns>` writes `<Ns>/{In,Out}.lean` (the files' bytes), `<Ns>/Spec.lean` (`@[fva_claim] def claim : Prop := Accepted R In.blob Out.blob`), `<Ns>/Proof.lean` (`R.check_sound` on the kernel's run of `R.check`); `lake build` fails when the checker rejects the pair; then `fva trust` as above (attachment = accepted output).
- FVA's relations: `FVA.Cert.SortedPerm` (integers, one per line in canonical decimal, output = input sorted, duplicates kept), `FVA.Cert.Compiled` (a toy expression compiler's output computes the expression for every input). Own relation: `def R (i o : List UInt8) : Prop` in a project module (`--relation-module`) + `R.check : FVA.Cert.Blob → FVA.Cert.Blob → Bool` + `R.check_sound : R.check i o = true → FVA.Cert.Accepted R i o` (`--sound-module`); the relation's module is in the review surface.
- Certificates bind bytes: the producer runs unchanged, its exact output is certified; a runtime rounding or formatting change is a different output.

## What a PASS rests on

FVA's specs (Wasm syntax, binary grammar, execution semantics, numerics, claim forms, certificate relations, verdict rules; reviewed once), FVA's verified implementation (decoder, stepper, float operators, instantiation, validator + type soundness, verdict function, certificate checkers: proven against the specs), trusted glue (fact collection, link checks, orchestration, external kernels, each canaried), residual trust (the Lean kernel cross-checked by an independent kernel, the Lean compiler, Mathlib at the pinned revision).
