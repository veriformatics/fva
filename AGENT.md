# FVA agent guide

FVA = Lean 4.35 + Mathlib v4.35.0 package: proofs about the compiled WebAssembly artifact (`.wasm` bytes, not a model of the source) + per-output certificates for programs FVA cannot verify as code. The verdict = `fva trust`; its review surface (code lines a person must read) is the metric to keep small.

## Program verification (C, C++, Rust, Zig, … → core wasm)

1. Project: `fva init <dir> --lib <Lib> --wasm <artifact.wasm>` → `<dir>/fva/` (vendored FVA), `<Lib>/Lifted.lean` (the artifact as one numeral + `decode_eq`, kernel-checked; never edit), `<Lib>/Spec.lean`, `<Lib>/Proof.lean`. Existing project: `lake exe fva lift <artifact.wasm> <Lib>/Lifted.lean --ns <Lib>.Lifted` (path relative to the project root). Build: `lake exe cache get && lake build`.
2. Claims (`<Lib>/Spec.lean`, the only file a reviewer reads besides FVA's base): `def <claim> : Prop := …`, docstring = the intent in plain words. Import `<Lib>.Lifted` + FVA specs only (`FVA.Spec.CAbi`, `FVA.Spec.Rel.*`); never import proofs or define notation here.
   - `Returns Lifted.module "f" [.i32 x, …] [.i32 r]`: in every fresh instance, under every host behavior, `f` returns exactly `r`, never traps, always ends (instantiability included).
   - `ReturnsAfterWrite Lifted.module p bytes "f" args results`: same after the caller wrote `bytes` at address `p` (a fresh instance with room for them must exist); state the buffer domain in the claim (`p.toNat + 4 * xs.length ≤ 65536 → …`).
   - `le32s xs`: an `int32_t`/`uint32_t` array as bytes. Integers are `BitVec 32/64` (`.slt` signed, `.toNat` unsigned); C `int` wraps like `BitVec` arithmetic.
3. Proofs (`<Lib>/Proof.lean`, never read; one `theorem <claim>_holds : <claim>` each), library `import FVA.Proof.Lib`:
   - Fix the instance: `refine ⟨instantiable_alloc rfl rfl rfl rfl rfl, ?_⟩; intro H s inst h; have ha := instance_alloc rfl rfl rfl rfl h`; derive `s.funcs[k]? = some (.wasm …)` and `inst.exportFunc "f" = some k` by `obtain ⟨rfl, rfl⟩ := Prod.mk.inj ha; rfl`, then `clear ha h` (keep the store abstract).
   - Execute: `refine ⟨k, he, ⟨_, hf, by simp [Val.HasType, FuncInst.type]⟩, ?_⟩; unfold invokeConfig; wasm_run [hf, Lifted.funcK, facts…]` steps until a branch needs a fact; `wasm_step1 [facts]` = one step; close with `Must.done (o := .returned s [.i32 _]) ⟨rfl, rfl⟩ ?_`. Facts = hypotheses that decide branches (`hb : ¬ b.toNat = 0`, `hr : BitVec.ofNat 32 … = 0`), memory reads (`read_le32s`), loop heads.
   - Loops: define the configuration at the loop head (locals as parameters), prove `Must` from it by strong induction on a measure, stepping one iteration with `iterate N wasm_step1 [...]` back to the head; enter it from the function start with `iterate M wasm_step1`.
   - Arithmetic: `iadd_eq`/`isub_eq`/`imul_eq`/`ishl_eq`/`ixor_eq`/`ieqz_eq_zero`/`iltS_eq_zero` turn FVA's integer ops into `BitVec`; then `bv_omega` (never `bv_decide`/`native_decide`: their axioms fail `fva trust`).
   - Kernel cost: step through `wasm_step1`/`wasm_run` (propositional rewriting), never by `rfl`/`decide` on stepper terms with symbolic values (the kernel unfolds `Nat` arithmetic next to literals like `4294967295` by unary recursion: minutes).
4. Defects: when a requirement fails on the artifact, prove the failure on the artifact: a concrete input where `Returns … [.i32 actual]` holds with `actual ≠ required` (concrete runs: `runDet n (invokeConfig …) = some …` by `decide +kernel`/`rfl` on small inputs, then `must_returned_of_runDet`), or the negation of the requirement's claim. Report it in the claim's docstring and VERIFICATION notes; never weaken a claim to make it provable without saying so.
5. Check: `lake build`, then `fva trust . --spec-module <Lib>.Spec --root-module <Lib>` (rc 0 = PASS) — run an `fva` built outside the project for the verdict that counts (a vendored copy can be edited). Each `[tag]`: `unproven` (no theorem typed by the claim), `axiom` (sorry, native_decide, custom axioms), `vacuous` (claim mentions no artifact), `layout` (theorem in the spec), `syntax` (notation/macros in a reviewed module), `override` (implemented_by/extern/unsafe/partial/opaque), `link` (lifted or blob file ≠ its numeral, missing `decode_eq`, edited generated file), `replay` (an independent kernel rejected the export), `checker` (a kernel accepted a known-false canary), `surface` (over `--surface-budget`), `prelude` (forged prelude). The report lists the review surface; FVA's own files count only when byte-identical to the pinned base.
6. Plain English (optional, needs a signed-in `codex`): `fva explain . --spec-module <Lib>.Spec --root-module <Lib>` → per-claim explanation, examples computed by Lean and by wasmtime, intent check; saved beside the spec.

## Per-output certificates (programs in Python, R, Java, TypeScript, compilers, generators)

- `fva certify . --relation <R> --input <in> --output <out> --ns <Ns>` writes `<Ns>/{In,Out}.lean` (the files' bytes), `<Ns>/Spec.lean` (`def claim : Prop := Accepted R In.blob Out.blob`), `<Ns>/Proof.lean` (`R.check_sound` on the kernel's run of `R.check`); `lake build` fails when the checker rejects the pair; then `fva trust` as above (attachment = accepted output).
- FVA's relations: `FVA.Cert.SortedPerm` (integers, one per line in canonical decimal, output = input sorted, duplicates kept), `FVA.Cert.Compiled` (a toy expression compiler's output computes the expression for every input). Own relation: `def R (i o : List UInt8) : Prop` in a project module (`--relation-module`) + `R.check : FVA.Cert.Blob → FVA.Cert.Blob → Bool` + `R.check_sound : R.check i o = true → FVA.Cert.Accepted R i o` (`--sound-module`); the relation's module is in the review surface.
- Certificates bind bytes: the producer runs unchanged, its exact output is certified; a runtime rounding or formatting change is a different output.

## What a PASS rests on

FVA's specs (Wasm syntax, binary grammar, execution semantics, numerics, claim forms, certificate relations, verdict rules; reviewed once), FVA's verified implementation (decoder, stepper, float operators, instantiation, verdict function, certificate checkers: proven against the specs), trusted glue (fact collection, link checks, orchestration, external kernels, each canaried), residual trust (the Lean kernel cross-checked by an independent kernel, the Lean compiler, Mathlib at the pinned revision).
