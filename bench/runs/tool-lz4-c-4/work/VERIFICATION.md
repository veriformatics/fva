## Machine-checked statements

The certificate is [`verification/base.c`](verification/base.c), generated by
[`verification/lift.py`](verification/lift.py). All nine functions in this file
are checked by Frama-C 33.0 WP, including their assertions, runtime-error guards,
postconditions, frames, and callee preconditions. There are no imported or
unproved copy-function contracts in this certificate.

The exact main theorem is the ACSL contract of `decode_base`. Let `M` be the
initial memory, `M'` the final memory, and `F` the unsigned i32 result. It states:

* `M` is a valid 2,097,152-byte array.
* `131072 <= s <= 2097151`, `size <= 1966080`, and `s+size <= 2097152`.
* `131072 <= d <= 2097151`, `cap <= 1966080`, and `d+cap <= 2097152`.
* **Domain restriction:** `cap = 0`, or `size = 0`, or
  `size = 1` and `M[s] = 0`.
* Under these preconditions, `M' = M` (`assigns \nothing`), and
  `F = 0` if `size = 1` and `M[s] = 0`; otherwise `F = 4294967295`,
  the signed i32 value `-1`.

All arguments are unsigned 32-bit values; the arithmetic in the mathematical
preconditions above is integer arithmetic. In particular, sizes fit the README's
nonnegative signed-i32 domain. The theorem universally quantifies memory contents
and permitted addresses/sizes. Disjointness is not needed for this restricted
no-write theorem; it includes the README's disjoint-buffer cases.

Every executed memory load in the model has separately proved `physical_bounds`
and `read_footprint` assertions: its entire byte interval is within the memory
and within the source or destination buffer. Stores would require corresponding
write assertions; these paths perform no stores. The `assigns \nothing` clauses
also establish the absence of memory modification.

The supporting exact statements are:

* `base_zero_one`: the main contract plus `cap = 0` and `size = 1`.
* `base_zero_other`: the main contract plus `cap = 0` and `size != 1`.
* `base_empty`: the main contract plus `cap > 0` and `size = 0`.
* `base_empty_tight`: the main contract plus `size = 1`, `M[s] = 0`,
  and `0 < cap < 12`.
* `base_empty_roomy`: the main contract plus `size = 1`, `M[s] = 0`,
  and `cap >= 12`.
* `move4`: for arbitrary unsigned addresses `d,s`, if `n = 0`, returns `d`
  and changes no memory. This is the zero-length portion of actual Wasm function
  4, not an assumed library specification.
* `move_zero_0` and `move_zero_1`: the preceding helper statement plus,
  respectively, `d >= s` and `d < s`.

The two dispatchers check the case coverage and every trace's preconditions.
The models are acyclic and have no recursive calls.

## Binding the model to the shipped artifact

`lift.py` checks the exact size and SHA-256 above and runs `wasm-tools validate`.
It obtains WAT from `wasm-tools print`, checks the decoder export is function 2
and the memory limits are 32/32 pages, and reads functions 2 and 4 directly.
No rebuilt binary or C-source-to-Wasm compiler correctness assumption is used.

The script resolves structured branch depths to instruction indices and follows
specified paths. Every conditional branch becomes an ACSL assertion of the
actual condition and selected outcome. Fixed arguments also become assertions.
All such assertions must be proved; they are not assumptions or axioms. C
instructions carry the corresponding Wasm instruction indices in comments.

Arithmetic uses 32-bit unsigned operations; shift counts are masked by 31;
signed comparisons use the `x86_32` signed-int model. Memory instructions use
explicit little-endian byte operations and checked effective addresses.
Address-normalization assertions and literal-length assertions are additional
proved facts. A reached call other than function 4 fails generation. The checked
base model's zero-length function-4 implementation is proved in the same file.

**Translation trust boundary:** the theorem is directly about the generated C.
There is no machine-checked proof that the Python translator preserves Wasm
semantics. Applying its result to the exact binary requires reviewing the
translator, its path specifications, and wasm-tools' decoding. The connection
between the single-byte zero block and the format's representation of empty
input is also a human correspondence to `lz4_Block_format.md`.

## Finite checks of the actual artifact

The first completed run of `node verification/test.js` checked **82,762 cases**,
including 3,277 valid-block cases and 9,144 nonnegative results. Its observed
output is recorded in [`verification/initial-tests.txt`](verification/initial-tests.txt).
The executable JavaScript statements are the same as in that completed run.

The script instantiates the original artifact using Node's WebAssembly runtime.
It checks returned lengths and output against an independent bytewise sequence
parser, and valid generated blocks against their intended decoded contents.
The corpus includes every one- and two-byte source with the capacities selected
in the script, extended lengths, selected offsets through 65535, zero offsets,
chained matches, malformed inputs, and boundary placements.

The parser accepts zero offsets and relaxes the last-five-literals and
last-match-distance rules. It retains a final-literal-sequence requirement,
which is stricter than R3. Thus the passing nonnegative cases satisfy R3's
allowed sequence semantics; this checker is not a complete decision procedure
for all inputs R3 would permit a decoder to accept.

`instrument.py` generates a second module with a check before every load/store
in decoder function 2 and its reachable helpers 3 and 4. Checks use the complete
access width and nonwrapping effective address. All original function/global
indices remain unchanged: new wrappers and globals are appended. The tests run
both modules, compare results and destination contents, check source preservation,
and require every access check to pass. These are finite checks, not a formal
proof of instrumentation equivalence or of unrestricted R1–R3.

`lift.py`. It attempts to cover literal-only payloads of length 0 through 14,
plus zero-capacity and empty-source cases, using 30 fixed-length memory-copy
traces and six decoder traces. Its contracts and assertions are not certified
as a complete unit by this submission and must not be used as proved lemmas.

The full split-goal run had not completed when preparing this report and had
reported `typed_move4_8_1_ensures_byte_7` as timed out. Its incomplete output
snapshot is in `verification/candidate-status.txt`. This is a missing proof,
not a software counterexample. Earlier versions also had copy-content timeouts.
The independent `base.c` proof does not import the candidate's contracts.
Unrestricted requirements additionally need general invariants for extended
lengths, wild copies, shortcut paths, and match reconstruction, together with
an arbitrary-block format semantics. Those proofs were not completed.

## Reproduction

From this directory, run:

```sh
bash verification/check.sh
```

The exact constituent commands are:

```sh
python3 verification/lift.py
frama-c --check-wp . verification/base.c -machdep x86_32 \
  -wp -wp-rte -wp-split -wp-timeout 10 -wp-par 4 -wp-prover qed,alt-ergo
python3 verification/instrument.py
node verification/test.js
```

Success requires zero exit status from every command, all generated WP goals
proved for **base.c**, and this finite-test output:

```text
PASS: 82762 artifact executions; 3277 valid-block cases; 9144 nonnegative results checked against sequence semantics; instrumented access checks passed
```

There is no goal selection/filtering for `base.c`. To attempt the larger,
unproved candidate separately, use the same Frama-C command with
`verification/traces.c` in place of `verification/base.c`. Its success is not
claimed here. No network, Lake build, or Lean proof is used.
