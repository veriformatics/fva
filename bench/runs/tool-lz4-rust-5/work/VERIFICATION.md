# Verification report

**Status: partial verification.** R1–R3 are proved for an explicit Rust decoder
model in Verus. The shipped Wasm passes 1,338 deterministic cases, including
instrumented checks of its memory accesses. Its build was reproduced byte for
byte. **There is no machine-checked refinement from the shipped Wasm to the
model, so this is not an unconditional proof of R1, R2, or R3 for the artifact.**
No counterexample to those requirements was found.

The artifact checked is the original `lz4-flex.wasm`: 7,161 bytes, SHA-256
`1f115e3a5ddee865621f406e2abf545854218cb8dc632d759e998553031aa775`.
The artifact, vendored implementation, and requirements were not modified.
Compression is outside the proof claims.

## Definitions and exact model statements

The authoritative definitions and contracts are in
[`verification/decoder.rs`](verification/decoder.rs) and
[`verification/optimized.rs`](verification/optimized.rs).
Use the following notation for their exact statements:

- `L = 2097152` (`LIMIT`).
- `S` is the immutable input byte sequence; `B` is the initial output buffer,
  including its arbitrary initial contents; `B'` is its final contents.
- `D(S,p,P,c) = decode(S,p,P,c)` is capacity-limited decoding from input
  position `p`, with already-decoded prefix `P` and capacity `c`.
- `F(S,p,P) = format_decode(S,p,P)` is the capacity-independent sequence grammar
  and its decoded meaning.
- `V(None,B') = None`;
  `V(Some(r),B') = Some(B'[0..r))` (`buffer_result`).

`extension` reads bytes until the first byte less than 255 and sums them,
including that last byte. `literals` extracts the high token field and optional
literal-length extension. `match_header` reads a two-byte little-endian offset
and the low token field plus 4 and any match-length extension. `match_bytes`
appends bytes sequentially, reading at current output length minus the offset;
thus overlapping matches use newly generated bytes.

`F` requires literal bytes to exist, match lengths to be at least 4, offsets to
be positive and no greater than the number of bytes decoded before the match,
and a final literal sequence to consume exactly the remaining input. It uses
no dictionary. It deliberately does not impose the three compatibility
end-of-block conditions. Its accepted language therefore includes blocks which
break only those conditions, as permitted by R3. The model completeness theorem
covers this larger language. The interpretation that a valid independent block
in the format document belongs to this grammar must be reviewed; a separate
formal predicate for the three end conditions was not introduced.

### R1: buffer access confinement

**Model result.** Verus checks the index bounds and arithmetic of every
executable function in the two Rust model files, including arbitrary malformed
input. Input reads use `S` indices; writes use the output array; match reads and
snapshot reads use that output array. Snapshots model `copy_within` semantics,
not additional caller-supplied memory. No raw pointers or unsafe blocks occur
in the model.

For `optimized_from(S,p,&mut B,pos)`, the exact preconditions are:

```text
|S| <= L, p <= |S|, pos <= |B| <= L
```

Its exact postconditions are:

```text
|B'| = |B|
result = Some(r) ==> r <= |B'|
V(result,B') = D(S,p,B[0..pos),|B|)
```

The checked body includes the fast path's 16-byte literal copy and 18-byte
match copy, the slow path's 32/64-byte wild copies, forward overlapping copies,
and the offset-one fill. Their individual contracts describe the logical
prefix after each copy; all actual modeled array accesses, including the wild
part, are bounds checked by Verus. The model does not claim that writes stop at
the returned length: R1 permits writes throughout `cap`.

`caller_layout` in `optimized.rs` proves the following exact address lemma:

```text
Given:
  131072 <= src, 0 <= n, src+n <= 2097152,
  131072 <= dst, 0 <= cap, dst+cap <= 2097152,
  src+n <= dst OR dst+cap <= src,
  0 <= i < n, 0 <= j < cap,
Then:
  131072 <= src+i < 2097152,
  131072 <= dst+j < 2097152,
  NOT (dst <= src+i < dst+cap),
  NOT (src <= dst+j < src+n),
  0 <= src+i < 4294967296,
  0 <= dst+j < 4294967296.
```

This connects valid array indices to the caller's legal, disjoint Wasm address
ranges. It is not a theorem about the instructions executed by the artifact.

**Artifact evidence.** `replay.py` checks the exact binary's hash and executes
all cases both unchanged and with a monitor inserted before every linear
memory operation. There are 219 static load/store/copy/fill instructions in the
whole module, including the compressor. For each executed decoder operation,
the monitor checks the whole accessed span: reads must be below 131072, inside
`src[0..n)`, or inside `dst[0..cap)`; writes must be below 131072 or inside
`dst[0..cap)`. All monitored cases pass. Checks use 64-bit effective addresses,
including load/store immediate offsets. Unknown memory instruction forms
cause the script to fail rather than be ignored.

`monitor_sound` in [`verification/monitor.rs`](verification/monitor.rs) proves:
for `base`, `offset`, and `len` in `[0,4294967295]`, legal source/destination
ranges, and `permitted(base+offset,base+offset+len,src,n,dst,cap,read)`,

```text
0 <= base+offset <= base+offset+len < 18446744073709551616
forall a in [base+offset,base+offset+len) intersect [131072,2097152):
  a in [dst,dst+cap) OR (read AND a in [src,src+n)).
```

`permitted` is exactly the integer predicate corresponding to the emitted
monitor: empty span, span below 131072, span in destination, or (for a read)
span in source. The correspondence between the emitted Wasm and this integer
predicate is reviewed code, not a verified translation.

**Not proved for the artifact:** that every possible execution passes this
monitor. In particular, passing these cases is not a universal read-confinement
proof, and uninstrumented sentinel checks alone would not establish reads.

### R2: completeness and decoded content

**Model results.** `model_r2` in `decoder.rs` has this exact statement:

```text
0 <= cap AND F(S,0,[]) = Some(expected) AND |expected| <= cap
  ==> D(S,0,[],cap) = Some(expected).
```

`capacity_equivalence` proves, for any `p`, prefix `P`, and `|P| <= cap`:

```text
D(S,p,P,cap) =
  match F(S,p,P):
    None      => None
    Some(out) => if |out| <= cap then Some(out) else None.
```

`optimized_decompress(S,&mut B)` is verified under `|S| <= L` and `|B| <= L`
with these exact postconditions:

```text
|B'| = |B|
result = Some(r) ==> r <= |B'|
V(result,B') = D(S,0,[],|B|)
V(result,B') =
  match F(S,0,[]):
    None      => None
    Some(out) => if |out| <= |B| then Some(out) else None.
```

Thus the optimized model succeeds with precisely the expected length and bytes
whenever the grammar yields content that fits. Output buffer initialization is
unrestricted. `token_fields` proves the equivalence of division/remainder in
the model to the original token shifts/masks. `abi_result` proves that mapping
`None` to -1 and `Some(n)` to `n as isize`, for `n <= L`, gives exactly -1 or the
nonnegative length without truncation.

**Artifact evidence.** The replay corpus includes literal-only blocks,
literal-length extensions, matches with offsets 1 through 65535, overlapping
matches, match-length extensions, multiple sequences, exact and oversized
capacities, and buffers near the upper memory boundary. Constructed matched
blocks satisfy the end conditions; the generator checks their independently
constructed expected content. The unchanged artifact's return value and all
successful output bytes are compared to a separate byte-wise Python decoder.

**Not proved for the artifact:** universal preservation of this theorem through
the source-to-model mapping and Rust-to-Wasm compilation.

### R3: soundness of successful results

**Model result.** `model_r3` in `decoder.rs` proves exactly:

```text
0 <= cap AND D(S,0,[],cap) = Some(out)
  ==> |out| <= cap AND F(S,0,[]) = Some(out).
```

Together with the exact `optimized_decompress` contract above, this proves
that every successful optimized-model result is bounded by capacity and has
precisely the content described by a complete parse into independent LZ4
sequences with positive, already-decoded match references. End-condition
violations may be accepted; truncated headers and offsets zero or beyond the
decoded prefix cannot produce success.

**Artifact evidence.** In addition to generated blocks, the 1,338 cases include
all 256 possible one-byte inputs, arbitrary byte strings, truncated blocks,
zero and excessive offsets, incomplete length extensions, insufficient output
capacity, and sequences lacking a final literal token. All returns agree with
the Python grammar interpreter. Each case also checks preservation of the
input and destination boundary sentinels. Successful outputs are compared
byte for byte, not by a digest.

**Not proved for the artifact:** that an input outside this finite corpus cannot
cause a spurious successful decode.

## Connection to the shipped artifact and remaining assumptions

[`verification/rebuild.sh`](verification/rebuild.sh) builds the unmodified
vendored crate and shim offline with Rust 1.99.1 and the options recorded in
`build.sh`, then uses `cmp` to check equality to the original artifact. This
succeeds. The options are on a single line: the literal newlines within the
original `RUSTFLAGS` value are rejected by this installed Cargo. This script
normalizes that whitespace and does not overwrite `lz4-flex.wasm`.

The system-packaged Rust compiler produces different embedded panic-location
paths and therefore different bytes. The supplied script selects the installed
Rustup 1.99.1 toolchain, which reproduces the documented hash. On another
installation, set `RUST_TOOLCHAIN_BIN` to that toolchain's `bin` directory.

The model was manually derived from `decompress_safe.rs` with `USE_DICT=false`
and `SliceSink` initially at position zero. Important representation changes
requiring review are:

1. Byte slices and the sink become input/output vectors. Their lengths model
   fixed buffer extents, not native allocator behavior.
2. Sequence and length-extension loops become well-founded recursive calls;
   overlapping and fill copies remain loops. Native execution of the model,
   native recursion stack consumption, and allocation failure are not claims.
3. Snapshot copies model `copy_within`/Wasm `memory.copy`. The snapshot helper
   reads the output buffer, including bytes beyond the logical cursor, all
   within capacity. Literal copy loops model `fastcpy`'s overlapping small
   loads/stores without reproducing their individual machine instructions.
4. The fast path's shadowed 16-byte input slice is replaced by indexing the
   original input at the equivalent position. Bit-field identities are proved;
   equivalence of the surrounding source control flow is manually assessed.
5. Error variants become `None`; the modeled slow parser may read the match
   length before rejecting offset zero, whereas the source rejects it earlier.
   These extra modeled reads stay inside input. Partial destination contents
   on errors are not specified by R2/R3.
6. `abi_result` models the shim's return conversion; the pointer-to-slice shim,
   Rust compiler, linker, core slice operations, and Wasm execution semantics
   are not themselves verified here.

Rebuild equality connects the artifact to the vendored source. It does not
prove this manual model extraction or compiler correctness. Completing a
universal artifact proof would require a checked refinement of its instructions
to the proved model, or equivalent proofs over the original compiled code.
That step was not completed. The report therefore leaves all three universal
artifact requirements unproved rather than treating model proofs or testing
as substitutes.

## Rechecking

From this directory, without network access:

```sh
bash verification/check.sh
```

The individual commands it executes are:

```sh
verus --version
verus --no-cheating verification/decoder.rs
verus --no-cheating --rlimit 60 verification/optimized.rs
verus --no-cheating verification/monitor.rs
python3 verification/replay.py
bash verification/rebuild.sh
```

Expected Verus summaries are respectively `19 verified, 0 errors`,
`33 verified, 0 errors`, and `1 verified, 0 errors`. Progress notes about a
long-running function are harmless; every command must exit zero. The replay
must print:

```text
original: 1338 cases PASS
monitored: 1338 cases PASS
artifact SHA256 1f115e3a5ddee865621f406e2abf545854218cb8dc632d759e998553031aa775; 219 memory instructions instrumented
PASS (finite replay only; no universal artifact claim)
```

Rebuilding must print the same SHA-256 and
`PASS: rebuild is byte-identical to the shipped artifact`.
The final runner line is
`PASS: model proofs, finite artifact replays, and byte-identical rebuild`.
A nonzero exit, failed assertion, Verus error, hash mismatch, unexpected trap,
or differing rebuilt binary means the corresponding check failed.

Tools used: Verus release `0.2026.10.18.7d82994`, Rust
`1.99.1 (58cf8f9c3 2026-10-13)`, Wasmtime `50.0.0 (ebe5e8df1)`, wasm-tools
`1.262.0 (e22db44da)`, and Python 3. No Lean proof or Mathlib assumption is used.
