# Verification of glm-iround.wasm

R1 **fails**. The binary64 input with bits `0x3fdfffffffffffff`, printed as
`0.49999999999999994`, returns `1`. Its uniquely nearest integer is `0`.
This input is finite, positive, within the required range, and strictly below
the halfway point. Thus the requirement's permission to choose either integer
at an exact tie does not apply.

## Machine-checked result

The theorem in `Proofs/Proof.lean` is exactly:

```lean
theorem r1_counterexample_holds : r1_counterexample
```

Its complete statement is defined in `Proofs/Spec.lean` as follows (names are
in namespace `Proofs`, with FVA's Wasm, execution, and numeric namespaces open):

```lean
def badInput : BitVec 64 := 0x3fdfffffffffffff

noncomputable def badValue : ℝ := (ofBits f64fmt badInput).toReal f64fmt

def r1_counterexample : Prop :=
  (ofBits f64fmt badInput).IsNum ∧
  badValue = (9007199254740991 : ℝ) / 18014398509481984 ∧
  (0 ≤ badValue ∧ badValue ≤ 2147483647) ∧
  (∀ n : ℤ, n ≠ 0 → |badValue| < |badValue - (n : ℝ)|) ∧
  Returns Lifted.module "iround" [.f64 badInput] [.i32 1]
```

The strict distance comparison proves uniqueness over **all** integers.
`Returns` includes successful instantiation and termination without a trap,
with exactly the stated result, in every fresh instance under every host
semantics. This is a counterexample to R1, the README's only requirement;
no universal correctness claim for R1 is asserted.

The supporting theorems, also in `Proofs/Proof.lean`, have these exact types:

```lean
theorem badInput_decoded :
  ofBits f64fmt badInput = .normal false 4503599627370495 (-2)

theorem badValue_exact :
  badValue = (9007199254740991 : ℝ) / 18014398509481984

theorem badInput_returns :
  Returns Lifted.module "iround" [.f64 badInput] [.i32 1]
```

## Connection to the shipped bytes

The subject is the original, unchanged, 66-byte `glm-iround.wasm`, SHA-256:

```text
eded7ae1f3c1ba100d618a98f8f86eb690577a8358e47e31f2039eb2f4a75a3a
```

`Proofs/Lifted.lean` was generated by:

```sh
lake exe fva lift glm-iround.wasm Proofs/Lifted.lean --ns Proofs.Lifted
```

It contains the complete artifact as a little-endian numeral, its length and
source path, the decoded module, and the kernel-checked theorem
`Proofs.Lifted.decode_eq : decode bytes len = .ok module`.
FVA's link check compares those bytes to the actual file and checks the
generated lifting. The proof executes that decoded module using FVA's verified
deterministic runner and transfers the result to its Wasm execution semantics.
The runner's fuel of 20 is only a proof computation bound; the resulting
`Returns` statement has no fuel assumption.

The module executes `local.get 0; f64.const 0.5; f64.add;
i32.trunc_sat_f64_s`. Binary64 rounding of the addition produces `1.0` for this
input, after which the conversion produces `1`. No C++ source model or
assumption that the compiler preserves the headers' meaning is used.

## Reproduction

From this directory, with the supplied offline Lean 4.35.0 environment:

```sh
lake build
sha256sum glm-iround.wasm
/tmp/fva-iround-verifier/.lake/build/bin/fva trust . \
  --spec-module Proofs.Spec --root-module Proofs
```

The external verifier path above was built outside this project from the
unchanged supplied FVA package. If that temporary directory is absent, prepare
a fresh external verifier with these commands, then run its `trust` command:

```sh
iround_verifier=$(mktemp -d /tmp/fva-iround-check.XXXXXX)
cp -a --reflink=auto fva/. "$iround_verifier/"
python3 - "$iround_verifier" <<'PY'
import json, pathlib, sys, tomllib
p = pathlib.Path(sys.argv[1])
packages = str(pathlib.Path(tomllib.loads(pathlib.Path('lakefile.toml').read_text())['packagesDir']).resolve())
f = p / 'lakefile.toml'
f.write_text(f.read_text().replace('allowNonModules = true',
    'allowNonModules = true\npackagesDir = ' + json.dumps(packages)))
f = p / 'lake-manifest.json'
d = json.loads(f.read_text())
d['packagesDir'] = packages
f.write_text(json.dumps(d, indent=2) + '\n')
PY
rm "$iround_verifier/.lake/build/bin/fva" \
   "$iround_verifier/.lake/build/bin/fva.hash" \
   "$iround_verifier/.lake/build/bin/fva.trace"
(cd "$iround_verifier" && lake build fva)
"$iround_verifier/.lake/build/bin/fva" trust . \
  --spec-module Proofs.Spec --root-module Proofs
```

The setup changes only the external copy's package-location configuration and
relinks its executable. It uses the already installed dependencies and cached
canaries, with no network. FVA's source is unchanged.

Success means `lake build` exits 0, the hash matches the value above, and
`fva trust` exits 0 and prints `fva trust: PASS`. A PASS certifies the
**counterexample**, and consequently does not mean that R1 holds.

The completed audit is saved in `FVA-TRUST.txt`: **PASS**, exit 0; the artifact
link matches; `leanchecker` accepted the replay in 99 seconds and `con-leche`
accepted it in 75 seconds. The only proof axioms reported are `propext`,
`Classical.choice`, and `Quot.sound`. FVA reports a review surface of **13 code
lines**, all in `Proofs.Spec`.

The audit also records the 72 known-false canaries: `leanchecker` rejected 71
and accepted one documented exception; `con-leche` rejected 69 and declined
three. There were no crashes or timeouts. FVA's canary coverage rules accepted
the combined results; the complete counts and trust boundary are in the log.

An additional runtime reproduction, separate from the proof, is:

```sh
wasmtime run -C cache=no --invoke iround glm-iround.wasm 0.49999999999999994
```

It prints `1` (possibly with experimental-interface warnings).

## Review and trust

The project-specific mathematical interpretation to review is
`Proofs/Spec.lean`: 13 code lines; 24 physical lines, 915 bytes, including comments and blanks.
It defines the input, its value via FVA's binary64 interpretation, and the
counterexample claim. There is no separate hand-written program model.

`Proofs/Proof.lean` has 47 physical lines, 1597 bytes, and is kernel checked;
`Proofs/Lifted.lean` has 42 physical lines, 1452 bytes, and is generated and
byte-linked. `Proofs.lean` is a one-line import. These proof and generated
files need not be trusted as mathematical assertions without checking them.
No `sorry`, custom axiom, `native_decide`, or `bv_decide` is used.

The shared base is the unchanged supplied FVA package: its reviewed
`FVA/Spec/**/*.lean` files total 3606 physical lines. Its trusted tooling in
`FVA/Trust/` and `FVA/Tool/` totals 3781 physical lines. The reproduction
commands above are orchestration to review as well. FVA checks its base
against the manifest compiled into the external executable, and checks the
artifact link, proof axioms, and independent-kernel replay. Its verified
decoder, execution runner, instantiation, and IEEE-754 arithmetic connect the
computed execution to those specifications.

Residual trust includes the accuracy of FVA's Wasm and numeric specifications,
Lean 4.35.0, the independent replay kernels and canary infrastructure, the
compiler used for the verifier, and the supplied Mathlib v4.35.0 checkout
(`56a005855ea17e0b0958f73ec801ae140b0a1679`) and its dependencies.
The runtime check additionally depends on Wasmtime, but the theorem does not.
