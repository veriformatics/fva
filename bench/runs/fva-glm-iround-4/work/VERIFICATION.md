# Verification result

**R1 fails on the shipped artifact.** For binary64 input bits `0x3fdfffffffffffff`,
`iround` returns `1`. This input is exactly
`9007199254740991 / 18014398509481984 = 1/2 - 2^-54`
(approximately `0.49999999999999994`). It is finite and in `[0, 2147483647]`.
Integer `0` is strictly closer to it than integer `1`, so the halfway exception
cannot excuse this result. A single such input refutes the universal requirement.

## Machine-checked result

The exact theorem in [Proofs/Proof.lean](Proofs/Proof.lean) is:

```lean
theorem R1Counterexample_holds : R1Counterexample
```

Its complete claim definition, in [Proofs/Spec.lean](Proofs/Spec.lean), is:

```lean
def R1Counterexample : Prop :=
  let x : BitVec 64 := 0x3fdfffffffffffff
  let v := ofBits f64fmt x
  v.IsNum ∧
  v.toReal f64fmt = (9007199254740991 : ℝ) / 18014398509481984 ∧
  0 ≤ v.toReal f64fmt ∧ v.toReal f64fmt ≤ 2147483647 ∧
  |v.toReal f64fmt - 0| < |v.toReal f64fmt - 1| ∧
  Returns Lifted.module "iround" [.f64 x] [.i32 1]
```

The names are interpreted in namespaces `Proofs`, `FVA.Wasm`, `FVA.Wasm.Exec`,
and `FVA.Wasm.Num`. `IsNum` excludes infinities and NaNs, and `toReal` is the
exact real value of the binary64 bit pattern. The strict absolute-distance
inequality demonstrates the returned integer is not nearest.
`Returns` includes instantiability and proves termination without traps with
exactly the specified result, for every fresh instance and every host behavior.
The proof uses a kernel-evaluated deterministic run and FVA's theorem connecting
that run to all executions in the Wasm semantics. The internal fuel bound of 20
is sufficient for this run; the resulting `Returns` statement has no fuel bound.
No universal success claim for R1 is made or left as an admitted proof.

The artifact computes `i32.trunc_sat_f64_s(f64.add(x, 0.5))`. For this input the
exact addition is `1 - 2^-54`, a binary64 rounding midpoint. Ties-to-even produces
`1.0`, and conversion produces `1`. This explains the defect; the theorem above
checks the actual execution rather than relying on this explanation.

The completed external-checker audit reports `fva trust: PASS`, with only the
standard axioms `propext`, `Classical.choice`, and `Quot.sound`. Both `leanchecker`
and `con-leche` accepted the exported proof; the artifact link matched. FVA
reports **14 code lines**, all in `Proofs.Spec`, as the project review surface.
The end-to-end `./verify.sh` run exited zero; its replay took 101 seconds in
`leanchecker` and 68 seconds in `con-leche`.
The canary report records 71 rejections and one known acceptance for
`leanchecker`, and 69 rejections and three declines for `con-leche`, with no
crashes or timeouts. The known acceptance is handled by FVA's pinned
`trust/canaries/known.tsv`; the PASS does not mean that every canary was rejected.
See `fva-trust.txt` for the complete report.

## Reproduction

From this directory, using the supplied Lean 4.35.0, built Mathlib/FVA caches,
Python 3, and ordinary shell utilities:

```sh
./verify.sh
```

[verify.sh](verify.sh) checks the artifact hash, runs `lake build`, copies the
unchanged FVA package into a temporary directory outside this project, points
its Lake configuration at the already installed package cache, and relinks its
checker there. It then runs:

```sh
EXTERNAL_FVA_CHECKER trust . --spec-module Proofs.Spec --root-module Proofs
```

Here `EXTERNAL_FVA_CHECKER` is the absolute executable path constructed by the
script, not a command to enter literally. No network or artifact rebuild is
needed. Success requires exit status zero, `glm-iround.wasm: OK`, a successful
Lake build, and an FVA `PASS` with the lifted file matching and both default
kernel replays accepting. `PASS` certifies the counterexample claim; the software
requirement R1 is **false**. The script saves the audit output in
[fva-trust.txt](fva-trust.txt).

An additional runtime reproduction, independent of the formal proof, is:

```sh
wasmtime run -C cache=n --invoke iround glm-iround.wasm 0.49999999999999994
```

It prints `1` (possibly with CLI warnings). Disabling Wasmtime's cache avoids
writing outside the permitted directories. This runtime test is corroboration;
it is not a premise of the theorem.

custom models, axioms, notation, or alternative numeric semantics in that file.

inspect if relying on the one-command reproduction.

numeric, and claim specifications (the `FVA/Spec` directory: 23 Lean files,
3,606 physical lines, 161,903 bytes). In particular, `Spec/Numerics/Float.lean`
provides exact binary64 interpretation and IEEE rounding, and `Spec/CAbi.lean`
defines `Returns`. FVA's implementation proofs connect the executable decoder,
stepper and numeric operations to those specifications. The full FVA Lean
library comprises 128 files, 24,159 physical lines, 1,104,104 bytes; this is a
shared foundation, not a new project-specific specification. FVA's trust
collection, replay, canary, verdict, and trust CLI code comprises 5 files,
1,196 physical lines, 56,949 bytes (included in that library total).

Residual trust includes the supplied FVA base and checker provenance, the Lean

human review connects the formal claim to the English requirement and the
