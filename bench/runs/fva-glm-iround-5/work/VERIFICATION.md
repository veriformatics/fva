# Verification of `glm-iround.wasm`

**R1 is false.** The shipped module returns `1` for the finite binary64 input
`0x3fdfffffffffffff`, whose exact real value is

```
x = 1/2 - 1/18014398509481984
  = 0.499999999999999944488848768742172978818416595458984375.
```

This is within `[0, 2147483647]`. Its distance to `0` is strictly smaller
than its distance to `1`, so returning `1` violates R1, including its rule
allowing either integer only at an exact halfway point. The decimal CLI
argument `0.49999999999999994` denotes this binary64 value.

## Machine-checked statement

The theorem in `Proofs/Proof.lean` is exactly:

```lean
theorem r1_counterexample_holds : r1_counterexample
```

Its complete specification, from `Proofs/Spec.lean`, is:

```lean
def r1_counterexample : Prop :=
  let bits : BitVec 64 := 0x3fdfffffffffffff
  let x := ofBits f64fmt bits
  x.IsNum ∧
  x.toReal f64fmt = (1 : ℝ) / 2 - 1 / 18014398509481984 ∧
  0 ≤ x.toReal f64fmt ∧ x.toReal f64fmt ≤ 2147483647 ∧
  |x.toReal f64fmt - 0| < |x.toReal f64fmt - 1| ∧
  Returns Lifted.module "iround" [.f64 bits] [.i32 1]
```

Here `ofBits`, `f64fmt`, and `toReal` are FVA's binary64 interpretation
and exact real value; `IsNum` excludes infinities and NaNs. FVA's `Returns`
includes successful instantiation and says that every execution from every
fresh instance, under every host semantics, terminates without trapping and
returns the specified result. Thus this is a formal counterexample to R1,
not a proof of a weakened rounding requirement. R1 is the only requirement
in `README.md`.

The proof evaluates FVA's verified deterministic interpreter for the
concrete call (fuel 10), then uses `must_returned_of_runDet` to establish
`Returns`. The numeric interpretation and strict distance comparison are
proved in Lean using exact real arithmetic. There are no `sorry`, custom
axioms, or `native_decide` in the submitted proof.

## Connection to the artifact

The subject is the original **66 bytes** of `glm-iround.wasm`, SHA-256:

```
eded7ae1f3c1ba100d618a98f8f86eb690577a8358e47e31f2039eb2f4a75a3a
```

`Proofs/Lifted.lean` was generated by:

```sh
fva/.lake/build/bin/fva lift glm-iround.wasm Proofs/Lifted.lean --ns Proofs.Lifted
```

It contains all bytes as one numeral, their length, the artifact path, the
decoded module, and the kernel-checked theorem
`Proofs.Lifted.decode_eq : decode bytes len = .ok module`.
FVA checks that the numeral equals the on-disk bytes and independently
replays `decode_eq` along with the counterexample proof. This verifies the
compiled artifact directly; neither the GLM headers nor a source-level
model nor the compiler is an assumption of the result.

The decoded function is `local.get 0; f64.const 0.5; f64.add;
i32.trunc_sat_f64_s`. For this input the exact sum is `1 - 2^(-54)`,
midway between adjacent binary64 values `1 - 2^(-53)` and `1`.
Binary64 ties-to-even addition produces `1`, which truncates to integer
`1`. This explains the defect; the formal statement above is the evidence.

## Reproduce offline, from this directory

Build and check the expected artifact hash:

```sh
sha256sum glm-iround.wasm
lake build
```

The hash must match the value above and `lake build` must exit zero with
`Build completed successfully`.

For the FVA verdict, build the supplied, unchanged checker outside the
project. These commands use the already installed packages and canary
files; no network is needed:

```sh
check_root=$(mktemp -d /tmp/iround-fva.XXXXXX)
cp -a fva/. "$check_root/"
ln -s /home/eturkes/.cache/fva-bench/packages-v4.35.0 "$check_root/.lake/packages"
rm "$check_root/.lake/build/bin/fva"
(cd "$check_root" && lake build fva)
"$check_root/.lake/build/bin/fva" trust . --spec-module Proofs.Spec --root-module Proofs
```

Success is exit status zero and `fva trust: PASS`. A PASS here means the
**counterexample is proved**, not that the artifact satisfies R1. The
checker also reports the review surface, artifact link, kernel replays,
and false-proof canary results.

As an independent runtime reproduction:

```sh
wasmtime run -C cache=n --invoke iround glm-iround.wasm 0.49999999999999994
wasm-tools print glm-iround.wasm
```

The first command prints `1` (Wasmtime may also print experimental CLI
warnings); the second displays the instructions described above. Disabling
the cache avoids writing to the environment's read-only home directory.
These runtime commands corroborate the proof and are not proof assumptions.

## Recorded FVA result

The external checker returned `fva trust: PASS` (exit zero). Both
`leanchecker` and the independent `con-leche` accepted the proof export,
including `decode_eq`; the artifact link matched. The review surface was
13 code lines, all in `Proofs.Spec`. The proof depends only on the standard
axioms `propext`, `Classical.choice`, and `Quot.sound`.

For the 72 pinned known-false exports, `leanchecker` rejected 71 and
accepted the one documented replaced-prelude canary; `con-leche` rejected
69 and declined three, accepting none. FVA permits the documented Lean
prelude exception because an independent kernel rejects that canary and
FVA separately checks the prelude. These are the observed checks, not a
claim that every kernel rejected every canary. See
`fva/trust/canaries/known.tsv` for the exception. The complete final output
is saved in `FVA-REPORT.txt`.
