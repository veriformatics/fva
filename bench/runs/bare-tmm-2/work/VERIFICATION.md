# Verification of the shipped TMM factors

**R3 fails on the shipped artifact bytes.** For R1 and R2, the result depends on a distinction the documentation does not resolve: exact mathematical TMM versus the implementations' floating-point treatment of ties. At an absolute tolerance of **10⁻¹⁰**, the Lean exact-real model below refutes conformance of every value in both files. Operational replay reproduces the supplied outputs. These findings are compatible: rounding changes which genes survive trimming.

The R1/R2 counterexamples are explicitly **model-relative**. They do not establish that either output file was incorrectly generated by its implementation. If R1/R2 mean agreement with the complete R/Python/SciPy floating-point execution semantics, a formal proof of those requirements remains **unproved**; the replay evidence and its limitations are given below. No equivalence between those runtimes and the exact-real model is assumed.

## Requirements and exact checked statements

All declarations below are in namespace `TMM`. Indices in Lean are zero-based; sample numbers in this report are one-based. `edge` and `rna` parse the finite decimal text as exact rational numbers, not binary floats. `tolerance : ℚ := 1 / 10^10`. `factor` is the exact-real TMM model described in the next section.

### R1: edgeR artifact

[Proofs/Results.lean](Proofs/Results.lean) proves:

```lean
theorem R1_exact_real_fails (s : Fin 7) :
    (tolerance : ℝ) < |(edge[s.val]! : ℝ) - factor s|
```

Thus every sample fails the chosen tolerance against this model. A concrete witness is **the complete shipped `counts.tsv`, sample 4**: the model's factor lies in `[0.95641087, 0.95641287]`, whereas the shipped value is `0.95358597286325431`. The certified separation is much larger than 10⁻¹⁰.

For the operational interpretation, `verification/replay.R` sources the two bundled R implementation files and calls `normLibSizes(m, method="TMM")`. Its seven factors, formatted with `sprintf("%.17g", ...)` and final newlines, reproduce **all 138 bytes** of `edger-factors.txt`. `verification/replay.py` asserts this equality. This is a checked execution result, not a proof of R's floating-point semantics or all possible executions.

### R2: RNAnorm artifact

[Proofs/Results.lean](Proofs/Results.lean) proves:

```lean
theorem R2_exact_real_fails (s : Fin 7) :
    (tolerance : ℝ) < |(rna[s.val]! : ℝ) - factor s|
```

Again every sample fails against the exact-real model. The same **sample-4 input** witnesses failure: the shipped value `0.9550875280917844` is outside the certified interval `[0.95641087, 0.95641287]` by more than 10⁻¹⁰.

For the operational interpretation, `verification/replay.py` executes the original, unmodified AST definitions of `TMM`, `UQ`, `remove_zero_genes`, and `LibrarySize` from the shipped Python files. It calls `TMM().fit(m.T).get_norm_factors(m.T)` and asserts absolute error below 10⁻¹⁰ for **every** shipped value. NumPy is installed, but SciPy, pandas and sklearn are not. The script therefore supplies dependency adapters: average ranks of equal doubles, interpolated percentiles, `exp(mean(log(...)))` geometric means, array validation, default output configuration, context management and transformer scaffolding. These adapters are a model of the unavailable dependencies, **not a replay of the complete installed RNAnorm package**. Its result does not formally prove R2 for the original dependency stack.

### R3: agreement to ten decimal places

[Proofs/Results.lean](Proofs/Results.lean) proves directly about the parsed artifacts:

```lean
theorem artifact_lengths : edge.length = 7 ∧ rna.length = 7

theorem R3_first_difference :
    edge[0]! - rna[0]! = 931142302732627/10^17

theorem R3_all_differ :
    ∀ s : Fin 7, tolerance < |edge[s.val]! - rna[s.val]!|

theorem R3_fails :
    ¬ (∀ s : Fin 7, |edge[s.val]! - rna[s.val]!| ≤ tolerance)
```

The first sample alone is a counterexample:

```text
edgeR:   0.99099942459293067
RNAnorm: 0.9816880015656044
difference, exactly: 0.00931142302732627
```

All seven differences exceed 10⁻¹⁰. This also rules out equality after rounding to ten places: numbers rounding to the same multiple of 10⁻¹⁰ cannot differ by more than 10⁻¹⁰. R3 needs no TMM model, logarithm evaluation, source execution or assumption about what TMM ought to mean.

## Mathematical model and its connection to the documentation

[Proofs/Model.lean](Proofs/Model.lean) embeds the three input files with Lean's `include_str` and defines the following finite computation:

1. Read the 454 × 7 nonnegative integer matrix. There are no all-zero rows. Compute column sums `[1261, 621, 755, 1097, 1916, 1136, 1219]`.
2. Compute each library-normalized 75th percentile by type-7 linear interpolation: sorted, zero-based entries 339 and 340 with weights 1/4 and 3/4. Select the first column minimizing distance from the mean. The reference is sample 4. Every upper quartile exceeds 10⁻²⁰, so edgeR's sparse fallback is irrelevant. RNAnorm's geometric rescaling of these quartiles preserves the minimizing column in exact arithmetic.
3. Discard a gene in a pair if either count is zero. There are `[244,195,205,300,259,244,227]` positive pairs. The theorem `default_Acutoff_inactive` proves all their A-values exceed edgeR's default `-10^10`.
4. Use average ranks for **exact ties**, matching the rank policy of the bundled source. For a sample/reference pair `(o,r)`, rank M by the rational key `o/r` and A by the integer product `o*r`. Their library constants and increasing logarithms do not change ranks in exact arithmetic. Twice an average rank is `2 * numberLess + numberEqual + 1`.
5. Keep the intersection of inclusive M ranks `floor(0.3*n)+1` through `n-floor(0.3*n)` and A ranks `floor(0.05*n)+1` through `n-floor(0.05*n)`. The exact kept counts are `[63,79,76,283,89,95,79]`.
6. Weight a retained pair by `1 / (1/o + 1/r - 1/Nsample - 1/Nreference)`. Normalize these rational weights to sum to one. Let `z[s]` be the weighted mean of `ln(o*Nreference/(r*Nsample))`.
7. Define `factor[s] = exp(z[s] - sum(z)/7)`. Changing from log2 to ln cancels against the final base-2 exponentiation; subtracting the mean log is division by the geometric mean. The reference comparison gives a raw factor of one.

This model uses the default `m_trim=0.3`, `a_trim=0.05`, inverse variance weighting, and geometric rescaling, as explained by the docs and made precise by the bundled code. The RNAnorm summary bullet says `m_trim` for A trimming, but its separate `a_trim` parameter description and its code use `a_trim`; this report uses that interpretation. Neither documentation specifies an IEEE rounding policy or how rounding should split mathematical ties. The correspondence of this mathematical model to the prose, including that interpretation and the source's average-rank convention, is a **review obligation**, not a theorem about an R/Python interpreter.

[Proofs/Intervals.lean](Proofs/Intervals.lean) proves a rational enclosure procedure sound for Mathlib's real logarithm and exponential. Logarithms use a twelve-term atanh series with a proved remainder and exact range reduction. Exponentials use twelve Taylor terms and a proved remainder on `[-1,1]`. Outward rounding before exponentiation is separately checked. There are no numerical oracle assumptions about log or exp.

The following theorem in [Proofs/Results.lean](Proofs/Results.lean) certifies all displayed intervals:

```lean
theorem exact_factor_enclosures (s : Fin 7) :
    (displayBox s).Holds (factor s)
```

Here `Box.Holds b x` means `(b.lo : ℝ) ≤ x ∧ x ≤ (b.hi : ℝ)`, and the definition `displayBox` gives:

## Why source replay and exact-real factors differ

The source executions retain `[65,79,77,300,89,95,81]` rows in R and `[64,79,77,283,89,95,81]` in the Python replay. R returns unity early for the reference, so its reference count of 300 describes finite input rows rather than a trimming decision. The nonreference differences from the exact-real model arise from rounding before ranking; they cannot be handled by assuming that each floating-point arithmetic error only makes a small final perturbation.

For sample 1, rows **163** and **355** have counts `(8,13)` and `(13,8)` against sample 4. Their products are both 104, so their exact A-values tie at rank **232.5**, just above the upper allowed rank **232**. `TMM.A_boundary_tie` in `Proofs/Model.lean` checks these counts, doubled rank 465 and doubled cutoff 464 from the embedded matrix.

The R exit trace and Python AST trace report:

```text
row 163: A_R = -6.8496303262951601, rank_R = 233
row 355: A_R = -6.849630326295161,  rank_R = 232
both:    A_Python = -6.8496303262951601, rank_Python = 232.5
```

edgeR computes A as `(log2(p)+log2(pref))/2`; RNAnorm computes `log2(p*pref)/2`. Both are the same real expression. On this input, their floating-point evaluations change whether row 355 survives. It is the only difference between the sample-1 source masks; geometric rescaling spreads the resulting difference to all seven output factors. Other rounding-split ties also explain why both source computations differ from the exact-rank mathematical model.

## Commands and success criteria

From this directory, with the provided offline toolchain and built Mathlib:

```sh
python3 verification/check.py
```

It checks all pinned bytes, runs the following commands in order, requires zero exit codes, checks that the three main theorems' axiom reports are present and contain no `sorryAx`, and checks the source replay assertions:

```sh
lake build
lake env lean Proofs/Results.lean
python3 verification/replay.py
```

Success ends with:

```text
PASS: all checks completed; native_decide/compiler trust is documented in VERIFICATION.md
```

`lake build` must report `Build completed successfully`. The explicit Lean command prints the axiom dependencies described below. The replay reports byte-identical R output, Python agreement within 10⁻¹⁰, all seven artifact differences exceeding 10⁻¹⁰, the reference, mask counts, and tie observations. No command regenerates either shipped factor file or needs a network connection. Individual commands omit the manifest check; the single `check.py` command checks the complete deliverable.

**Trusted computation boundary:** the analytic enclosure proofs are checked by Lean's kernel using Mathlib inequalities. Large finite rational computations and file parsing use Lean's `native_decide`. In this Lean version it introduces native-evaluation axioms: the printed main R1/R2 dependency lists include `all_terms_valid._native.native_decide.ax_1_1`, `numeric_valid._native.native_decide.ax_1_1`, `displayed_enclosures_check._native.native_decide.ax_1_1` and `separated._native.native_decide.ax_1_1`; R3 uses `R3_all_differ._native.native_decide.ax_1_1`. Thus these are **not kernel-only arithmetic certificates**: they also trust Lean's native evaluator/compiler and runtime. The other printed dependencies are `propext`, `Classical.choice`, and `Quot.sound`. There are no hand-written axioms or admitted proofs, and the main results do not depend on `sorryAx`.

The installed Lean executable is 5616 bytes and its `libleanshared.so` is 161697472 bytes; Mathlib's source tree contains 8637 files totaling 98879465 bytes. These sizes identify the surrounding installation, not an audited minimal trusted code base. The ordinary assumptions about the operating system and hardware remain in scope for every machine check.
